# 데이터 흐름도와 STRIDE 위협표 — 「이 AI가 우리 데이터를 어떻게 다루나」에 답하는 한 장

> [정보보안](README.md) › 01 · 짝 기법: [기대손실 결정표](../../../methods/의사결정분석/01-기대손실-결정표.md) · [다기준 의사결정](../../../methods/의사결정분석/03-다기준-의사결정.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분(가정 변환·적용 예·지표·6시간 형태)은 별도 표시가 없으면 전부 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 「데이터 보안」 질문에 데이터 흐름도 한 장 + 신뢰 경계별 STRIDE 표로 답한다.
- **필요한 데이터**: 우리 서비스의 실제 구성요소 목록(스냅샷·캐시·LLM 호출·감사 로그). 이 목록이 없으면 흐름도를 못 그린다.
- **6시간 최소 형태**: 공격 트리 하나(OR 노드는 가장 싼 자식, AND 노드는 자식 합). 화면: 흐름도(노드 5~7, 경계 점선 3) + 경계마다 STRIDE 1행·「킷에서 막는 통제」 칸.
- **반문 하나**: 「표 한 장으로 보안이 되나」 → 보안 증명이 아니라 남은 위험 목록이다. 「아직 안 막는 것」 칸을 일부러 남긴다.
- **하지 말 것**: 팹 AI 서비스에 STRIDE 를 적용한 공개 1차 사례는 근거 없음 — STRIDE 대응은 추론이다.

## 상세

**한 줄**: 「보안 공학에서는 새 시스템이 어디서 뚫릴지를 만들기 전 설계 단계에서 풀 때 데이터 흐름도 위에 신뢰 경계를 긋고 경계를 넘는 흐름마다 STRIDE 6유형을 묻는 위협 모델링을 쓴다. 이 기법은 「공격자는 인터넷 너머에 있다」고 가정한다. 이 가정을 팹의 실제 경계(장비망–MES–사무망–외부 LLM API–협력사)와 내부자·실수 사용자로 바꾸면, 하이닉스 「데이터 보안」 질문에 답하는 아키텍처 한 장이 된다.」

- **과제 문구 신호**(추론): 「사내 데이터 활용」「현업 적용 가능성」「보안」「실제 도입」「MES/설비 데이터 연계」. 신호가 없어도 제출물 부록으로 늘 준비한다.
- **가정 변환**

| 원래 가정(보안 공학) | 팹으로 바꾼 것 |
|---|---|
| 공격자 = 외부 해커 | 실수하는 내부 사용자, 권한 밖을 보고 싶은 협력사, 프롬프트에 섞여 들어온 지시 |
| 자산 = 고객 개인정보 | 레시피 파라미터·수율·고객 제품 정보(국가핵심기술·영업비밀 성격) |
| 경계 = 인터넷/사내망 | 장비망(Purdue L0~2)/MES(L3)/DMZ/사무망/외부 API |
| 영향 = 기밀성 우선 | OT 는 무결성·가용성이 먼저다. 「장비가 서거나 잘못된 판정이 로트를 움직이는 피해가 더 크다」는 팹 적용은 추론 |

- **원 분야 사실**:
  - Schneier(1999) — 「Attack trees provide a formal, methodical way of describing the security of systems, based on varying attacks.」
  - 「OR nodes have the value of their cheapest child; AND nodes have the value of the sum of their children.」 STRIDE 의 6유형(사칭·변조·부인·유출·서비스 거부·권한 상승) 정의는 Microsoft Learn 위협 모델링 도구 문서를 따른다.
- **하이닉스 적용 예**(STRIDE 를 팹 AI 서비스에 대 본 것)
  - S(사칭): 다른 엔지니어 계정으로 AI 에 조회.
  - T(변조): 스냅샷 파일·프롬프트 템플릿 변조.
  - R(부인): 「AI 가 그렇게 말했다」를 증명 못 함 → [04](04-변조-방지-감사-로그.md).
  - I(유출): RAG 가 권한 밖 문서를 요약해 줌 → [02](02-권한-상속-RAG.md), 외부 API 로 레시피 송신.
  - D(서비스 거부): 대량 질의가 MES 조회 부하로 → [03](03-조회-예산과-정책-결정점.md).
  - E(권한 상승): 프롬프트 주입으로 도구 호출 범위 확대 → [05](05-간접-프롬프트-주입-방어.md).
- **기준선과 지표**: 따로 정해 둔 지표는 없다. 기준선 = 위협표 없이 만든 구성(가정), 지표 = 아래 화면에 찍히는 값(경계별 STRIDE 행 수, 「킷에서 막는 통제」 칸이 채워진 비율, 공격 트리 루트 비용).
- **6시간 최소 형태**
  - 화면: 데이터 흐름도 한 장(노드 5~7개, 신뢰 경계 점선 3개) + 경계마다 STRIDE 표 1행씩, 각 행에 「킷에서 막는 통제」 칸.
  - 데이터: 우리 서비스의 실제 구성요소 목록(스냅샷·캐시·LLM 호출·감사 로그).
  - 계산: 공격 트리 하나(루트 「레시피 값이 사무망 밖으로 나간다」). OR 노드는 가장 싼 자식, AND 노드는 자식 합으로 비용을 전파한다. 통제 하나를 넣을 때 루트 비용이 얼마나 오르는지 보여 준다.
- **반론과 답**: 「표 한 장으로 보안이 되나」 → 이 표는 보안 증명이 아니라 **남은 위험 목록**이다. 표에 「킷에서 아직 안 막는 것」 칸을 일부러 남기면 오히려 신뢰를 얻는다(추론). 「STRIDE 는 오래된 기법」 → 맞다. 그래서 LLM 고유 위험은 OWASP LLM Top 10 칸([05](05-간접-프롬프트-주입-방어.md))으로 보강한다.
