# 조회 예산과 정책 결정점 — 제로 트러스트를 「AI 에이전트의 데이터 조회」에 적용

> [정보보안](README.md) › 03 · 짝 기법: [대기행렬과 운영 곡선](../../../methods/확률과-시뮬레이션/02-대기행렬과-운영-곡선.md) · [민감도 분석](../../../methods/의사결정분석/02-민감도와-가정-바꿔-보기.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분(가정 변환·적용 예·지표·6시간 형태)은 별도 표시가 없으면 전부 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 에이전트가 날린 MES·SPC 조회마다 정책 결정점이 허용/축소/거부를 정하는 「조회 예산」을 보인다.
- **필요한 데이터**: 정책 표(역할 × 테이블 × 허용 컬럼 × 행 상한 × 일 예산) + 읽기 전용 스냅샷. 정책 표가 없으면 못 쓴다.
- **6시간 최소 형태**: PEP 함수 하나: 요청 → 정책 조회 → 컬럼·행 제한 → 예산 차감 → 로그. 화면: 조회 목록(허용/축소/거부 + 이유) + 남은 예산 막대.
- **반문 하나**: 「예산이 업무를 막는다」 → 거부 대신 축소(행 상한·집계만 반환)를 기본값으로 둔다.
- **하지 말 것**: 예산 수치는 근거가 없으니 「초기값, 운영 로그로 조정」이라 말한다(추론). 팹에서 운영한 공개 1차 사례는 근거 없음.

## 상세

**한 줄**: 「제로 트러스트 아키텍처에서는 내부망에 들어온 주체가 모든 자원에 닿는 문제를 경계 방화벽이 무의미해진 상황에서 풀 때 요청마다 정책 결정점이 주체·자원·맥락을 보고 최소 권한으로 세션을 여는 방식을 쓴다. 이 기법은 「주체 = 사람·기기」를 가정한다. 이 가정을 LLM 에이전트가 MES·SPC 스냅샷에 날리는 조회로 바꾸면 킷의 「조회 예산」이 정책 집행점(PEP)이 되고, 모델 추출·데이터 유출 방어(ATLAS M0004)까지 함께 설명된다.」

- **과제 문구 신호**(추론): 「MES/설비/계측 데이터 연동」「에이전트」「자동 조회」「대시보드」「실시간」. 생산 데이터 원본 무접촉 원칙(레포 CLAUDE.md)과 바로 맞물린다.
- **가정 변환**

| 원래 가정 | 팹으로 바꾼 것 |
|---|---|
| 주체 = 사용자·단말 | 사용자 + 그 사용자를 대신하는 LLM 에이전트(권한은 사용자 권한 ∩ 에이전트 정책) |
| 자원 = 서버·앱 | 스냅샷 테이블·컬럼(로트, 장비, 레시피 파라미터) |
| 판정 맥락 = 기기 상태·위치 | 질의 목적 태그, 남은 예산, 시간대, 요청 행 수 |
| 위협 = 측면 이동 | 대량 조회로 레시피·모델 동작을 통째로 재구성(모델 추출, ATLAS T0024), 원본 DB 부하 |

- **원 분야 사실**
  - NIST SP 800-207 — 「Access to individual enterprise resources is granted on a per-session basis. Trust in the requester is evaluated before the access is granted. Access should also be granted with the least privileges needed to complete the task.」
  - 「All communication is secured regardless of network location. Network location alone does not imply trust.」
  - MITRE ATLAS `AML.M0004` 「Restrict Number of AI Model Queries」 — 「Limit the total number and rate of queries a user can perform.」 T0024 에 대해 「Limit the volume of API queries in a given period of time to regulate the amount and fidelity of potentially sensitive information an attacker can learn.」
  - Tramèr 외(USENIX Security 2016)는 예측 API 로 모델을 훔치는 공격(모델 추출)을 다룬다(초록 기준). OWASP LLM Top 10 2025 에는 Unbounded Consumption(LLM10) 항목이 있다.
- **하이닉스 적용 예**(추론): 에이전트가 MES·SPC 스냅샷을 자동 조회하는 과제. 조회 예산이 PEP 역할을 한다.
- **기준선과 지표**: 따로 정해 둔 지표는 없다. 기준선 = 예산·컬럼 제한 없는 조회(가정), 지표 = 화면의 허용/축소/거부 건수와 남은 예산.
- **6시간 최소 형태**
  - 화면: 에이전트가 날린 조회 목록, 행마다 「허용/축소/거부 + 이유(예산 초과·컬럼 등급·목적 불일치)」와 남은 예산 막대.
  - 데이터: 정책 표 하나(`역할 × 테이블 × 허용 컬럼 × 행 상한 × 일 예산`)와 읽기 전용 스냅샷.
  - 계산: PEP 함수 하나 — 요청 → 정책 조회 → 컬럼 잘라내기·행 상한 적용 → 예산 차감 → [04](04-변조-방지-감사-로그.md) 로그 기록. LLM 은 PEP 를 우회하는 경로를 갖지 않는다.
- **반론과 답**: 「사내망인데 왜 요청마다 판정하나」 → NIST 원칙 2 가 「망 위치만으로 신뢰하지 않는다」고 적는다. 「예산이 업무를 막는다」 → 거부 대신 축소(행 상한·집계만 반환)를 기본값으로 둔다. 예산 수치 자체는 근거가 없으니 「초기값, 운영 로그로 조정」이라고 말한다(추론). 「사람 승인을 붙여야 하지 않나」 → 승인 게이트는 [컴퓨터과학 › 자율성 설계](../자율성-설계/README.md) 몫이다.
