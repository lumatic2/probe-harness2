# 변조 방지 감사 로그 — 「AI 가 그렇게 말했다」를 증명 가능한 기록으로

> [정보보안](README.md) › 04 · 짝 기법: 없음
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분(가정 변환·적용 예·지표·6시간 형태)은 별도 표시가 없으면 전부 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: AI 판단 한 건을 해시 체인 로그로 남겨 「AI 가 그렇게 말했다」를 재현·증명 가능한 기록으로 만든다.
- **필요한 데이터**: JSONL 한 파일, 레코드마다 prev_hash. 판단 한 건의 입력 스냅샷 해시·프롬프트·검색 문서 ID·응답·사용자 결정을 못 남기면 재현이 안 된다.
- **6시간 최소 형태**: h_i = SHA-256(h_{i-1} ‖ record_i). 화면: 판단 이력 표 + 「체인 검증」 버튼, 한 레코드를 고치면 그 뒤가 전부 적색.
- **반문 하나**: 「DB 에 append-only 권한만 주면 되지 않나」 → 관리자를 믿는 방식이다. 해시 체인은 제3자가 재계산으로 확인하게 한다.
- **하지 말 것**: 머클 트리는 이름만 언급한다(6시간 규모는 체인으로 충분 — 추론). 팹 AI 판단 로그에 적용한 공개 1차 사례는 근거 없음.

## 상세

**한 줄**: 「보안 포렌식에서는 로그를 남긴 쪽이 로그를 고칠 수 있는 문제를 로그 서버를 완전히 믿을 수 없는 상황에서 풀 때 해시 체인·머클 트리로 사건이 그대로 있고 과거와 일관됨을 증명하는 변조 방지 로그를 쓴다. 이 기법은 「사건 = 로그인·파일 접근」을 가정한다. 이 가정을 AI 판단 한 건(입력 스냅샷 해시 + 프롬프트 + 검색된 문서 ID + 응답 + 사용자 결정)으로 바꾸면 수율·품질 판단 보조 과제의 추적성 요구에 적용된다.」

- **과제 문구 신호**(추론): 「추적성」「근거 제시」「설명 가능」「책임」「감사」「이력」「재현」.
- **가정 변환**

| 원래 가정 | 팹으로 바꾼 것 |
|---|---|
| 로그 사건 = 시스템 이벤트 | AI 판단 레코드: 스냅샷 버전·조회 결과 해시·모델 버전·프롬프트 템플릿 버전·응답·사람의 최종 결정 |
| 검증자 = 외부 감사인 | 품질팀·보안팀·고객 감사(8D·PCN 대응) |
| 목적 = 침해 조사 | 「그때 AI 가 왜 그렇게 말했나」 재현, 사람의 최종 판단 기록(회사 원칙 「AI가 원인과 대응 방안을 제시하고, 사람은 최종 판단」과 맞물림 — 레포 CLAUDE.md) |

- **원 분야 사실**
  - Crosby & Wallach(USENIX Security 2009) — 「The logger must be able to prove that individual logged events are still present, and that the log, as seen now, is consistent with how it was seen in the past.」 머클 트리 쪽에서 논문은 8천만 건에서 해시 체인 증명 800MB 를 3KB 로 줄였다고 적는다.
  - OWASP LLM08:2025 — 「Maintain detailed immutable logs of retrieval activities to detect and respond promptly to suspicious behavior.」
  - STRIDE 의 R(부인 방지)에 해당한다([01](01-데이터-흐름도와-STRIDE-위협표.md)).
  - 개인정보 보호법 제28조의4 는 가명정보 처리 기록의 작성·보관을 요구한다.
- **하이닉스 적용 예**(추론): 수율·품질 판단 보조에서 「AI 가 이 로트를 보류하라고 했다」의 근거 데이터·프롬프트·응답을 재현한다.
- **기준선과 지표**: 따로 정해 둔 지표는 없다. 기준선 = 수정 가능한 일반 로그(가정), 지표 = 체인 검증 결과(녹색/적색)와 레코드 하나를 고쳤을 때 적색이 되는 범위.
- **6시간 최소 형태**
  - 화면: 판단 이력 표 + 「체인 검증」 버튼(전 레코드 해시 재계산 → 녹색/적색), 레코드 하나를 고치면 그 뒤가 전부 적색이 되는 시연.
  - 데이터: JSONL 한 파일, 레코드마다 `prev_hash`.
  - 계산: `h_i = SHA-256(h_{i-1} ‖ record_i)`. 머클 트리는 이름만 언급한다. 6시간 규모는 체인으로 충분하다(추론).
- **반론과 답**:
  - 「DB 에 append-only 권한만 주면 되지 않나」 → 그건 관리자를 믿는 방식이다. 해시 체인은 관리자도 몰래 못 고친다는 걸 **제3자가 재계산으로 확인**하게 한다(Crosby & Wallach).
  - 「로그에 레시피가 남으면 로그가 유출 통로」 → 원값 대신 해시·ID 만 남기고 원값은 스냅샷에서 다시 꺼낸다. 이것이 가명처리 법리의 「추가 정보 분리 보관」과 같은 구조다(추론).
  - 통제 테스트·표본 감사는 [회계학 › 회계감사 › 통제 테스트](../../회계학/회계감사/04-통제-테스트.md) 몫이다.
