# 단순 감시기 구조와 안전 실드(Simplex) — 검증된 단순 규칙이 AI 제안을 거른다

> [자율성 설계](README.md) › 05 · 짝 기법: [관리도와 오경보 주기](../../../methods/품질과-신뢰성-통계/01-관리도와-오경보-주기.md) · [강건·시나리오 계획](../../../methods/확률과-시뮬레이션/04-강건-시나리오-계획.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: AI 레시피 보정 제안을 규칙 기반 한계(사양·인터록)가 걸러, AI 가 틀려도 공정이 안전 영역에 남게 한다.
- **필요한 데이터**: 합성 공정 시계열(목표·드리프트) + 실드 규칙 YAML(Q-Time 초과 금지·연속 보정 횟수 등). 실드 규칙이 없으면 못 쓴다.
- **6시간 최소 형태**: apply = ai if shield_ok(ai, state) else baseline. 화면: AI 제안값·적용값 두 선 + 안전 영역 띠 + 실드 차단 시점과 사유.
- **반문 하나**: 「실드가 너무 자주 막으면 AI 가 의미 없다」 → 차단률 자체가 지표다. 차단이 잦으면 AI 쪽을 고친다.
- **하지 말 것**: 팹 R2R·FDC 가 이미 실행 자동 층이라는 것과 R2R 확장 = Simplex 대응은 근거 없음(추론)이다. 인터록·비상 정지는 건드리지 않는다.

## 상세

**한 줄**: 「실시간 제어에서는 검증하기 어려운 고성능 제어기를 운영 중에 들여오는 문제를 멈출 수 없는 공정이 돌고 있는 상황에서 풀 때 Simplex 구조(검증된 단순 제어기 + 고성능 제어기 + 전환 결정 로직)를 쓴다. 「고성능 제어기」를 AI 레시피 보정·디스패칭 제안으로, 「단순 제어기」를 기존 R2R·사양 한계·인터록 규칙으로 바꾸면, AI 가 틀려도 공정이 안전 영역에 남는 구조가 된다.」
- **과제 문구 신호**(추론): 「레시피 자동 보정」「APC」「R2R」「설정값 최적화」「냉동기·공조 설정」「자동 디스패칭」
- **가정 변환**

| 원 분야 | 반도체 현장 |
|---|---|
| 고성능 제어기(검증 어려움) | AI·LLM 제안(레시피 오프셋, 디스패칭 순서, 공조 설정값) |
| 단순 고신뢰 제어기(검증됨) | 기존 R2R(EWMA 등)·현행 디스패칭 규칙·현행 설정값 |
| 결정 모듈(안전 영역 검사) | 사양 한계·변경 폭 상한·Q-Time·장비 인터록 조건 검사 |
| 실드 명세(시간 논리) | 「한 번에 오프셋 ±x 초과 금지」「같은 챔버 연속 n 회 보정 금지」「Q-Time 초과 배정 금지」 |
| 안전 계통(IEC 61508) | 가스·플라즈마 인터록, 비상 정지 — AI 범위 밖 |

- **원 분야 사실**:
  - Simplex 논문(ACC 1998)은 이 구조를 「supports the safe, reliable introduction of control system upgrades while the system is running」하는 기술로 소개하고, 「a plasma-enhanced chemical vapor deposition (PECVD) system, a standard process in semiconductor manufacturing」에서 시연했다(**E2**, 초록 기준, 저자 미확인).
  - **반도체 공정 원 사례가 있다.** Sha(2001)는 이 접근을 「using simplicity to control complexity」로 요약하고, 다양한 중복 시스템이 정말 견고함을 주는지도 묻는다(**E2**, 초록 기준).
  - 학습 정책 쪽의 짝은 실드다. 실드는 학습자의 행동을 감시하고 「corrects them only if the chosen action causes a violation of the specification」한다(Alshiekh 외 2018, **E2**, 초록 기준).
- **기능안전과의 경계**:
  - IEC 는 기능안전을 「the automatic responses that keep systems safe when something goes wrong」로 설명하고, 예로 화학 공정의 비상 정지 시스템을 든다(IEC 설명 페이지, **E1** 기관 설명, 표준 본문 미판독).
  - FAQ 에는 「안전 계통에 요구를 거는 제어 계통도 안전 관련 계통으로 지정해야 하나」라는 항목이 있다(질문 목록만 받았고 답변 본문은 **미확인**).
  - 여기서 끌어낼 설계 선은 **AI 는 제어·권고 계통에 두고, 인터록·비상 정지(안전 계통)는 건드리지 않는다**는 것이다(추론). 안전 무결성 수준(SIL) 계산은 6시간에 과해 다루지 않고 이 한 줄로만 쓴다.
- **하이닉스 적용 예**(추론): AI 레시피 보정 제안을 규칙 기반 한계(사양·인터록)가 거른다. 「Q-Time 초과 금지」「같은 챔버 연속 보정 n 회 이상 금지」를 실드 규칙으로 둔다.
- **기준선과 지표**:
  - 지금 = R2R·FDC 는 이미 「실행 자동」 층이라는 가정. 팹에서 R2R·FDC·자동 디스패칭이 어느 자동화 수준으로 운영되는지(사람 승인 여부)를 밝힌 1차 자료는 **근거 없음** — 「이미 실행 자동 층」은 **추론**이다.
  - R2R 의 실무 확장(변경 폭 상한·데드밴드)이 Simplex·실드와 같은 역할을 한다는 직접 근거도 **근거 없음**(R2R 교과서 목차의 「Practical Extensions to Algorithms」 장 제목만 확인) → 변환 표의 대응은 추론이다.
  - 지표 = AI 제안 채택 n / 실드 차단 m / 단순 제어기로 전환 k, 차단률.
- **6시간 최소 형태**: 화면 = 시계열 하나에 선 둘(AI 제안값, 실제 적용값)과 안전 영역 띠. 실드가 막은 시점에 표시 + 「차단 사유: 변경 폭 상한」. 옆에 위 카운터. 데이터 = 합성 공정 시계열(목표·드리프트) + 실드 규칙 YAML. 계산 = `apply = ai if shield_ok(ai, state) else baseline`. MPC(모델 예측 제어)를 쓰는 과제면 제약 위반 0건을 함께 보인다.
- **반론과 답**:
  - 「실드가 너무 자주 막으면 AI 가 의미 없다」 → 차단률 자체가 지표다. 차단이 잦으면 AI 쪽을 고친다. 실드 규칙은 현업이 이미 가진 한계를 옮겨 적은 것이라 새 위험을 만들지 않는다(추론).
  - 「R2R 이 이미 자동인데 무엇이 새로운가」 → 기존 R2R 은 단순 선형 보정이 주류다. Fraunhofer 정리도 「use linear algorithms」에서 시작하라고 권한다.
  - 새 AI 는 그 위에 얹는 고성능 층이고, 기존 층이 Simplex 의 단순 제어기가 된다. 「기존 시스템을 갈아엎지 않는다」는 메시지가 된다(추론).
