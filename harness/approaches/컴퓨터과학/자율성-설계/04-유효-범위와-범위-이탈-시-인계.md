# 유효 범위(ODD)와 범위 이탈 시 인계 — AI 가 모르는 범위를 화면에 그린다

> [자율성 설계](README.md) › 04 · 짝 기법: [관리도와 오경보 주기](../../../methods/품질과-신뢰성-통계/01-관리도와-오경보-주기.md) · [기대손실 결정표](../../../methods/의사결정분석/01-기대손실-결정표.md) · [강건·시나리오 계획](../../../methods/확률과-시뮬레이션/04-강건-시나리오-계획.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」. 멈춤 스위치·우아한 성능 저하는 별도 챕터 없이 이 챕터에 접었다.

## 바로 쓰는 칸
- **쓸 점**: AI 판정이 유효한 범위(제품·공정·장비·레시피)를 화면에 그리고, 범위 밖이면 판정 대신 사람에게 넘긴다.
- **필요한 데이터**: 유효 범위 정의 YAML(허용 값 목록·범위) + 입력 스냅샷(센서 결측률·분포 이탈 점수). 유효 범위 정의가 없으면 못 쓴다.
- **6시간 최소 형태**: 범위 검사 규칙 + 분포 이탈 점수(z 또는 마할라노비스 거리) → 이탈이면 판정 생략. 화면: 판정 가능 범위 카드 + 「사람에게 넘김」 배지.
- **반문 하나**: 「범위를 좁히면 쓸 데가 없다」 → 범위 밖 건을 숨기지 않고 세어서 보여 주고, 그 숫자가 다음 학습·확장 목록이 된다.
- **하지 말 것**: 자율주행 ODD·MRC 사실을 반도체 사실로 말하지 않는다. 「기대 MRC」는 개인 견해(E4)라 반론으로만 싣는다.

## 상세

**한 줄**: 「자율주행 안전에서는 자동화 기능이 언제 믿을 만한지 정하는 문제를 도로·날씨·지역이 끝없이 다양한 상황에서 풀 때 유효 범위(운영 설계 영역, ODD) + 이탈 시 폴백 + 최소 위험 상태(MRC)를 쓴다. 「도로·날씨」를 제품·공정 단계·장비·레시피 버전·센서 상태로, 「갓길 정차」를 LOT hold·마지막 검증 레시피 유지·사람 호출로 바꾸면, AI 판정이 유효한 범위와 범위 밖 처리 규칙이 된다.」
- **과제 문구 신호**(추론): 「신규 제품·신규 공정에도」「예외 상황」「데이터가 없는 경우」「AI 가 틀리면」「장애 시」
- **가정 변환**

| 원 분야 | 반도체 현장 |
|---|---|
| 유효 범위(도로 종류·속도·날씨·지역) | 학습·검증한 제품 코드·공정 단계·장비 ID·레시피 버전·PM 이후 경과·센서 정상 여부 |
| 범위 이탈 감지 | 입력이 학습 분포 밖(새 레시피 버전, 신규 챔버, 결측 센서), 모델 신뢰도 하한 미만 |
| DDT 폴백(수준 3 = 사람이 받음) | AI 판정 보류 → 담당 엔지니어 호출 + 지금까지의 근거 묶음 인계 |
| 최소 위험 상태 | LOT hold(가공 전), 마지막 검증 레시피로 고정, 장비 「점검 필요」 표시 |
| 실패 완화 전략 | AI 서비스 자체 장애 시 → 기존 규칙(SPC·FDC 인터록)만으로 운영. AI 없이도 팹은 돈다 |

- **원 분야 사실**:
  - SAE 는 J3016 을 「Level 0 (no driving automation) to Level 5 (full driving automation)」의 분류로 소개한다.
  - 2021 개정에서 수준 3·4 의 차이를 분명히 하고 「failure mitigation strategy」 개념을 정의·명확화했다고 밝혔다(SAE 개정 안내문 2021-05-03, **E3**, 본문 판독 — J3016 본문은 미판독).
  - 최소 위험 상태는 J3016 이 「when a given trip cannot or should not be continued」 쓰는 상태로 소개되며, 수준 4·5 에서는 사람이 아니라 자동 운전 시스템이 이를 달성해야 한다.
  - 같은 글의 J3016 재인용에 따르면 자동 달성의 특성은 「the type and extent of the system failure, the ODD (if any) for the ADS feature in question, and the particular operating conditions when the system failure or ODD exit occurs」에 따라 달라진다(Stanford CIS 블로그 2022-01, **E4**, J3016 문구는 **2차 인용**).
- **반론(같은 출처)**: 필자는 MRC 를 「그 시스템이 할 수 있는 최선」으로 정의하면 수준 4 정의가 동어반복이 된다고 비판한다. 그래서 「기대 MRC」(시스템 능력과 무관하게 그 환경에서 마땅한 상태)를 따로 두자고 제안한다(**E4** 개인 견해). 표준 정의를 기본으로 쓰고 이 제안은 반론으로만 싣는다.
- **멈춤 스위치·우아한 성능 저하**: OpenAI 백서는 중단 가능성을 「a critical backstop」으로 보고, 특정 행동 범주만 멈추는 것과 전체 중단을 둘 다 갖추라고 쓴다. 중간에 끊겼을 때를 대비해 폴백 절차를 미리 만들어 두라는 원칙도 같은 절(§4.7)에 있다(**E4**). EU AI Act 14조 4항 e호의 「halt in a safe state」([02](02-가역성과-영향-크기로-나누는-승인-게이트.md))도 같은 쪽이다. 둘 다 결국 「무엇이 안전 상태인가」를 묻는다.
- **하이닉스 적용 예**(추론): 「학습한 레시피·장비·제품 범위 밖이면 AI 는 판정하지 않고 넘긴다.」 안전 상태 = LOT hold·마지막으로 검증된 레시피. 범위 밖 입력에도 확신 있는 답을 내는 AI 는 유효 범위를 정의하지 않은 AI 다.
- **기준선과 지표**: 지금 = AI 가 아는 범위를 밝히지 않는 서비스(가정). 지표 = 범위 밖으로 넘긴 건수와 이유별 분포, 넘김의 사람 시간 대 놓침의 웨이퍼 비용(기대손실 결정표).
- **6시간 최소 형태**: 화면 = 「AI 판정 가능 범위」 카드. 지원 제품·공정·장비 목록 + 입력 건강 상태(센서 결측률·분포 이탈 점수). 범위 밖이면 판정 칸 대신 「사람에게 넘김 — 이유: 신규 레시피 v3.2」 배지. 상단에 「AI 끄기(행동 범주별 / 전체)」 토글과 끈 뒤의 기본 동작 표시. 데이터 = 유효 범위 정의 YAML(허용 값 목록·범위) + 입력 스냅샷. 계산 = 범위 검사 규칙 + 간단한 분포 이탈 점수(학습 구간 평균·표준편차 대비 z, 또는 마할라노비스 거리). 이탈이면 판정 생략.
- **반론과 답**: 「범위를 좁히면 쓸 데가 없다」 → 범위 밖 건을 숨기지 않고 **세어서 보여 준다**(「이번 주 범위 밖 23건 — 신규 레시피 15건」). 이 숫자가 다음 학습·확장 목록이 된다([03](03-그림자-모드와-승격-기준.md)과 연결). 「분포 이탈 점수도 틀린다」 → 맞다. 그래서 이탈 판정은 보수적으로(넘김 쪽으로) 둔다. 넘김의 비용은 사람 시간이고, 놓침의 비용은 웨이퍼다(기대손실 결정표 로 비교).
