# 그림자 모드에서 자동까지 — 단계적 확대와 승격 기준

> [자율성 설계](README.md) › 03 · 짝 기법: [몬테카를로](../../../methods/확률과-시뮬레이션/03-몬테카를로.md) · [계측 샘플 배분](../../../methods/품질과-신뢰성-통계/04-계측-샘플-배분.md) · [민감도 분석](../../../methods/의사결정분석/02-민감도와-가정-바꿔-보기.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 도입을 그림자 → 권고 → 승인 후 실행 → 자동 + 장부 4칸 사다리로 두고 승격·강등 조건을 숫자로 적는다.
- **필요한 데이터**: 과거 사례(합성 가능) N건에 AI 판정과 사람 판정을 함께 둔 표. 사람 판정이 없으면 일치율을 못 낸다.
- **6시간 최소 형태**: 일치율·누락률의 신뢰구간(몬테카를로) → 승격 조건 충족까지 필요한 건수. 화면: 사다리 4칸 + 칸별 들어오는/나가는 조건 카드.
- **반문 하나**: 「그림자 모드 기간이 길면 도입이 늦다」 → 행동별로 따로 승격한다. 되돌릴 수 있는 행동은 짧게, 없는 행동은 길게 둔다.
- **하지 말 것**: 「누락 0건 + 일치율 하한 95% + 최소 n 건」은 예시 숫자다. 현업이 정한 기준처럼 말하지 않는다.

## 상세

**한 줄**: 「릴리스 공학에서는 새 변경이 실제 운영에서 문제를 일으키는 문제를 시험 환경이 운영과 같지 않은 상황에서 풀 때 카나리(작은 비율·짧은 시간 노출 후 평가)와 트래픽 티잉(복사본만 처리하고 응답은 버림)을 쓴다. 「서버 트래픽」을 LOT·장비군으로, 「새 바이너리」를 AI 판정 규칙으로 바꾸면, AI 자율성을 데이터로 한 단계씩 올리는 도입 계획이 된다.」
- **과제 문구 신호**(추론): 「현장 도입」「파일럿」「단계적 적용」「검증 후 확대」「기존 방식 대비」
- **가정 변환**

| 원 분야 | 반도체 현장 |
|---|---|
| 트래픽 5% 카나리 | 한 장비군·한 제품·한 교대조만 |
| 티잉(응답 버림) | 그림자 모드 — AI 판정은 기록만 하고 실제 처리는 사람 판정대로. 둘을 비교 |
| 평가 지표(SLI) | AI-사람 판정 일치율, 놓친 이상(누락), 헛 hold(오경보), 판정까지 시간 |
| 오류 예산 | 단계별 허용 누락 건수([SLO와 오류 예산](../../공학/신뢰성공학/01-SLO와-오류-예산.md)) |
| 롤백 | 자율성 단계 강등(자동 → 승인 후 실행) |
| 상태 있는 시스템의 한계 | 그림자 모드는 「AI 판정대로 했으면 어떻게 됐을지」(반사실)를 못 보여 준다 → 사람이 다르게 처리한 건만 사후 검토 |

- **원 분야 사실**:
  - Google SRE 워크북은 카나리를 「a partial and time-limited deployment of a change in a service and its evaluation」로 정의한다.
  - 티잉은 운영 시스템이 실제 응답을 내는 동안 「the canary deployment serves the copy and discards the responses」하는 방식이다.
  - 이게 **그림자 모드**다. 다단계 카나리는 첫 단계를 작게 시작해 통과하면 모집단을 넓힌다(SRE Workbook 16장, **E3**, 본문 판독).
  - **한계**(같은 출처): 티잉은 「doesn't adequately identify risk in stateful systems」이고, 동시에 여러 카나리를 돌리지 말라고 한다.
- **올리는 길과 내리는 길**: 조정 가능 자율성 쪽에서는 Falcone·Castelfranchi 가 자율성 조정이 「bilateral」이고 「bidirectional」이며, 위임자 쪽의 「crisis of trust」로도 바뀐다고 정리했다(2001, **E2**, 초록 기준). 올리기만 하는 것이 아니라 내리는 길도 설계 대상이다.
- **하이닉스 적용 예**(추론): 한 라인·한 장비군부터 그림자 모드로 시작해, 「그림자 → 권고 → 승인 후 실행 → 자동 + 장부」로 행동별로 승격한다. 야간·교대 인계 시간에는 권고만, 안정 구간에는 자동 같은 시간대·상태별 단계도 같은 틀이다.
- **기준선과 지표**: 지금 = 승격 기준이 숫자로 없는 「검증 후 확대」 계획(가정 — 숫자와 강등 조건이 없으면 계획이 아니다). 지표 = 일치율·누락률의 신뢰구간, 승격 조건 충족까지 필요한 건수.
- **6시간 최소 형태**: 화면 = 가로 사다리 4칸(그림자 → 권고 → 승인 후 실행 → 자동 + 장부). 칸마다 「들어오는 조건 / 나가는(강등) 조건」 카드, 현재 위치 표시. 데이터 = 과거 사례(합성) N 건에 AI 판정과 사람 판정을 함께 둔 표. 계산 = 일치율·누락률의 신뢰구간(몬테카를로) → 「승격 조건 충족까지 필요한 건수」. 승격 조건 예: 「누락 0건 + 일치율 하한 95% 이상 + 최소 n 건」. 숫자는 예시이며 현업이 정한다.
- **반론과 답**: 「그림자 모드 기간이 길면 도입이 늦다」 → 행동별로 따로 승격한다([01](01-행동별-자율성-단계표.md) 행 단위). 되돌릴 수 있는 행동은 짧게, 되돌릴 수 없는 행동은 길게 둔다. 「사람 판정이 정답이 아닐 수도 있다」 → 맞다. 비교 기준은 「사람 판정 + 사후 확인 결과(계측·수율)」로 둔다. 불일치 건은 사후 검토 큐로 보낸다([블레임리스 포스트모템](../../공학/신뢰성공학/02-블레임리스-포스트모템.md)).
