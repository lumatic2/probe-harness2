# 행동별 자율성 단계표 — 「AI 제시, 사람 판단」을 칸으로 쪼갠다

> [자율성 설계](README.md) › 01 · 짝 기법: [기대손실 결정표](../../../methods/의사결정분석/01-기대손실-결정표.md) · [질문을 파라미터로](../../../methods/최적화/05-질문을-파라미터로.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: AI 조치 도우미가 어디까지 맡는지를 행동 8~12개 × 4기능 칸의 자율성 단계표 한 장으로 보인다.
- **필요한 데이터**: 행동 목록 + 결과 비용 등급, AI 과거 적중률(합성·과거 사례 가능). 행동 목록과 비용 등급이 없으면 못 쓴다.
- **6시간 최소 형태**: 칸 단계 = f(결과 비용, AI 과거 적중률) 규칙표 한 장. 화면: 행동(행) × 4기능(열) 표, 칸 = 단계 1~6, 색 = 지금 / 다음 승격 후보.
- **반문 하나**: 「단계표는 문서일 뿐, 실제 시스템이 지키나?」 → 표를 설정 파일로 두고 서버가 실행 전에 읽어 게이트를 건다.
- **하지 말 것**: 사내 AI 의 실제 권한 단계는 근거 없음(가정)이다. 실험실 과제(Endsley–Kaber)를 현장 일반화로 말하지 않는다(추론).

## 상세

**한 줄**: 「인간-자동화 상호작용 연구에서는 어떤 기능을 얼마나 자동화할지 정하는 문제를 항공·원전처럼 사람이 자동화를 감독하는 상황에서 풀 때 4기능 × 단계 모형을 쓴다. 「조종사·운전원」을 팹 엔지니어·교대 운영자로, 「항공 기능」을 이상 감지 → 원인 분석 → 조치 선택 → 조치 실행으로 바꾸면, AI 조치 도우미가 어디까지 맡는지를 칸 단위로 보이는 설계 표가 된다.」
- **과제 문구 신호**(추론): 「AI 가 의사결정 지원」「엔지니어 판단 보조」「자동화」「어디까지 자동으로」「현업이 최종 결정」
- **가정 변환**

| 원 분야 | 반도체 현장 |
|---|---|
| 조종사·원전 운전원 | 설비·공정 엔지니어, 교대 운영자 |
| 정보 수집(센서·레이더) | FDC 신호·계측값·MES 이력 조회 (읽기 전용 스냅샷) |
| 정보 분석(경보·예측) | 이상 원인 후보·영향 LOT 범위 추정 |
| 결정·행동 선택 | 조치 후보(관찰 / 재측정 / hold / PM 요청) 순위 |
| 행동 실행 | MES hold 입력, 레시피 변경, 작업 지시 발행 |
| 결과 비용(2차 기준) | 오판 시 스크랩 웨이퍼·장비 정지 시간·고객 영향 |

- **원 분야 사실**:
  - 저자들은 자동화가 「1) information acquisition; 2) information analysis; 3) decision and action selection; and 4) action implementation」 네 기능에 적용될 수 있고, 각 기능 안에서 「a continuum of levels from low to high」를 갖는다고 했다.
  - 또 「A particular system can involve automation of all four types at different levels」라고 썼다(Parasuraman·Sheridan·Wickens 2000, **E2**, 초록 기준).
  - 평가 기준은 1차가 사람 수행 결과이고, 2차로 「automation reliability and the costs of decision/action consequences」를 든다(같은 초록).
  - Sheridan–Verplank(1978)는 감독 제어 보고서로, 흔히 인용되는 10단계 척도의 출처다(**E3**, 초록 기준 — 단계별 문구는 2차이고 **원문 미확인**).
- **조건·반례**:
  - Endsley–Kaber 실험(피험자 30명, 모의 동적 제어 과제)에서 실행 자동화는 「only under normal operating conditions」에서 이로웠다.
  - 그리고 「removal of the operator from task implementation is detrimental to performance recovery if the automated system fails」였다.
  - 같은 실험에서 「Joint human/system option generation significantly degraded performance」였다(**E2**, 초록 기준).
  - 즉 사람과 AI 가 같이 대안을 만드는 칸은 오히려 나빴다. 「AI 가 대안을 만들고 사람이 고른다」를 지지하는 쪽으로 읽힌다(추론 — 실험실 과제라 현장 일반화는 추론).
- **열 이름 후보**: AI 에이전트 자율성 연구는 사용자 역할을 「operator, collaborator, consultant, approver, and observer」로 나눈다(arXiv 2506.12469, **E3** 프리프린트, 초록 기준). 아래 6단계 표의 이름과 거의 겹친다. Horvitz(1999)는 자동 서비스와 직접 조작을 「elegant coupling」하는 원칙을 다룬다(**E2**, 초록 기준) — 「AI 가 후보 제시, 사람이 고름」 칸에 흡수했다.
- **하이닉스 적용 예**(추론): 회사 원칙 「AI가 원인과 대응 방안을 제시하고, 사람은 최종 판단」(2026 미래포럼, 근거 참조)을 위 틀로 옮기면 **「정보 분석은 높게, 결정 선택은 중간, 실행은 낮게」**가 된다. FDC 알람 해석(분석)은 높게, 장비 정지·레시피 변경(실행)은 낮게 하는 식이다. 「어디까지 맡기나」를 물으면 원칙을 되풀이하는 대신 칸 단위로 답한다.
- **기준선과 지표**: 지금 = 원칙 한 줄만 있고 칸 구분은 없다(가정). 하이닉스 사내 AI 의 실제 권한 단계(읽기 전용인지, MES 쓰기를 하는지)는 공개 자료 **근거 없음**. 지표 = 행동별 단계, 결과 비용 등급, AI 과거 적중률.
- **6시간 최소 형태**: 화면 = 행(서비스 행동 8~12개) × 열(4기능), 칸 = 단계(1 사람이 함 · 2 AI 가 후보 제시 · 3 AI 가 하나 추천 · 4 승인하면 실행 · 5 거부 안 하면 n 분 뒤 실행 · 6 실행 후 통보). 색 = 「지금 단계 / 다음 승격 후보」. 데이터 = 행동 목록 + 결과 비용 등급([02](02-가역성과-영향-크기로-나누는-승인-게이트.md)). 계산 = 칸 단계 = f(결과 비용, AI 과거 적중률) 규칙표 한 장(적중률은 합성·과거 사례로 표시만).
- **반론과 답**: 「단계표는 문서일 뿐, 실제 시스템이 지키나?」 → 단계표를 설정 파일로 두고, 서버가 행동을 실행하기 전에 이 표를 읽어 게이트를 건다([02](02-가역성과-영향-크기로-나누는-승인-게이트.md)와 같은 코드). 「표 = 실행 규칙」임을 시연한다. 「10단계는 너무 잘다」 → 화면에는 4~6단계로 접는다. 위 초록도 단계는 연속체라고 했고 특정 개수를 고집하지 않는다.
- **서술형 답 한 줄**(추론): 「우리 AI 는 더 할 수 있지만 일부러 이만큼만 합니다.」 능력과 허용 단계를 분리한 프레임워크(arXiv 2607.23438, **E4** 프리프린트·자사 단일 사례, 초록 기준)가 근거다. 능력이 높아도 위험·가역성·조직 준비도 때문에 낮은 허용 단계에 묶는다는 내용이다.
