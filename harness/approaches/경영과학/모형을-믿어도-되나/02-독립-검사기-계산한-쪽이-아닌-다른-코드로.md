# 독립 검사기 — 계산한 쪽이 아닌 다른 코드로 다시 센다

> [모형을 믿어도 되나](README.md) › 02 · 짝 기법: [제약 프로그래밍 일정](../../../methods/최적화/01-제약-프로그래밍-일정.md) CP-SAT 잡숍 (+[기대손실 결정표](../../../methods/의사결정분석/01-기대손실-결정표.md) · [파레토 프런티어](../../../methods/최적화/04-파레토-프런티어.md) · [강건·시나리오 계획](../../../methods/확률과-시뮬레이션/04-강건-시나리오-계획.md) · [대기행렬과 운영 곡선](../../../methods/확률과-시뮬레이션/02-대기행렬과-운영-곡선.md))
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 「위반 0건」 주장을 솔버와 다른 코드(스케줄 표만 읽는 검사기)와 작은 사례의 전수 탐색 대조로 뒷받침한다.
- **필요한 데이터**: 솔버가 낸 스케줄 CSV(겹침·정지창·Q-Time 를 재계산할 열). 스케줄 CSV 가 없으면 검사기를 못 만든다.
- **6시간 최소 형태**: 검사기는 솔버 모듈을 import 하지 않고 스케줄 CSV 만 읽는다(30분). 화면: 「검사기 위반 0건」 배지 + 검사 항목 목록 + 마지막 실행 시각.
- **반문 하나**: 「검사기도 틀릴 수 있다」 → 맞다. 검사기를 솔버보다 단순하게 쓰고, 일부러 위반을 넣은 입력을 잡는지 한 번 확인한다.
- **하지 말 것**: 하드체크를 지우거나 완화하지 않는다. 시간 제한이 걸린 솔버의 제출 숫자는 마지막 실행 값으로 고정한다.

## 상세

**한 줄**: 「경영과학 실무에서는 솔버가 낸 해를 믿기 전에 솔버와 다른 코드로 해의 조건을 다시 확인한다. 핵심 논리는 「최적이라고 답한 쪽이 검사까지 하면 같은 실수를 두 번 한다」다. 솔버 변수를 쓰지 않고 스케줄 표만으로 겹침·정지창·Q-Time 위반을 다시 세고, 작은 사례는 전수 탐색과 대조하면 「위반 0건」 주장의 증거가 된다. 검사기 통과 여부와 전수 탐색 일치 여부로 보인다.」
- **과제 문구 신호**(추론): 「위반 0건」「검증」「정확도」「믿을 수 있나」「재현」
- **가정 변환**

| 계산 쪽 | 검사 쪽 |
|---|---|
| 솔버 변수 · 최적 판정 | 스케줄 표만 받아 행렬곱·pandas 로 다시 센 위반 건수 |
| 최적성 주장 | 작은 사례 전수 탐색과 일치 확인 |
| 근사식 | 시뮬레이션과 비교하고 오차를 숫자로 적는다 |
| 데이터 교체 | 바꾼 데이터에서도 통과 문구가 나와야 주장한다 |

- **원 분야 사실**:
  - 외부 문헌이 아니라 이 레포 기법 문서의 실행 기록이다. 20개 코드를 일괄 실행했고(2026-11-08, Windows, 새 venv) 전부 종료코드 0이었으며, 끝의 독립 하드체크가 통과해야 통과 문구가 찍힌다(방법론 지도 README).
  - 예: 강건·시나리오 계획 는 3⁹=19,683개 배정을 솔버와 다른 코드로 전수 평가해 CP-SAT 값과 일치를 확인하고, 기대손실 결정표 는 격자로 훑은 전환점과 해석적 경계를 대조하고, 대기행렬과 운영 곡선 는 근사식을 Lindley 재귀 시뮬레이션과 비교해 비포아송 도착에서 7.2% 오차임을 수치로 보인다(각 기법 문서).
  - 솔버 결과를 별도 검사기로 다시 확인하는 것이 「위반 0건」 주장의 증거라는 점은 이 선반의 추론이다.
- **하이닉스 적용 예**(추론): (a) 제출물에 「위반 0건」을 쓸 때 검사기 출력을 같이 둔다(유형 ②). (b) 제출물의 README·코드를 누가 읽든 설명문의 숫자와 코드 출력이 같아야 한다. (c) 제출물에 쓰는 숫자는 시간 제한이 걸린 솔버(제약 프로그래밍 일정·롤링 호라이즌·최소 변경 재스케줄)의 마지막 실행 값으로 고정한다.
- **기준선과 지표**: 기준선 = 검사기 없는 솔버 출력. 지표 = 검사기 위반 0건, 전수 탐색 일치, 근사 오차 %.
- **6시간 최소 형태**: 검사기는 솔버 모듈을 import 하지 않고 스케줄 CSV 만 읽는다(30분). 화면 모서리에 「검사기 위반 0건」 배지, 검사 항목 목록, 마지막 실행 시각. 하드체크를 지우거나 완화하지 않는다.
- **반론과 답**: 「검사기도 틀릴 수 있다」 → 맞다. 그래서 검사기를 솔버보다 단순하게 쓰고(행렬곱·집계), 일부러 위반을 넣은 입력으로 검사기가 잡는지 한 번 확인한다. 「시간 제한 때문에 실행마다 숫자가 다르다」 → 방향만 말하고 제출 숫자는 마지막 실행 값으로 고정한다.
