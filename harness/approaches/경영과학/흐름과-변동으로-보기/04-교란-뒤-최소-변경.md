# 교란 뒤 최소 변경 — 장비 다운과 긴급 LOT 이후의 재스케줄

> [흐름과 변동으로 보기](README.md) › 04 · 짝 기법: [최소 변경 재스케줄](../../../methods/최적화/03-최소-변경-재스케줄.md) 최소 변경 재스케줄 (+[제약 프로그래밍 일정](../../../methods/최적화/01-제약-프로그래밍-일정.md) · [강건·시나리오 계획](../../../methods/확률과-시뮬레이션/04-강건-시나리오-계획.md) · [질문을 파라미터로](../../../methods/최적화/05-질문을-파라미터로.md))
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 장비 다운·긴급 LOT 뒤 처음부터 다시 짜지 않고 「KPI + λ × 변경 수」로 바뀐 LOT 수 대 완료 시각 곡선을 그린다.
- **필요한 데이터**: 현행 일정(기존 배정), 장비 다운·긴급 LOT 사건, 동결·정지창. 기존 배정이 없으면 변경 수를 못 센다.
- **6시간 최소 형태**: 일정 모형에 「기존 배정과 다르면 +벌점」 항을 넣고 λ 를 쓴다. 화면: 변경 수 대 완료 시각 곡선 + 기존/신규 간트(바뀐 LOT 강조) + λ 슬라이더.
- **반문 하나**: 「그냥 다시 짜는 게 최적 아닌가」 → 완료 시각만 보면 맞다. 현장이 감당할 변경 수가 따로 있어 두 축으로 보인다.
- **하지 말 것**: SWISS·AA HEAT 수치는 시스템 전체 효과다 — 「변경 최소화」 항 단독 효과나 하이닉스 효과로 말하지 않는다.

## 상세

**한 줄**: 「경영과학에서는 고장·지연 같은 교란이 일어난 뒤 일정을 복구할 때 처음부터 다시 짜지 않고, 남은 일정의 KPI 와 현행 계획에서 바뀐 정도를 함께 줄인다. 핵심 논리는 「목적 = KPI + λ × 변경 수」이고 λ 를 쓸어 트레이드오프 곡선을 그린다. 항공기·승무원을 LOT·장비로, 운항 교란을 장비 다운·긴급 LOT 으로 바꾸면 교대 중 재배정에 적용된다. 바뀐 LOT 수 대 완료 시각 곡선으로 보인다.」
- **과제 문구 신호**(추론): 「장비가 멈췄다」「긴급 LOT 이 들어왔다」「기존 일정을 최대한 유지」「현장 혼란을 줄여라」「다시 짜면 다 바뀐다」
- **가정 변환**

| 원 분야 | 반도체 |
|---|---|
| 운항 교란 | 장비 다운, 긴급 LOT 투입 |
| 동결 | 이미 시작한 공정(`start < t_now`)은 그대로 — 안 지키면 되돌릴 수 없는 해가 나온다 |
| 변경 | 장비가 바뀌었거나 시작이 허용오차(TOL)를 넘게 움직인 LOT — 정의가 결과를 좌우한다 |
| 투입 조절 | 병목이 느려질 때 앞 공정 투입 시각을 함께 늦춘다(재배정보다 작은 조치) |

- **원 분야 사실**:
  - Lufthansa Group/SWISS(+Google Research) 2025 Edelman 결선: 「This system is used by Lufthansa’s subsidiary, SWISS International Airlines, saving 12 million euros and reducing CO2 emissions by 14,000 tons.」(INFORMS 결선 발표, E2, 자기 신고, 방법 세부 미확인).
  - American Airlines HEAT 2024 결선: 「prevented nearly 1,000 flight cancellations across the network」(같은 종류의 발표, 자기 신고, 세부 미확인).
  - 이 수치는 시스템 전체 효과이지 「변경 최소화」 항 단독 효과가 아니다(최소 변경 재스케줄 문서).
- **하이닉스 적용 예**(추론): (a) 장비 다운 뒤 현행 일정에서 가장 적게 바꾸는 재배정(유형 ②①). (b) 사전 대비는 [분포·강건](03-평균-말고-분포로-말한다.md), 사후 복구는 이 챕터로 나눈다. (c) AA HEAT 처럼 앞 공정 투입 시각을 늦추는 조치는 Q-Time 초과를 막는 후보다 — 이식은 추론이고 세부도 확인하지 못했다.
- **기준선과 지표**: 기준선 = 처음부터 다시 푼 해(λ=0)와 현행 일정 유지(λ→∞). 지표 = 변경 LOT 수 대 완료 시각 곡선, 검사기 위반 0건, 현장이 받아들일 변경 수 상한.
- **6시간 최소 형태**: 제약 프로그래밍 일정 모형에 「기존 배정과 다르면 +벌점」 항 추가(최소 변경 재스케줄), 동결·정지창 검사 포함. 화면 = 변경 수 대 완료 시각 곡선 + 기존/신규 간트를 위아래로 두고 바뀐 LOT 만 강조색, λ·TOL 슬라이더. 질문창(질문을 파라미터로)과 한 화면에 붙인다. CP-SAT 시간 제한이 걸리면 곡선이 들쭉날쭉할 수 있어 제출 숫자는 마지막 실행 값으로 고정한다.
- **반론과 답**: 「그냥 다시 짜는 게 최적 아닌가」 → 완료 시각만 보면 맞다. 현장이 바뀐 LOT 수를 감당하는 크기가 따로 있어 두 축으로 보인다([05](../모형으로-다시-쓰기/04-실행-가능한-해와-사람-승인.md)). 「진행 중 공정은 중단하나」 → 현업 규칙이다. 코드는 마친 뒤 정지로 가정했다고 화면에 적는다.
