# 결정변수·목적·제약으로 다시 쓰기 — 과제 문장을 모형 세 칸으로

> [모형으로 다시 쓰기](README.md) › 01 · 짝 기법: [제약 프로그래밍 일정](../../../methods/최적화/01-제약-프로그래밍-일정.md) CP-SAT 잡숍 · [선형·정수계획](../../../methods/최적화/02-선형-정수계획.md) LP/MIP
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 과제 문장을 결정변수·목적·제약 세 칸 표로 먼저 옮기고, 비는 칸은 현업 질문 목록으로 올린다.
- **필요한 데이터**: lot, step, 장비 후보, 공정시간, PM 창, Q-Time 규칙. 「무엇을 바꿀 수 있나」가 안 보이면 모형 이전의 범위 문제다.
- **6시간 최소 형태**: 코딩 전 세 칸 표(30분) → 제약 프로그래밍 일정. 화면: 세 칸 표 + 장비별 간트 + 「검사기 위반 0건」 배지.
- **반문 하나**: 「모형이 현실을 너무 단순화한다」 → 맞다. 단순화 항목을 화면에 적고, 결론이 뒤집히는지는 민감도로 본다.
- **하지 말 것**: 기준선 없는 「30% 개선」을 말하지 않는다. SK하이닉스의 OR 효과 수치는 공개 자료에서 근거 없음.

## 상세

**한 줄**: 「경영과학에서는 말로 된 현장 문제를 계산할 수 있는 꼴로 옮겨야 할 때 결정변수·목적·제약 세 칸으로 다시 쓴다. 핵심 논리는 「무엇을 바꿀 수 있나(변수), 무엇을 좋게 하려나(목적), 무엇은 어길 수 없나(제약)」다. 결정변수를 LOT×장비 배정과 시작 시각으로, 제약을 장비 겹침 금지·공정 선후·Q-Time 상한·PM 정지창으로 바꾸면 Q-Time 일정 문제에 적용된다. 현행 방식을 같은 데이터로 재현해 두고 위반 건수와 완료 시각으로 비교해 보인다.」
- **과제 문구 신호**(추론): 「일정을 짜라」「배정」「LOT 우선순위」「위반 0건」 / 「제안하라」「개선하라」만 있고 무엇을 바꿀 수 있는지 안 보일 때
- **가정 변환**

| 과제 문장 | 모형 칸 |
|---|---|
| 「어느 장비에 언제 넣나」 | 결정변수 — 공정별 장비 선택, 시작 시각 |
| 「Q-Time 을 넘기지 않게」 | 제약 — 다음 공정 시작 − 앞 공정 종료 ≤ 상한 |
| 「PM 시간은 피해서」 | 제약 — 장비별 고정 구간 |
| 「빨리 끝내라 · 지연을 줄여라」 | 목적 — 완료 시각(makespan) 또는 가중 지연 |
| 「현장이 받아들일 수 있게」 | 제약 또는 목적의 벌점 — [04](04-실행-가능한-해와-사람-승인.md) |
| 「얼마나 좋아졌나」 | 기준선 — 현행 규칙을 같은 데이터로 재현 |

- **원 분야 사실**:
  - Google OR-Tools 잡숍 문서는 일정을 장비별 겹침 금지(no-overlap)·선후 제약·makespan 목적으로 쓴다(E2, 공식 문서 서술).
  - 솔버가 OPTIMAL 이라고 답하면 「이 제약 아래 이보다 짧은 일정은 없다」는 증명까지 딸려 온다(제약 프로그래밍 일정 문서). Samsung SLIM 은 단계별 목표 사이클타임·목표 WIP 를 계산하는 데서 출발했다(Interfaces, E2 — 저자가 컨설팅 수행사 대표라 이해관계가 있다).
  - 변수·목적·제약 세 칸의 정의 자체는 교과 일반이라 출처를 달지 않았다(추론).
- **하이닉스 적용 예**(추론): (a) Q-Time 을 지키는 LOT×장비 일정(유형 ②). (b) 변수가 안 보이면 그 칸을 비워 두고 현업 질문으로 올린다 — 「무엇을 바꿀 수 있나」가 답이 안 나오는 과제는 모형 이전에 범위 문제다. 공식 채널에 Q-Time 폐기 손실·LOT 우선순위·지능형 스케줄링이 반복 등장하지만, SK하이닉스의 OR 효과 수치는 공개 자료에서 **근거 없음**.
- **기준선과 지표**: 기준선 = 현행 규칙(예: FIFO — 실제 규칙은 미확인, 가정)을 같은 데이터·같은 KPI 로 재현한 값. 지표 = 독립 검사기가 센 Q-Time 위반 건수, 완료 시각, 가중 지연. 기준선 없는 「30% 개선」은 약하다.
- **6시간 최소 형태**: 코딩 전에 세 칸 표를 먼저 쓴다(30분). 데이터 `lot, step, 장비 후보, 공정시간, PM 창, Q-Time 규칙`. 계산 = 제약 프로그래밍 일정. 화면 = 세 칸 표 + 장비별 간트 + 「검사기 위반 0건」 배지. 모형이 단순화한 것(소수 공정시간 반올림 등)은 표 아래 한 줄로 적는다.
- **반론과 답**: 「모형이 현실을 너무 단순화한다」 → 맞다. 단순화한 항목을 화면에 적고, 결론이 뒤집히는지는 [민감도](../모형을-믿어도-되나/01-가정이-틀리면-민감도와-뒤집히는-경계.md)로 본다. 「규칙이 문서로 정리돼 있지 않다」 → 비는 제약 칸을 그대로 현업 질문 목록으로 쓴다.
