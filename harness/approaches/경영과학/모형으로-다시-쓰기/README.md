# 모형으로 다시 쓰기 — 학문 지도

> [입구](../../README.md) › [경영과학](../README.md) › **모형으로 다시 쓰기** · 챕터 4
> 한 줄: **경영과학**은 현장 문제를 결정변수·목적·제약으로 다시 써서 계산할 수 있는 꼴로 만들고, 그 답을 사람이 고를 수 있는 선택지로 돌려준다.
> **주의**: 이 모듈은 「어떻게 다시 쓰나」만 다룬다. 계산하는 법과 코드는 [기법·코드 선반](../../../methods/README.md)(기법 18개)에 있고 챕터 끝 「짝 기법」로만 잇는다. 사례 효과 수치는 모두 기업·팀의 자기 신고라 하이닉스 효과로 쓰지 않는다.

## 핵심 질문
**무엇을 바꿀 수 있고, 무엇을 좋게 하려 하며, 무엇은 어길 수 없나? 그리고 그 답을 누가 고르나?**

## 이럴 때 꺼낸다 / 옆 모듈로
- **꺼낸다**: 과제가 「개선하라」「제안하라」로만 적혀 변수가 안 보일 때 · 목표가 둘 이상 부딪칠 때 · 규정(Q-Time)을 어떻게 모형에 넣을지 정할 때 · 현업이 「만약 ~면?」을 묻게 해야 할 때 · 솔버 결과를 현장에 내려보내야 할 때.
- **옆 모듈로**
  - 병목·가동률·교란 뒤 복구·분포로 말하기 → [흐름과 변동으로 보기](../흐름과-변동으로-보기/README.md)
  - 가정이 틀릴 때·검사기·효과 수치 읽기 → [모형을 믿어도 되나](../모형을-믿어도-되나/README.md)
  - 판정 금액(재작업·폐기·진행의 기대 손익) → 회계학 › [원가관리회계](../../회계학/원가관리회계/README.md)
  - 기대값·정보의 가치 → 기대손실 결정표 결정분석

## 핵심 개념어
- **결정변수**: 사람이 정할 수 있는 값. 정할 수 없는 것은 데이터다.
- **목적함수**: 좋음의 정의. 한 줄로 쓰지 못하면 [트레이드오프](02-목적이-둘이면-트레이드오프-곡선.md)다.
- **하드 제약 / 소프트 제약**: 어기면 해가 아닌 규칙 / 어기면 값을 치르는 규칙.
- **실행 가능 해(feasible)**: 모든 제약을 지키는 해. 최적해는 그중 목적이 가장 좋은 해다.
- **INFEASIBLE**: 모든 제약을 동시에 지키는 해가 없다는 솔버의 답. 어느 제약이 부딪쳤는지 알아내라는 신호다.
- **파레토 프런티어**: 하나를 좋게 하면 다른 하나가 나빠지는 해들의 경계.
- **파라미터 diff**: what-if 질문을 입력의 변경분으로 쓴 것.

## 관점 쌍
- **최적해 ↔ 선택지와 대가**: 수상 사례들은 효과를 「더 많은 시나리오를 더 짧은 시간에」로 말했다. 최적해의 정확도를 자랑한 문장은 없었다.
- **하드 ↔ 벌점**: 운영은 하드, 진단은 벌점([03](03-깰-수-없는-규칙과-값을-매길-규칙.md)).
- **완료 시각 ↔ 현장이 받아들일 변경**: 가장 빠른 일정이 가장 적게 바뀐 일정은 아니다([04](04-실행-가능한-해와-사람-승인.md)).

## 이 분야 사람이 먼저 묻는 것 5
1. 결정변수가 무엇인가? 사람이 실제로 바꿀 수 있는 값인가?
2. 목적이 하나인가, 둘인가? 둘이면 어느 점을 누가 고르나?
3. 어길 수 없는 규칙은 어느 것이고, 풀리지 않으면 어떻게 진단하나?
4. 이 해를 솔버와 다른 코드로 확인했나?
5. 비교할 기준선(현행 규칙)이 같은 데이터·KPI 로 재현됐나?

## 흔한 함정
- 변수가 안 보이는데 모형부터 짠다([01](01-결정변수-목적-제약으로-다시-쓰기.md)).
- 규정을 전부 하드로 두고 INFEASIBLE 에서 멈춘다([03](03-깰-수-없는-규칙과-값을-매길-규칙.md)).
- 위험 점수를 확률처럼 읽고 곡선을 원화로 바로 환산한다([02](02-목적이-둘이면-트레이드오프-곡선.md)).
- 솔버가 낸 「위반 0건」을 같은 솔버로 검증한다([04](04-실행-가능한-해와-사람-승인.md)).
