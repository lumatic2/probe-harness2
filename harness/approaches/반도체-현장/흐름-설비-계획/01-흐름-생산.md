# 흐름·생산 관점 — 「웨이퍼는 어디서 기다리나」

> [흐름-설비-계획](README.md) › 01 · 짝 기법: [디스패칭 규칙 시뮬레이션](../../../methods/확률과-시뮬레이션/01-디스패칭-규칙-시뮬레이션.md), [대기행렬과 운영 곡선](../../../methods/확률과-시뮬레이션/02-대기행렬과-운영-곡선.md), [병목 분석](../../../methods/생산과-재고-운영/01-병목-분석.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 「대기시간·사이클타임·WIP」 과제에서 리틀의 법칙 검산과 장비군별 대기 시간 합 순위로 먼저 병목을 짚는다(추론).
- **필요한 데이터**: 로트 이력(`lot_id, current_step, arrive_time, start_time`)과 장비 상태 — 없으면 장비군별 대기시간을 못 잰다(추론).
- **6시간 최소 형태**: 로트 이력 CSV → 장비군별 「대기 시간 합」 순위 + 리틀의 법칙 검산 / 「사이클타임을 가장 많이 먹는 장비군 Top 5」.
- **반문 하나**: 「평균 말고 p90 은요?」 → 평균은 극단 대기를 숨기므로 평균과 p90 을 같이 보인다(추론).
- **하지 말 것**: FabTime 응답 건수를 비율로 쓰기, 판매사 예시 수치(80.1%·15% 버퍼)를 우리 팹 값으로 말하기.

## 핵심
- **이 눈이 던지는 질문**: 웨이퍼가 어디서 기다리나? 오늘 무엇을 먼저 돌리나?
- **과제 문구 신호**(추론): 「대기시간」「사이클타임·TAT」「WIP」「Q-time 위반」「디스패칭」「납기」
- **핵심 지표와 공식**(원문 표는 부록)

| 지표 | 뜻 | 근거 |
|---|---|---|
| 리틀의 법칙 L = λW | 평균 재공(WIP) = 평균 처리율 × 평균 체류시간 — 처리율이 같으면 사이클타임을 줄이는 것과 WIP 를 줄이는 것은 같은 말 | Little(2011) |
| TAT(Turn Around Time) | 투입부터 모든 공정을 거쳐 나올 때까지 총 시간 | 뉴스룸 각주 |
| X-factor | 실제 사이클타임 ÷ 이론(순수 가공) 사이클타임 | 정의식은 검색 요약(원문 미확인) |
| 운영 곡선 | 병목 가동률이 100% 에 다가갈수록 대기시간이 비선형으로 폭증, 변동을 줄이면 곡선이 눕는다 | 예시 수치는 부록 |
| 완충 용량 | 장비를 100% 로 계획하지 않고 남겨 두는 몫 — 대수가 있는 장비군 기준 | INFICON(E3) |
| Q-time 위반률 | 앞 공정 뒤 정해진 시간 안에 다음 공정을 못 시작하면 앞 공정부터 다시 함 | 부록 「Q-time」 |

- **결정 직무**: 양산관리(SK하이닉스) — 생산 계획·Capa·물류. 매일 디스패칭, 매주 부서 간 「데이터의 의미를 통일하는」 회의(부록 「결정 직무」).
- **데이터**: MES 로트 이력·경로·장비 상태. 컬럼 예 로트 `lot_id, priority, due_date, current_step, arrive_time, start_time` / 장비 `eqp_id, capability, available_from`(필자 설계 — `unique()` 로 확인). 지표는 정의부터 묻는다(추론).
- **6시간 최소 문제**(추론): ① 로트 이력 CSV → 장비군별 「대기 시간 합」 순위 + 리틀의 법칙 검산. ② Q-time 구간 하나에서 「앞 공정 투입 보류 규칙」을 시뮬레이션으로 바꿔 재처리 건수·처리량 트레이드오프 곡선. ③ 디스패칭 규칙 비교(FIFO·납기·최소여유·Q-time 우선).
- **현장 사람이 할 반문**: ① 「그 숫자, 우리 정의로는 다르게 나오는데요?」 ② 「「너무 많다」는 몇이고, 핫랏이 오면 남의 Q-time 을 깨도 됩니까?」 ③ 「평균 말고 p90 은요?」(추론)
- **옆 챕터로**(같은 과제에서 함께 꺼낼 것):
  - 가동률 목표·운영 곡선 대기행렬과 운영 곡선 → 경영과학 › [가동률을 높이면 대기가 폭증한다](../../경영과학/흐름과-변동으로-보기/01-가동률을-높이면-대기가-폭증한다.md)
  - 장비 다운·긴급 LOT 뒤 재스케줄 → 경영과학 › [교란 뒤 최소 변경](../../경영과학/흐름과-변동으로-보기/04-교란-뒤-최소-변경.md)
  - 핫 로트 남발 → 경제학 › [우선순위 가격](../../경제학/메커니즘-디자인/01-우선순위-가격.md)
  - Q-time 초과 로트를 재작업·폐기·진행 → 회계학 › [관련원가와 증분분석](../../회계학/원가관리회계/01-관련원가와-증분분석.md)
  - 같은 데이터, 부서마다 다른 해석 → 경영학 › [지식 경계와 경계 객체](../../경영학/조직과-지식/01-지식-경계와-경계-객체.md)

## 부록 — 상세·인용·근거
### 무엇을 보나
- **무엇을 보나**: 웨이퍼 한 장이 팹에 들어가 나올 때까지의 **시간과 대기**.
  - 팹은 같은 장비를 여러 번 다시 지나가는 **재진입(re-entrant) 흐름**이고 공정이 길다.
  - INFICON(FabTime) 의 Jennifer Robinson: 「Products today can have close to 100 layers, and more than 1000 process steps.」 같은 글은 팹 사이클타임이 나쁜 이유를 「cost, complexity and change」 세 단어로 요약한다 — 비싼 장비를 놀리지 않으려다 가동률이 올라가고, 흐름이 길고 복잡해 변동이 커지고, 제품 믹스가 빠르게 바뀐다.
- **현장이 꼽는 사이클타임 원인 — 숫자로**: FabTime 웹사이트에 20년 넘게 「무엇이 당신 팹의 사이클타임에 가장 크게 기여하나」를 자유 응답으로 물어 묶은 결과(응답 하나가 여러 항목에 셀 수 있어 %가 아닌 건수):

| 순위 | 원인 | 건수 |
|---|---|---|
| 1 | Downtime(장비 고장·정지) | 50 |
| 2 | Utilization / Constraint / Bottleneck / Loading | 46 |
| 3 | Variability / Variation / Variance | 41 |
| 4 | Single Path / One-of-a-Kind Tools / Process Restrictions | 27 |
| 5 | Product / Process Mix | 19 |
| 6 | Holds | 12 |

  - 같은 글의 관찰: 제품 믹스가 해마다 순위를 올리고, 믹스 탓인지 Hold(보류) 얘기가 늘었고, 팬데믹 때는 작업자 부족 얘기가 가장 많았고, 핫랏(긴급 로트)은 비중이 줄고 있다.
    - **조건**: 표본은 FabTime 웹 양식 응답자·강의 참가자로 무작위 표본이 아니다(자기 선택). 「문제가 있다」의 증언으로 쓰고 비율로는 쓰지 않는다.
    - **(추론) 읽는 법**: 1위가 「설비 고장」이라는 점이 중요하다 — 흐름 관점의 1번 원인이 설비 관점([설비 관점](02-설비.md))에 있다.
    - 「사이클타임을 줄여라」를 받으면 디스패칭 규칙보다 **어느 장비의 정지가 대기를 가장 많이 만드나**를 먼저 보는 편이 근거와 맞는다.
    - **조건(추론)**: 메모리 팹은 제품 수가 적고 물량이 커 이 응답의 「제품 믹스」 순위가 다를 수 있다. INFICON·Applied Materials 의 일반론이 메모리 IDM 팹에 대체로 맞는다는 것은 전제일 뿐이다 — 두 출처 모두 웨이퍼 팹 일반을 대상으로 썼고 SK하이닉스 직무 기사의 용어(WIP·Capa·TAT·PM·FDC)와 겹친다는 이유로 둔다.
- **Q-time — 반도체 흐름 관점의 특이점**:
  - 정의: 「a lot must start processing at a later operation within some time window after completing processing at an earlier operation」. 대표 예는 세정 뒤 일정 시간 안에 베이크. 공정 엔지니어가 수율을 위해 건다.
  - 위반하면: 로트가 앞 공정으로 돌아가 다시 처리 → 앞 장비 용량 손실 + 그 로트의 사이클타임 증가 + 뒤 공정 도착 변동 증가.
  - **악순환**: 몇 로트가 밀려 재처리되면 앞 장비 도착률이 올라가고 → 대기 증가 → 더 많은 로트가 재처리. 원문은 「A “vicious cycle” ensues」. 중간 공정이 끼어 있는 다단 Q-time 루프는 예측도 운영도 어려워 「We recommend avoiding them as much as possible」.
  - 현장의 실제 운영: 앞 공정에서 **투입을 보류**한다 — 뒤 장비가 서 있거나 뒤 장비 앞 WIP 가 너무 많으면 앞 공정을 시작하지 않는다. 이어지는 질문(「너무 많다」는 몇인가, 핫랏이 오면 남의 Q-time 을 깨도 되나, 뒤 장비가 배치 장비면 배치를 채우려 얼마나 기다리나)은 원문이 미해결로 남긴 실무 문제다.
  - 배치 장면(영상 서술, E4): 「100장 정도 되는 웨이퍼를 산화 장비 안으로 넣어줍니다」·「약 1000도에 열을 가해주면」 — 산화로는 웨이퍼를 묶음(배치)으로 처리한다는 장면이다(bRd 3D 영상, 2023-03-28, https://www.youtube.com/watch?v=bAXxxmXCk1o t=1020s, 자동 자막 단일 경로). 배치 크기 수치는 영상 서술이고 장비마다 다르다.
  - 권고(원문, 판매사 관점): 뒤 장비의 정비 시간 자체를 줄이기, 로트가 루프에 들어간 뒤엔 새 PM 을 잡지 않기, 뒤 공정에 장비를 더 인증(qualify)하기, 「WIP Hours」(대기 중인 WIP 의 필요 가공시간 합)로 투입 시작·중단 기준을 걸기.
  - 학술: 시간 제약이 있는 흐름 일정 문제는 시간 제약이 없어도 이미 NP-hard 이고, 웨이퍼 팹의 시간 제약을 다섯 부류로 나눈 분류가 있다(Klemmt & Mönch 2012, WSC — **검색 요약 기준, 원문 미판독**). 확률적 Q-time 일정 연구는 IEEE TSM 에도 계속 나온다(Chien 외 2023, 메타데이터만 확인).

### 핵심 지표와 공식 — 원문
- **핵심 지표와 공식**

| 지표 | 뜻 | 근거 |
|---|---|---|
| 리틀의 법칙 L = λW | 평균 재공(WIP) = 평균 처리율 × 평균 체류시간. 처리율이 같으면 사이클타임을 줄이는 것과 WIP 를 줄이는 것은 같은 말 | Little(2011): 「L = λW has become widely known as “Little's Law.”」 팹 적용: 「if a fab retains the same throughput rate and reduces cycle time, WIP will also be reduced」 |
| TAT(Turn Around Time) | 웨이퍼가 팹에 투입된 시점부터 모든 공정을 거쳐 나올 때까지 총 시간. SK하이닉스가 쓰는 말 | 뉴스룸 각주 |
| X-factor | 실제 사이클타임 ÷ 이론(순수 가공) 사이클타임. 「3X」 = 순수 가공시간의 3배 | 「target average cycle time of 3X」 쓰임은 원문. 정의식 자체는 검색 요약으로만 확인(원문 미확인) |
| 운영 곡선(가동률–사이클타임) | 병목 가동률이 100% 에 다가갈수록 대기시간이 비선형으로 폭증. 변동을 줄이면 곡선이 눕는다 | 예시: 목표 3X 에서 변동이 가장 큰 경우 병목 가동률을 80.1% 로 묶어야 하고, 변동을 줄이면 84%, 더 줄이면 87% 까지(단, 필자 스스로 「the magnitude of this bottleneck utilization increase might be exaggerated」라고 단서). 대기 근사식은 대기행렬과 운영 곡선 |
| 완충 용량 | 장비를 100% 로 계획하지 않고 남겨 두는 몫 | 「A typical buffer for tools with some redundancy is 15% of available time.」 — 대수가 있는 장비군 기준이라는 조건이 붙어 있다 |
| Q-time 위반률 | 앞 공정이 끝난 뒤 정해진 시간 안에 다음 공정을 시작하지 못하면 앞 공정부터 다시 함 | 아래 「Q-time」 |

  - 용어 정의(필자 요약, ★ = 출처를 열어 확인하지 못한 통념): 사이클 타임/TAT(★) 투입부터 완료까지 걸린 시간 · 대기시간(★) 로트가 다음 공정을 기다린 시간, **평균과 p90 을 같이 본다** · WIP(★) 공정 중 재공 물량 · 디스패칭(★) 다음에 어느 로트를 어느 장비에 넣을지 정하는 규칙·시스템 · Hold/Release(★) 의심 로트를 멈춤/판정 후 다시 흘림
    - 로트 웨이퍼를 묶어 함께 흘리는 생산 단위(한 로트 장수 25장 등은 ★) · AMHS/OHT 자동 반송 시스템 전체/천장 레일로 FOUP 을 나르는 무인 반송 · 스토커(★)/AMR(NVIDIA 협약 기사).

### 결정 직무와 데이터
- **결정 직무**: 양산관리(SK하이닉스). 양산기술을 「연주자」, 양산관리를 「지휘자」에 비유하고, 양산관리가 「매일 전후 공정의 대기 물량(WIP*), 장비 생산 능력(Capa*), 목표 생산량 등 방대한 데이터를 종합적으로 분석해 그날의 최적 운영 계획을 수립한다」고 적었다. 세부 직무 셋: 생산 계획 및 진도 관리 · Capa 및 효율 관리(Capa 시뮬레이션·장비 배정) · 물류 개선 및 관리(물류 흐름 시뮬레이션).
  - 매일: 어느 공정·장비에 어떤 로트를 먼저 보낼지(디스패칭), 어느 장비에 어떤 제품을 배정할지. 매주: 부서 간 「데이터의 의미를 통일하는」 회의 — 양산관리 TL: 「동일한 데이터를 보더라도 부서마다 해석이 다를 수 있기 때문에 “어떻게 타 팀을 논리적으로 설득할 것인가”를 항상 고민한다」, 「최소 주 1회 이상 유관 부서와 눈높이를 맞추는 미팅」.
  - 수시: 「팹 현장에서는 기한이 정해진 업무보다 '지금 당장' 해결해야 하는 이슈들이 훨씬 많다」. 신입이 처음 하는 일: 「데이터 분석 툴을 활용해 현업에 필요한 데이터를 뽑는 업무」, 요구 역량으로 Python·SQL 명시.
- **데이터**: MES(제조실행시스템)에 로트 이력·경로·장비 상태. Moyne & Iskandar 는 팹 데이터 저장소를 「equipment trace data through metrology, maintenance, yield, inventory management, manufacturing execution system (MES) and enterprise resource planning (ERP)」로 나열한다.
  - 같은 논문의 데이터 품질 경고 인용 둘은 [엔지니어 업무 관점](../업무-유틸리티-사람/01-엔지니어-업무.md) 부록 「근거로 확인한 업무 장면」 표(E2). 같은 이름의 지표가 직무마다 정의가 다르므로(가용도 4종, 부서마다 다른 데이터 해석) 과제 데이터의 지표는 **정의부터 묻는다**(추론).
  컬럼 예(필자 설계 — 추론. 실제 과제의 열 이름은 반드시 `unique()` 로 확인): 로트 `lot_id, priority, due_date, current_step, arrive_time, start_time` / 장비 `eqp_id, capability(step 목록), available_from` / 반송 `from_bay, to_bay, distance, travel_time` / PM 일정 `eqp_id, pm_due, pm_hours`.

### 흔한 고통
- **흔한 고통**: 위 「현장이 꼽는 사이클타임 원인」 표 · Q-time 악순환 · 부서마다 다른 데이터 해석. 더해서: ① 평균만 보면 극단 대기가 숨는다(외부 출처 미확인). ② 반송 — OHT 는 중앙 컨트롤러가 최단경로 안내·교차점 감속·막히면 우회(외부 출처 미확인), 이동 자산 최적화는 공개 탐색 과제(NVIDIA 협약 기사, E2 양사 홍보·효과 수치 없음).
  - ③ 인력 — 팬데믹 때 작업자 부족 응답 급증(위 표 글). 교차훈련 부족과 「Standby-WIP-waiting time」 인력 제약 신호는 [사람·안전·숙련 관점](../업무-유틸리티-사람/03-사람-안전-숙련.md) 부록 「근거로 확인한 것」(FabTime 「Why and How Fabs Should Focus on CT Improvement」, E3).
  - ④ 계측과의 충돌 — 검사 용량 한정이 사이클타임에 직접 영향(Mines Saint-Étienne 연구 묶음 초록 — https://hal-emse.ccsd.cnrs.fr/emse-01555584, E2 초록 기준→한 단계 낮춰 E3 취급). 원문 인용은 [계측·제어 관점](../품질-계측-후공정/02-계측-제어.md) 부록 지표 표.

### 현장 사람이 할 반문 — 상세
- **현장 사람이 할 반문**:
  - 「그 숫자, 우리 정의로는 다르게 나오는데요?」 — 필자가 든 예시 문구(필자 설계). 근거는 양산관리 TL 의 위 발언(부서마다 해석이 다르다, 주 1회 이상 눈높이 회의, 뉴스룸 「양산관리」 E2/E4).
  - 「「너무 많다」는 몇이고, 핫랏이 오면 남의 Q-time 을 깨도 됩니까?」 — 원문(FabTime)이 미해결로 남긴 실무 질문 그대로(위 Q-time, E3).
  - 「평균 말고 p90 은요?」(추론) — 대기시간은 평균과 p90 으로 같이 보고, 평균은 극단 대기를 숨긴다(필자 요약, 외부 출처 미확인).

### AI/최적화 기회와 이미 쓰이는 것
- **AI/최적화 기회와 이미 쓰이는 것**: 학술 정리 — 팹 일정 문제는 배치 장비·병렬 장비·잡숍·보조자원(레티클 등)·한 잡에 여러 주문·클러스터 장비 일정으로 나뉜다(Mönch 외 2011). 2023 서베이도 배치 처리·보조자원·호환 불가 제품군·재진입을 핵심 제약으로 묶는다. 판매사 관점: 「Many fabs are moving from standard dispatching to smart scheduling」.
  - RL 디스패칭은 실데이터 개선 폭이 작다(Infineon 납기지연 최대 4%, 처리량 최대 1% — arXiv 초록, 근거 참조). 예측 스케줄링은 Moyne & Iskandar 의 「부분 성공」 목록에 든다(E2, 원문 인용은 [설비 관점](02-설비.md) 부록).
  - 반송·물류·스케줄 최적화(OHT/AMR 이동, 로트 디스패칭, PM 일정 배치, 인력 교대 편성)의 공개 근거는 아래 하나다.
    - NVIDIA 협약이 팹 디지털 트윈에 cuOpt 를 붙여 AMR 등 이동 자산 최적화를 탐색(NVIDIA 협약 기사, https://nvidianews.nvidia.com/news/sk-hynix-ai-factory, 2026-06-07, E2 양사 홍보·효과 수치 없음).
    - 해법 틀(추론): 디스패칭 규칙 비교(FIFO·납기우선·최소여유시간) 시뮬레이션 / OR-Tools 배정·경로 / 시나리오(장비 1대 다운 시 재배치) → 현행 대비 지표(대기시간·이동거리·위반 0건).
    - 데모(추론): 규칙별 KPI 비교표(평균·p90 대기, 납기 위반 수) · 베이 지도 위 반송 흐름 · 간트.

### 6시간 최소 문제 — 상세
- **6시간 최소 문제**(추론): ① 로트 이력 CSV → 장비군별 「대기 시간 합」 순위 + 리틀의 법칙 검산(WIP·처리율·사이클타임이 서로 맞는지) → 「사이클타임을 가장 많이 먹는 장비군 Top 5」. ② Q-time 구간 하나를 골라 「앞 공정 투입 보류 규칙」(뒤 장비 WIP Hours 상한)을 시뮬레이션으로 바꿔 보며 재처리 건수·처리량의 트레이드오프 곡선. ③ 디스패칭 규칙 비교(FIFO·납기·최소여유·Q-time 우선) — 디스패칭 규칙 시뮬레이션.
  - 화면 뼈대(추론): 입력 데이터 요약 → 결과표(근거 열) → 근거 드릴다운 → 사람 확인 버튼(HITL) → 전후 비교 지표. 트레이드오프 곡선 하나(가동률 ↔ 대기, 투입 보류 ↔ 처리량)가 대부분 관점에서 가장 설득력 있는 화면이다(추론).
