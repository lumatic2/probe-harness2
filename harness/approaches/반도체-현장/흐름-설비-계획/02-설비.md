## 바로 쓰는 칸
- **쓸 점**: 「정비팀 숫자와 생산팀 숫자가 다르다」 과제에 가용도 4종 정의를 한 화면에 나란히 놓아 설명한다.
- **필요한 데이터**: 장비 상태 이력 `eqp_id, state(RUN/IDLE/PM/DOWN/ENG), start, end` — 없으면 가용도 4종을 못 계산한다.
- **6시간 최소 형태**: 장비 상태 로그(E10 상태·시작·끝) → 가용도 4종과 CV 를 한 표에 / 「정비팀 숫자와 생산팀 숫자가 왜 다른가」를 한 화면에서 설명.
- **반문 하나**: 「그 가용도, 분모에 비계획 시간을 뺐나요, 분자에 엔지니어링 시간을 넣었나요?」 → 4종 정의 표를 보이고 어느 정의인지 확인한다(추론).
- **하지 말 것**: PdM 사례(5일 전 85%)를 하이닉스 효과로 말하기(판매사 단일 사례).

## 핵심
- **이 눈이 던지는 질문**: 장비가 왜 멈추나? PM 을 언제 하나? 챔버끼리 결과가 같은가?
- **과제 문구 신호**(추론): 「장비가 멈췄다」「가동률·가용도」「PM 주기」「고장 전조」「챔버 간 차이」「정비팀 vs 생산팀 숫자」
- **핵심 지표 — 같은 「가용도」도 누가 보느냐에 따라 다르다**(INFICON 이 고객사들과 정리한 네 가지):

| 이름 | 공식 | 주로 쓰는 쪽 |
|---|---|---|
| E79 Availability % | (Prod + Standby + Engineering) / Total Time | OEE 개선용. 「E79 Availability % remains the most relevant of the four for improving overall equipment effectiveness」 |
| Operational Availability % | (Prod + Standby + Engineering) / (Total − Non-Scheduled) | 정비 조직 — 사업상 이유로 세운 시간(비계획)을 정비 탓으로 돌리지 않음 |
| Operational Manufacturing % | (Prod + Standby) / (Total − Non-Scheduled) | 생산 조직 — 엔지니어가 실험·레시피 인증에 쓴 시간은 생산이 못 쓴 시간 |
| E79 Manufacturing % | (Prod + Standby) / Total Time | 재무 — 전체 시간 대비 |

- **결정 직무**: SK하이닉스 양산기술의 장비 엔지니어 — 셋업·점검·PM·부품 수급. 결정 예: PM 을 당길까 미룰까, 이 챔버를 생산에 돌려도 되나, 어느 부품을 미리 사 둘까.
- **데이터**: 장비 상태 이력(SEMI E10 상태), 정비 기록, 센서 트레이스(FDC). 컬럼 예 상태 이력 `eqp_id, state(RUN/IDLE/PM/DOWN/ENG), start, end`(필자 설계 — 실제 열 이름은 `unique()` 로 확인).
- **6시간 최소 문제**(추론): ① 장비 상태 로그 → 4가지 가용도와 CV 를 한 표에 → 정비팀·생산팀 숫자 차이를 한 화면에서 설명. ② 센서 요약 + 정비 기록 → 고장 전조 점수 → 「지금 PM / 다음 PM 까지 유지」 기대비용 비교. ③ 챔버별 결과 분포 비교 → 매칭이 깨진 챔버 표시. ④ 조치 기록 텍스트 → 증상 유사 검색 → 원인·조치 후보 + 근거 행 + 담당자 확인 버튼.
- **현장 사람이 할 반문**: ① 「정비팀 탓인가요, 생산 사정인가요?」 ② 「그 가용도, 분모에 비계획 시간을 뺐나요, 분자에 엔지니어링 시간을 넣었나요?」(추론) ③ 「오경보와 미탐은 몇 건입니까?」(추론)
- **옆 챕터로**(같은 과제에서 함께 꺼낼 것):
  - 장비를 사고 굴리는 총비용 → 회계학 › [수명주기원가와 장비 소유원가](../../회계학/원가관리회계/05-수명주기원가와-장비-소유원가.md)
  - PM·부품 교체 기록의 세무 분류 → 법학 › [자본적·수익적 지출 분류](../../법학/세법/02-자본적-수익적-지출-분류.md)
  - 장비 시간을 실험에 쓸까 생산에 쓸까 → 경영학 › [램프업 중 실험과 생산의 상충](../../경영학/생산운영관리/01-램프업-실험과-생산의-상충.md)

## 부록 — 상세·인용·근거
### 무엇을 보나
- **무엇을 보나**: 장비의 **시간 쓰임새**.
  - SEMI E10 은 장비 시간을 생산(Productive)·대기(Standby)·엔지니어링(Engineering)·계획 정지·비계획 정지·비계획 시간(Non-scheduled) 같은 상태로 나눈다(상태 구분은 INFICON 글이 E10 을 인용해 설명한 것).
  - E10 의 가용도 정의: 「the probability that the equipment system will be in a condition to perform its intended function when required」(INFICON 이 E10 원문을 인용).

### 핵심 지표 — 가용도 4종의 뒷받침(표 아래 서술)
  - 핵심 문장: 장비 엔지니어 눈에는 엔지니어링 시간도 「살아 있는」 시간이지만, 생산 감독자 눈에는 「if a process engineer is using the tool to run experiments, the tool is not available to be used by manufacturing」.
    - 또 정비가 되는데도 생산이 장비 전체를 세우지 못해 챔버 하나를 「non-scheduled」로 표시하는 관행도 소개한다 — 정비팀이 벌점을 받지 않게 하려고. **가용도의 평균만이 아니라 변동(CV = 표준편차/평균)** 을 줄여야 한다는 게 FabTime 의 주장이고, 정비 조직 평가에는 Operational Availability 의 CV 를 권한다. **OEE** — SEMI E79 가 장비 생산성 지표(OEE 포함)를 정의하는 표준이다.
    - 「가용 효율 × 성능(속도) 효율 × 품질 효율」 분해는 표준 원문(유료)을 못 열어 **검색 요약 기준**이다. MTBF·MTTR·고장률: 신뢰성과 보전 주기.
  - 용어 정의(필자 요약, ★ = 출처 미확인 통념): PM(★) 고장 전 계획 정비 · BM(★) 고장 후 수리 — **PM vs BM = 계획 정지 vs 고장 정지, 가동률 분모에서 따로 센다** · MTBF 고장 사이 평균 정상 가동 시간 · MTTR 평균 수리 시간 · 가동률(★) 가동 시간 ÷ 기준 시간, 분모(달력/계획) 정의를 반드시 확인 · 챔버(★) 장비 안 실제 처리가 일어나는 방, 장비 하나에 여럿.
    - 같은 이름 다른 정의 → 과제 데이터의 지표는 **정의부터 묻는다**(추론). 분모·분자 차이로 가용도 숫자가 출처마다 다른 것은 상충이 아니라 정의 차이다(분자에 엔지니어링 시간 포함 여부 × 분모에 비계획 시간 포함 여부).

### 결정 직무와 데이터
- **결정 직무**: SK하이닉스 양산기술의 장비 엔지니어 — 「생산 장비의 셋업, 점검, 개조·개선」, 이상 시 신속 대응, 정기 유지관리(PM)·부품 수급. 메인트(정비) 전임직과의 구분은 외부 출처 미확인.
  - 결정 예: PM 을 당길까 미룰까, 이 챔버를 생산에 돌려도 되나, 어느 부품을 미리 사 둘까. 직무 구분·학력 요건(생산직 전임직 / 기술사무직)은 [사람·안전·숙련 관점](../업무-유틸리티-사람/03-사람-안전-숙련.md) 부록 「결정 직무」 — 「요즘 장비 엔지니어도 대졸」은 기술사무직만 맞고 전임직 메인트는 고졸·전문대졸.
- **데이터**: 장비 상태 이력(SEMI E10 상태), 정비 기록, 센서 트레이스(FDC). 컬럼 예(필자 설계 — 추론. 실제 열 이름은 `unique()` 로 확인): 조치 기록·상태 이력·부품·FDC 컬럼 목록은 [엔지니어 업무 관점](../업무-유틸리티-사람/01-엔지니어-업무.md) 부록 「데이터」.

### 흔한 고통
- **흔한 고통**: 고장 정지가 사이클타임 1위 원인이라는 현장 응답([흐름·생산 관점](01-흐름-생산.md)). 「100% 가동을 요구했지만 쓸모없었다」는 구독자 사례 — 원문은 총가용도보다 **로트가 도착했을 때 장비가 없을 확률**을 줄이라고 권한다(정비를 몰아서 하지 말 것).
  - Inform Note 에이전트의 문제 서술(대응 제각각·분석 오래 걸림·표준화된 조치 없음·숙련자 지식 의존)은 [엔지니어 업무 관점](../업무-유틸리티-사람/01-엔지니어-업무.md) 부록 「흔한 고통」. 더해서: ① 수율은 장비 상태에 좌우된다.
  - ② FDC 는 십 년 넘게 쓰였지만 「continues to be plagued by high setup costs and high rates of false and missed alarms」(Moyne & Iskandar, E2). ③ 센서가 수백 개이고 알람 연쇄로 한 사건이 여러 줄이 된다(외부 출처 미확인).
  - 3σ 한계도 정상일 때 평균 약 371점마다 오경보(NIST e-Handbook, 근거 참조) — 알람 피로 자체는 ★(직관)이고 오경보율만 NIST 근거. ④ 레시피 단위 인증(recipe-level quals)은 장비가 멀쩡해도 생산이 못 쓰는 시간을 만든다(FabTime 가용도 글, E3).

### 현장 사람이 할 반문 — 상세
- **현장 사람이 할 반문**:
  - 「정비팀 탓인가요, 생산 사정인가요?」 — 필자가 든 예시 문구(필자 설계). 근거는 가용도 4종과, 정비팀 벌점을 피하려 챔버 하나를 「non-scheduled」로 표시하는 관행(FabTime, E3).
  - 「그 가용도, 분모에 비계획 시간을 뺐나요, 분자에 엔지니어링 시간을 넣었나요?」(추론) — 위 정의 차이에서 나온 질문.
  - 「오경보와 미탐은 몇 건입니까?」(추론) — FDC 가 「high rates of false and missed alarms」에 시달린다는 위 인용(Moyne & Iskandar)에서.

### AI/최적화 기회와 이미 쓰이는 것
- **AI/최적화 기회와 이미 쓰이는 것**:
  - **예지 보전(PdM)**: Moyne & Iskandar 의 에피 장비 램프 사례 — 단변량 FD 로는 램프 교체를 「only 4–5 h in advance」 예측해 돌발 정지 위험이 컸는데, 다변량 PdM 으로 「lamp failure can be predicted five days in advance with about 85% accuracy」. **조건**: 저자가 Applied Materials 소속(판매사), 단일 사례.
  - PdM 의 핵심 어려움은 「health factors」(상태 지표)를 만들고 그것을 운영비·고장 위험과 잇는 것. Susto 외는 예측 기간이 다른 분류기 여러 개를 두고 「frequency of unexpected breaks and unexploited lifetime」(돌발 고장 빈도 대 덜 쓰고 버린 수명)의 트레이드오프를 운영비 기준으로 고르는 방식을 냈고 반도체 보전 벤치마크로 검증했다(초록 기준).
  - 업계 현황 판정: 「FD, SPC and R2R control are pervasive in existing fabs」, 반면 「Isolated successes in PdM, VM, and predictive scheduling have been reported; however, challenges still exist」 — **PdM 은 아직 「부분 성공」 영역**이다.
  - **챔버 매칭**: 같은 레시피가 챔버·장비마다 다른 결과를 내서, 공정을 여러 챔버로 넓힐 때 매칭을 「commonly performed experimentally」(실험으로) 하느라 비용이 든다. AI 로 기준 챔버의 최적 조건을 찾고 다른 챔버로 옮기는 사례(4개 챔버, 초록 기준, 2024 ASMC).
  - 현장 사람의 시선: SK하이닉스 김진환 기술명장(Wire Bond) 인터뷰(2020, E4)의 인용 둘 → [사람·안전·숙련 관점](../업무-유틸리티-사람/03-사람-안전-숙련.md) 부록 「근거로 확인한 것」·「흔한 고통」.
  - **SK하이닉스가 이미 낸 것 — Inform Note 기반 장비 보전 가이드**(GaiA 위 첫 Biz 특화 에이전트, 뉴스룸 황청석 TL 글, https://news.skhynix.co.kr/gaia_ep1_biz_ai_agent/ 2025-10-31, E2 자사): Inform Note(장비 이상 상태·문제점·처리 결과를 다음 작업자·부서에 알리는 문서)를 학습하고 명장·마스터 지식으로 보완한다. 기능은 「장비 이력 요약」·「불량 조치 가이드」 두 가지.
    - 기대효과: 주니어도 근거 기반 판단, 팹 간 품질 관리 표준화. **단서**: 「현재는 Inform Note 중심」이고 다른 데이터 연동은 향후 계획이다.
  - 2030 자율 팹 발표(도승용 부사장, 아시아경제 영문 AI 번역 기사 https://www.asiae.co.kr/en/article/2026031814572597859 2026-03-18, E3)는 정비·불량 분석 처리시간 50% 이상 단축을 성과로 든다(자사 성과 주장).
  - RAG 의 한계는 회사 스스로 적었다: 「검색 결과 품질에 따라 답변이 달라지고 복잡한 작업은 어렵다」(GaiA 플랫폼 글 https://news.skhynix.co.kr/ai-platform-gaia-launching-2025/ 2025-08-14, E2 자사).
  - 사람 확인의 근거(품질보증 채용 담당 TL, https://news.skhynix.co.kr/ambassador-job-report-ep5/ 2026-10-14, E2 자사/발언 E4): 원문 인용은 [품질·수율 관점](../품질-계측-후공정/01-품질-수율.md) 부록 「AI/최적화 기회」 — 사람 확인 버튼의 근거로 쓸 수 있는 회사 자신의 문장(추론: 쓰는 법).
    - Moyne & Iskandar 결론(현장 전문가 지식 필요, E2)은 [엔지니어 업무 관점](../업무-유틸리티-사람/01-엔지니어-업무.md) 부록 「근거로 확인한 업무 장면」 표.
  - (추론) 널리 쓰이는 FD·SPC·R2R 위에서 사람의 결정을 빠르게 하는 쪽이, 아직 부분 성공인 예측을 해냈다고 말하는 쪽보다 서술형 답에서 방어하기 쉽다.

### 6시간 최소 문제 — 상세
- **6시간 최소 문제**(추론): ① 장비 상태 로그(E10 상태·시작·끝) → 4가지 가용도와 CV 를 한 표에 → 「정비팀 숫자와 생산팀 숫자가 왜 다른가」를 한 화면에서 설명.
  - **현장 설득용으로 강하다** — 양산관리가 말한 「데이터 해석 시각차」를 정의 차이로 풀어 준다.
  - ② 센서 요약 + 정비 기록 → 고장 전조 점수 → 「지금 PM / 다음 PM 까지 유지」 기대비용 비교(신뢰성과 보전 주기·기대손실 결정표).
  - ③ 챔버별 결과 분포 비교 → 매칭이 깨진 챔버 표시 + 보정 후보(레시피 오프셋). ④ 조치 기록 텍스트 → 증상 유사 검색(RAG) → 원인·조치 후보 + 근거 행(note_id 인용 필수) + 신뢰도 + 담당자 확인 버튼(필자 설계): 추천 조치 카드 화면은 [엔지니어 업무 관점](../업무-유틸리티-사람/01-엔지니어-업무.md) 부록 「6시간 최소 문제」 해법 틀 참고 · 장비별 MTBF 막대
  - 고장 타임라인(간트) · MTBF·MTTR·가동률 계산과 「다음 고장 위험 높은 장비」 단순 점수.
