# 정보 설계 알람과 대시보드 — 정보 설계(베이지언 설득): 알람·대시보드에 무엇을 먼저 보여 줄까

> [인센티브와 정보 설계](README.md) › 03 · 짝 기법: [관리도와 오경보 주기](../../../methods/품질과-신뢰성-통계/01-관리도와-오경보-주기.md) · [기대손실 결정표](../../../methods/의사결정분석/01-기대손실-결정표.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 알람 등급을 정해 엔지니어가 무시하지 않을 알람만 위로 올린다. (추론)
- **필요한 데이터**: 과거 알람 이력: 컬럼 = 등급 기준별 엔지니어 조치 여부 · 실제 이상 여부. 이 이력이 없으면 못 쓴다.
- **6시간 최소 형태**: 등급 A/B/C 별 조치 비율·실제 이상 비율 표 → 이상 확률이 일정 이상일 때만 상위 등급 / 정밀도·놓친 이상 수 비교.
- **반문 하나**: 「불리한 정보를 숨기는 것 아닌가」 → 원본은 늘 열람 가능하고 기본 화면의 순서·요약만 설계한다. (추론)
- **하지 말 것**: 원본 알람을 숨기는 설계로 말하기 — 원본은 열어 두고 기본 화면의 순서·요약만 정한다. 알람 적용은 추론이다.

## 상세

**한 줄**: 「정보경제학에서는 보내는 쪽이 받는 쪽의 행동을 바꾸고 싶지만 행동을 강제할 수 없는 문제를 풀 때 신호 설계(베이지언 설득)를 쓴다. 핵심 논리는 무엇을 어떤 규칙으로 드러낼지를 미리 정해 상대의 믿음과 행동을 움직이는 것이다. 「소송 변호사·영업 사원의 신호」를 FDC 알람 등급·대시보드 기본 화면으로, 「받는 사람」을 교대 근무 엔지니어로 바꾸면 알람이 너무 많아 무시되는 문제에 적용된다.」
- **과제 문구 신호**(추론): 「알람이 너무 많다」「오경보」「무시한다」「대시보드」
- **가정 변환**

| 원 분야 | 반도체 |
|---|---|
| 신호를 고르는 쪽 | 알람 등급·대시보드를 설계하는 쪽 |
| 신호를 받아 행동하는 쪽(행동은 계약 불가능) | 교대 근무 엔지니어(조치 여부는 강제할 수 없음) |
| 신호 규칙 | FDC 알람 등급 기준, 대시보드 기본 화면의 순서·요약 |

- **원 분야 사실**(E2, 초록 기준): 보내는 쪽이 신호를 골라 받는 쪽에게 보여 주고 받는 쪽이 계약 불가능한 행동을 하는 모형에서, 보내는 쪽이 이득을 보는 신호가 존재할 필요충분조건과 최적 신호를 낸다. 본문의 조건·한계 절은 열지 않았다.
- **하이닉스 적용 예**(추론): 알람 등급을 정해 엔지니어가 무시하지 않을 알람만 위로 올린다. [알람 관리](../../공학/인간공학/01-알람-관리.md)와 같은 문제를 보내는 쪽의 설계로 읽는다.
- **기준선과 지표**(추론): 지금 = 현행 알람 등급(가정). 지표 = 상위 등급의 정밀도, 놓친 이상 수.
- **6시간 최소 형태**: 과거 알람 이력 → 「등급 기준 A/B/C 별로 엔지니어가 조치한 비율·실제 이상 비율」 표 → 실제 이상 확률이 일정 이상일 때만 상위 등급을 주는 규칙 제안. 정밀도와 놓친 이상 수를 비교한다.
- **반론과 답**(추론): 「불리한 정보를 숨기는 것 아닌가」 → 원본은 늘 열람 가능하고 기본 화면의 순서·요약만 설계한다고 말한다.
