# 샤플리 값 비용 배분 — 공용 설비 비용을 부서에 공정하게 나누기

> [메커니즘 디자인](README.md) › 02 · 짝 기법: [선형·정수계획](../../../methods/최적화/02-선형-정수계획.md) · [민감도 분석](../../../methods/의사결정분석/02-민감도와-가정-바꿔-보기.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 유틸리티 공용 비용·피크 기본요금을 사용량 비례가 아닌 규모 기준 공정성(샤플리 값)으로 나눠 본다. (추론)
- **필요한 데이터**: 공정 그룹별 피크 사용량 표가 없으면 못 쓴다. 단가는 산업용(을) 전기요금표(2026-04-16 개편 후)를 쓴다(근거 참조).
- **6시간 최소 형태**: 공정 그룹별 피크 사용량 → 샤플리 배분 대 사용량 비례 배분 비교표(작은 공정이 덜 내는지) / 피크를 경부하로 옮긴 부담 변화.
- **반문 하나**: 「시간 기준 배부로 충분하지 않나」 → 샤플리 값은 규모 기준 공정성으로 시간 기준 배부(TDABC)를 보완한다. (추론)
- **하지 말 것**: 샤플리 식을 모든 설비에 맞는 것처럼 쓰기 — 부분집합 비용이 가장 큰 사용자의 비용과 같은 특수한 경우인지 먼저 본다.

## 상세

**한 줄**: 「협조 게임이론에서는 여러 사용자가 한 설비를 같이 쓰고 사용자마다 필요한 규모가 다른 비용 분담 문제를 풀 때 샤플리 값을 쓴다. 활주로는 가장 긴 활주로가 필요한 비행기 기준으로 짓지만, 각 구간 비용을 그 구간이 필요한 비행기들끼리만 나눈다. 활주로 길이를 초순수·전력 피크 용량, 공조 등급으로, 비행기를 라인·공정 그룹으로 바꾸면 유틸리티 공용 비용과 피크 기본요금을 부서에 배분하는 문제에 적용된다.」
- **과제 문구 신호**(추론): 「유틸리티 비용」「전력 피크」「초순수 사용량」「부서별 배부」「누가 비용을 지나」
- **가정 변환**(추론)

| 원 분야 | 반도체 |
|---|---|
| 활주로 길이 | 초순수·전력 피크 용량, 공조 등급 |
| 비행기 | 라인·공정 그룹 |
| 착륙료 | 공용 비용과 피크 기본요금의 부서 부담분 |

- **원 분야 사실**: 부분집합의 비용이 그중 「가장 큰」 사용자의 비용과 같을 때 샤플리 값이 간단한 식으로 나오고, 기존 공항 착륙료 규칙이 정확히 그 값이라는 결과다(Littlechild·Owen 1973, E2 초록 기준).
  - 「It turns out that a simple rule previously proposed for calculating airport landing charges generates precisely the Shapley value for an appropriately defined game.」(Littlechild·Owen 초록).
  - 협조 게임이론 맥락은 노벨 2012 해설(E3)에도 있다.
- **하이닉스 적용 예**(추론): 유틸리티 공용 비용과 피크 기본요금을 사용량 비례가 아닌 규모 기준 공정성으로 나눠 본다.
- **기준선과 지표**(추론): 기준선 = 사용량 비례 배분. 지표 = 부서별 부담액, 작은 공정이 덜 내는지, 피크 이동 후 부담 변화.
- **6시간 최소 형태**: 공정 그룹별 피크 사용량 표를 받는다. 샤플리 배분 대 사용량 비례 배분 비교표(작은 공정이 덜 내는지)를 만든다. 피크를 경부하로 옮겼을 때 각 부서 부담 변화를 붙인다. 단가는 산업용(을) 전기요금표(2026-04-16 개편 후)를 쓴다(근거 참조).
- **반론과 답**(추론): 「시간 기준 배부로 충분하지 않나」 → 시간 기준 배부([TDABC](../../회계학/원가관리회계/04-시간동인-활동기준원가.md))를 샤플리 값은 규모 기준 공정성으로 보완한다. 「식이 모든 설비에 맞나」 → Littlechild·Owen 의 식은 부분집합 비용이 가장 큰 사용자의 비용과 같다는 특수한 경우다. 조건이 맞는지 먼저 본다.
