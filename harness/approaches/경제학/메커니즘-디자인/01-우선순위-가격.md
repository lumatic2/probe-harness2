# 우선순위 가격(혼잡 가격) — 핫 로트 남발을 막는 값 매기기

> [메커니즘 디자인](README.md) › 01 · 짝 기법: [대기행렬과 운영 곡선](../../../methods/확률과-시뮬레이션/02-대기행렬과-운영-곡선.md) · [디스패칭 규칙 시뮬레이션](../../../methods/확률과-시뮬레이션/01-디스패칭-규칙-시뮬레이션.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 핫 로트 지정이 공짜라 다 급해지는 구조에 값(우선순위 요금)을 붙이고 핫 로트 비율 상한을 둔다. (추론)
- **필요한 데이터**: 로트 부류(양산·개발·고객 샘플)별 도착률·단위시간당 지연 비용 표가 없으면 못 쓴다 — 그때는 규칙 비교 시뮬레이션 한 줄로만.
- **6시간 최소 형태**: 부류별 도착률·지연 비용 표 → 요금 있음/없음의 평균 대기·납기 위반 비교 / 화면은 핫 로트 비율 상한 슬라이더.
- **반문 하나**: 「사내 돈은 진짜 비용이 아니라 가격이 아무것도 못 막는다」 → 예산(토큰) 한도를 같이 준다. (추론)
- **하지 말 것**: 팹에서 운영된 사례가 있는 것처럼 말하기 — 실제 운영 사례는 미확인이고 데모는 시뮬레이션 비교까지만 보인다.

## 상세

**한 줄**: 「경제학(대기행렬 경제학)에서는 여러 부류의 사용자가 한 서버를 나눠 쓰고 각자 기다림 비용이 다른 문제를 누가 얼마나 급한지 중앙이 모르는 상황에서 풀 때 유인 정합적 우선순위 가격을 쓴다. 급한 쪽이 스스로 더 비싼 우선순위를 사게 해서, 각자 고른 결과가 전체 순가치를 최대로 만든다. 사용자 부류를 양산 로트·개발(기술) 로트·고객 샘플 로트로, 기다림 비용을 납기 위반·Q-Time 초과 위험(원)으로 바꾸면 핫 로트 지정이 남발돼 모든 로트가 급해지는 문제에 적용된다.」
- **과제 문구 신호**(추론): 「핫 로트」「긴급 로트가 너무 많다」「우선순위」「모두 급하다고 한다」「Q-Time」
- **가정 변환**(추론)

| 원 분야 | 반도체 |
|---|---|
| 사용자 부류 | 양산 로트 · 개발(기술) 로트 · 고객 샘플 로트 |
| 단위시간당 지연 비용 | 납기 위반·Q-Time 초과 위험(원) |
| 한 서버를 나눠 씀 | 한 장비군의 대기열을 나눠 씀 |
| 우선순위 가격 | 핫 로트 지정에 매기는 값. 현업에는 「우선순위 요금」「요청권」으로 부른다 |

- **원 분야 사실**: M/M/1 다부류 대기열에서 부류마다 단위시간당 지연 비용·서비스 시간·수요 함수가 다를 때, 개별 사용자가 분권적으로 고른 도착률·우선순위가 시스템 기대 순가치를 최대로 하는 가격 구조를 닫힌 식으로 낸다(Mendelson·Whang 1990, 초록 기준). 후속 문헌은 이 방식이 cμ 규칙을 구현한다고 정리한다(Mendelson·Whang 검색 요약 — 2차 인용, **미확인**). 가격 구조 식 본문은 **미확인**.
- **하이닉스 적용 예**(추론): 핫 로트 지정이 공짜라 다 급해지는 구조에 값을 붙이고, 핫 로트 비율 상한을 둔다.
- **기준선과 지표**(추론): 기준선 = 우선순위 요금이 없는 현행. 지표 = 평균 대기, 납기 위반, 핫 로트 비율.
- **6시간 최소 형태**: 로트 부류별 도착률·지연 비용 표를 받는다. 대기행렬과 운영 곡선 대기열 식으로 「우선순위 요금을 매길 때 / 안 매길 때」 평균 대기·납기 위반을 비교한다. 핫 로트 비율 상한 슬라이더를 붙인다.
- **반론과 답**(추론): 「사내 돈은 진짜 비용이 아니라 가격이 아무것도 못 막는다」 → 예산(토큰) 한도를 같이 준다. 「시장이라는 말이 부서끼리 돈 싸움으로 들린다」 → 운영 용어(우선순위 요금·요청권)로 부른다. 「팹에서 실제로 운영된 적이 있나」 → 사내 우선순위 가격의 실제 운영 사례는 이번에 별도로 찾지 않았다(**미확인**). 도입은 시범 단계로 말하고 데모는 시뮬레이션 비교까지만 보인다.
