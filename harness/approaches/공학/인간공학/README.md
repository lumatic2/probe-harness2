# 인간공학 — 학문 지도

> [입구](../../README.md) › [공학](../README.md) › **인간공학** · 챕터 5
> 한 줄: **인간공학**은 사람의 주의·기억·판단 한계에 맞춰 화면·절차·역할을 설계한다. 사람을 고치는 대신 일하는 환경을 고쳐 실수가 덜 나게 한다.
> **주의**: 「사실」은 출처에 있는 말, 「추론」은 반도체에 옮겨 붙인 말이다(추론에는 등급 없음). **의료·화학 플랜트의 효과 크기는 원 분야 수치이며 팹 효과의 예측이 아니다 — 제출물·서술형 답에서 이 숫자를 "하이닉스에서도 이만큼"으로 말하면 틀리다.**

## 핵심 질문
**이 일을 하는 사람이 어느 순간에 무엇을 놓치나? 그 순간에 화면·절차·역할을 어떻게 바꾸면 놓치지 않나?**

## 이럴 때 꺼낸다 / 옆 모듈로
- **꺼낸다**: 경보·차트가 사람이 볼 수 있는 양을 넘을 때 · 교대나 PM 뒤처럼 정보가 새는 순간이 있을 때 · 숙련자의 판단을 신입에게 전해야 할 때 · 「지금 볼 것」 화면을 설계할 때.
- **옆 모듈로**
  - 자동화 수준·인간-자동화 협업(AI가 어디까지 결정하고 사람이 어디서 확인하나) → [컴퓨터과학 › 자율성 설계](../../컴퓨터과학/자율성-설계/README.md)
  - 사고 경로의 방벽, 사고 보고서의 잠복 조건 → 공학 › [안전공학](../안전공학/README.md)
  - 사고 보고서 양식·재발 방지 추적, 변경 실험의 균형 → 공학 › [신뢰성공학](../신뢰성공학/README.md)
  - 알람 하나의 품질(관리도·ARL) → 경영과학 관리도와 오경보 주기. 알람 시스템 전체의 부하는 [01](01-알람-관리.md)이 맡는다.
  - 교대·인력 배치 최적화 → 경영과학 제약 프로그래밍 일정
  - 알람 유형별 엔지니어 시간을 원화로 → 회계학 › [원가관리회계](../../회계학/원가관리회계/04-시간동인-활동기준원가.md)

## 핵심 개념어
- **알람 홍수**: 짧은 시간에 신규 알람이 몰려 사람이 따라가지 못하는 상태. 기준은 [01](01-알람-관리.md)에 있다.
- **떨림(chattering) 알람**: 같은 알람이 켜졌다 꺼졌다 반복되는 것.
- **상황 인식(SA)**: 지금 무엇이, 무슨 뜻이고, 곧 어떻게 될지를 아는 상태.
- **인계(handoff)**: 교대 때 환자·장비·LOT 정보를 다음 사람에게 넘기는 일.
- **결정 요구표**: 증상 → 확인 순서 → 판단 단서 → 함정을 적은 표.

## 관점 쌍
- **알람 건수 ↔ 알람 건강**: 총 건수보다 1인당 부하·홍수 비율·상위 소스 비중으로 본다([01](01-알람-관리.md)).
- **데이터를 늘어놓기 ↔ 의미를 정리하기**: 센서별 차트 수십 장과, 지금 볼 것만 올린 화면([02](02-상황-인식-화면-설계.md)).
- **긴 SOP ↔ 짧은 멈춤 지점**: 모든 걸 적는 대신 꼭 멈춰야 할 몇 지점만([04](04-체크리스트.md)).

## 이 분야 사람이 먼저 묻는 것 5
1. 이 사람이 한 번에 처리해야 하는 정보량이 얼마인가? 기준선은 사이트에서 먼저 쟀나?
2. 정보가 새는 순간(교대·PM 뒤·작업 전환)은 언제인가?
3. 이상을 본 사람이 말하거나 멈출 수 있는 구조인가?
4. 줄이려는 것이 중복·떨림·거짓 경보인가, 진짜 이상까지 줄이는 것은 아닌가?
5. 훈련·문화 효과를 주장하나, 도구(양식·칸·기록)로 보여 주나?

## 흔한 함정
- 화학 플랜트 경험값(예: 시간당 12건)을 팹에 그대로 쓴다. 사이트 기준선부터 잰다([01](01-알람-관리.md)).
- 벤더가 가정으로 계산한 거짓 경보 비용을 실측처럼 말한다([01](01-알람-관리.md)).
- 의료 체크리스트·인계 연구의 효과 크기를 팹 효과로 말한다([03](03-구조화-교대-인계.md), [04](04-체크리스트.md)).
- 말로 꺼낸 노하우를 검증 없이 쓴다. 칸마다 실제 조치 기록을 붙여 대조한다([05](05-핵심-결정-기법.md)).
