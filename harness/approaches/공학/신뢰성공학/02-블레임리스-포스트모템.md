# 블레임리스 포스트모템

> [신뢰성공학](README.md) › 02 · 짝 기법: (없음)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 흩어진 사고 보고서를 정해진 양식·5개 검토 기준·후속 조치 추적으로 묶어 같은 근본 원인의 재발을 센다.
- **필요한 데이터**: incident.csv, action_item.csv(incident_id, owner, due, done_at). 후속 조치 기한·완료 열이 없으면 완료율을 못 잰다.
- **6시간 최소 형태**: 기준 충족 판정 → LLM 양식 채우기(근거 행 인용 필수) → 5개 검토 기준 체크 → 재발 묶기. 화면: 사건 목록 + 편집기 + 미완료 후속 조치 보드.
- **반문 하나**: 「한국 제조 현장에서 '비난 없음'이 가능하냐」 → 만드는 건 문화가 아니라 양식·검토 기준·추적이라는 도구이고, 그건 바로 만들 수 있다.
- **하지 말 것**: 안전 사건의 법적 책임 문제는 이 도구 범위 밖이라고 선을 긋는다. 구글 SRE 의 문화 효과를 팹 효과로 말하지 않는다.

## 상세

**한 줄**: 「데이터센터 운영(구글 SRE)에서는 사고가 반복되는데 사람들이 처벌이 두려워 문제를 숨길 때 블레임리스 포스트모템을 쓴다. 핵심 논리는 사고 전에 「언제 포스트모템을 쓰는가」 기준을 정해 두고, 영향·조치·근본 원인·후속 조치를 정해진 양식으로 쓰고, 선임 검토를 거쳐 저장소에 모아 추세를 분석하되, 개인이 아니라 시스템을 고친다는 것이다. 「서비스 장애」를 장비 장기 다운·대량 스크랩·안전 니어미스로 바꿔 대입하면 사고 보고서 품질·재발 방지 추적 문제에 적용된다. 지금 방식(사고 보고서가 흩어지고 후속 조치 추적이 약함)과 비교해 「후속 조치 완료율」과 「같은 근본 원인 재발 건수」로 개선을 보일 수 있다.」
- **과제 문구 신호**(추론): 「사고 보고서」「재발 방지」「후속 조치 추적」「근본 원인」「장기 다운」
- **가정 변환**

| 원 분야 | 반도체 |
|---|---|
| 사용자 영향 임계 | 영향 LOT 수·다운타임 임계 |
| 모니터링 실패 | FDC 가 못 잡고 계측·고객이 먼저 발견 |
| 근본 원인 깊이 | 스위스 치즈 잠복 조건까지 갔나 |
| 저장소 추세 분석 | 조치 기록·사고 보고 통합 검색 |

- **원 분야 사실**(원문):
  - 작성 기준 예: 일정 수준 넘는 사용자 영향, 데이터 손실, 당직 개입, 해결 시간 초과, 모니터링 실패(사람이 직접 발견). 기준은 사고 전에 정한다.
  - 블레임리스 문화는 의료·항공에서 왔다고 원문이 직접 쓴다. 검토 기준: 핵심 데이터 수집됐나, 영향 평가 완결됐나, 근본 원인이 충분히 깊은가, 조치 계획과 버그 우선순위가 적절한가, 이해관계자와 공유했나.
  - "검토되지 않은 포스트모템은 없었던 것과 같다"는 취지의 문장이 있다. 저장소의 포스트모템을 메타데이터로 모아 제품 간 공통 주제를 찾고, 머신러닝으로 약점 예측·중복 사고 감소를 앞으로의 일로 든다. **단서**: 작성에 비용이 들어 언제 쓸지 신중히 고른다.
- **하이닉스 적용 예**(추론): 포스트모템 초안 생성 + 품질 채점기: 사건 데이터에서 초안을 만들고 위 5개 검토 기준으로 빈칸을 표시. 저장소 전체에서 "같은 근본 원인 재발"을 묶는다.
- **기준선과 지표**: 작성 기준 충족 사건 중 작성 비율, 검토 통과율, 후속 조치 완료율·지연일, 근본 원인 재발 수.
- **6시간 최소 형태**: 데이터 `incident.csv`, `action_item.csv(incident_id, owner, due, done_at)`. 계산: 기준 충족 판정 → 양식 채우기(LLM, 근거 행 인용 필수) → 5개 검토 기준 체크 → 재발 묶기(임베딩 유사도). 화면: 사건 목록(기준 충족 표시) + 포스트모템 편집기 + 미완료 후속 조치 보드.
- **반론과 답**: "한국 제조 현장에서 '비난 없음'이 가능하냐" → 원문도 문화는 꾸준한 투자와 경영진 참여가 필요하다고 쓴다. 제출물은 문화가 아니라 **양식·검토 기준·추적**이라는 도구이고, 그건 바로 만들 수 있다. 안전 사건의 법적 책임 문제는 이 도구가 다루는 범위 밖이라고 선을 긋는다.
