# 보타이 분석 (Bowtie)

> [안전공학](README.md) › 01 · 짝 기법: [기대손실 결정표](../../../methods/의사결정분석/01-기대손실-결정표.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 점검표 합격률 대신 사고 경로마다 「살아 있는 방벽 수」를 세어 사실상 한 겹인 경로를 찾는다.
- **필요한 데이터**: barrier.csv(path_id, side, last_test_at, test_interval_days, bypass_flag), path.csv(path_id, threat, consequence). 시험 기한 열이 없으면 못 쓴다.
- **6시간 최소 형태**: 살아 있음 = 시험 기한 안 + 바이패스 아님 → 경로별 개수 → 1겹 이하 빨강. 화면: 사고 시점 좌우 방벽 막대 + 위험 경로 Top 5.
- **반문 하나**: 「보타이는 그림일 뿐 정량이 아니다」 → 맞다. 그래서 방벽 수와 기한 초과를 숫자로 붙이고, 확률은 기대손실 결정표로 넘긴다.
- **하지 말 것**: 실레인 팹 보타이 사례는 근거 없음. 공개 사고(청주 M15X 가스실 화재)의 원인을 단정하지 않는다(원인 미확인).

## 상세

**한 줄**: 「화학·석유 산업에서는 위험물을 다루는 설비에서 사고 하나가 어떤 원인들로 생기고 어떤 피해로 번지는지를 볼 때 보타이 분석을 쓴다. 핵심 논리는 사고 시점(top event)을 한가운데 두고, 왼쪽에는 원인과 그걸 막는 예방 방벽, 오른쪽에는 결과와 피해를 줄이는 완화 방벽을 그려, 방벽 하나하나가 지금 살아 있는지 보는 것이다. 「원인·방벽·결과」를 가스실·스크러버의 누출 원인, 가스 감지기·자동 차단 밸브·배기, 대피·소화로 바꿔 대입하면 특수가스 공급 계통의 방벽 건강 상태판이 된다. 지금 방식(점검표 항목별 합격/불합격)과 비교해 「사고 경로마다 살아 있는 방벽 수」로 개선을 보일 수 있다.」
- **과제 문구 신호**(추론): 「가스실·스크러버 점검」「방벽」「누출」「정전·순간 전압 강하」「안전 상태판」
- **가정 변환**

| 원 분야 가정 | 반도체 현장 대응물 |
|---|---|
| 위험원 = 탄화수소·고압 | 실레인(자연 발화)·불산·염소 등 특수가스, 고전압 |
| 사고 시점 = 탱크 누출 | 가스 캐비닛·밸브 박스 누출, 스크러버 정지 |
| 예방 방벽 = 정비·알람·비상 정지 | PM 이력, 가스 감지기(1·2차 경보), 자동 차단 밸브, 이중관 |
| 완화 방벽 = 소화·대피 | 배기 강화, 구역 대피, 소방 연동 |
| 열화 요인 = 정비 지연·교육 부족 | 감지기 교정 기한 넘김, 바이패스 상태 방치, 협력사 작업자 교육 공백 |

- **원 분야 사실**(발표 자료): 구성 요소는 위험원(hazard) · 사고 시점(top event, "통제를 잃는 순간") · 위협(원인) · 결과 · 예방 방벽 · 완화 방벽 · 열화 요인(방벽을 약하게 만드는 조건) · 열화 통제. 만드는 순서는 9단계(위험원→사고 시점→위협→결과→예방 방벽→완화 방벽→열화 요인→열화 통제→검증). 같은 자료는 흔한 실수로 "방벽을 지나치게 단순화", "열화 요인 빠뜨림", "정량화 없음", "검증 안 함"을 든다. 예제는 데이터센터 건물 정전이다(팹 유틸리티와 가까운 예).
- **하이닉스 적용 예**(추론): (a) 가스실·스크러버 방벽 상태판: "지금 이 구역에서 누출이 나면 몇 겹이 막아 주나". 공개 보도된 2026-06 청주 M15X 가스실 화재(첫 사고 3,600여 명 대피, 원인 미확인 — 외부 출처 미확인)가 이 유형의 문제가 실재함을 보여 준다. (b) 팹 정전·순간 전압 강하 보타이(데이터센터 예제를 그대로 옮김).
- **기준선과 지표**: 기준 = 점검표 항목별 합격률. 제안 지표 = 사고 경로(위협→결과)마다 살아 있는 방벽 수, "1겹 이하 경로 수", 열화 요인이 걸린 방벽 비율. (추론)
- **6시간 최소 형태**:
  - 데이터 `barrier.csv(barrier_id, path_id, side[prevent|mitigate], type, last_test_at, test_interval_days, bypass_flag, owner)`, `path.csv(path_id, threat, top_event, consequence, severity)`.
  - 계산: 방벽이 살아 있음 = 시험 기한 안 + 바이패스 아님. 경로별 살아 있는 방벽 수 → 1겹 이하 경로를 빨강. 화면: 가운데 사고 시점, 좌우로 방벽 막대(초록·빨강), 오른쪽에 "위험 경로 Top 5". LLM 은 열화 요인 설명 문장만.
- **반론과 답**: "보타이는 그림일 뿐, 정량이 아니다" → 맞다, 발표 자료도 '정량화 없음'을 흔한 실수로 든다. 그래서 방벽 수와 기한 초과를 숫자로 붙이고, 확률까지 가려면 기대손실 결정표 기대손실로 넘긴다. "가스 안전은 이미 법정 점검이 있다" → 점검은 항목별, 보타이는 경로별이다. 같은 데이터를 다르게 묶어 "어느 경로가 사실상 한 겹인가"를 보여 준다.
