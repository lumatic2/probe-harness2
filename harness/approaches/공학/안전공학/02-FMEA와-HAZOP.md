# FMEA (고장 모드·영향 분석) / HAZOP

> [안전공학](README.md) › 02 · 짝 기법: [기대손실 결정표](../../../methods/의사결정분석/01-기대손실-결정표.md), [다기준 의사결정](../../../methods/의사결정분석/03-다기준-의사결정.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 자유 텍스트 조치 기록을 FMEA 표(고장 모드·RPN)로 자동 정리해 재발하는 상위 고장 모드를 고른다.
- **필요한 데이터**: note_id, eqp_id, chamber, occurred_at, symptom_text, cause_text, action_text, downtime_min. 조치 텍스트가 없으면 못 쓴다.
- **6시간 최소 형태**: LLM 추출 → 고장 모드 군집 → O=건수 구간, S=다운타임 구간, D=FDC 사전 경보 여부. 화면: RPN 정렬 표 + note_id 근거 링크 + 점수 수정 버튼.
- **반문 하나**: 「RPN 은 곱셈이라 S10·O1 과 S1·O10 이 같다」 → 맞는 약점이다. 심각도 상위는 RPN 과 따로 먼저 보여 준다(추론).
- **하지 말 것**: SEMATECH 92020963B-ENG·HAZOP 표준 IEC 61882 는 본문을 열지 못했으니 내용을 인용하지 않는다(미확인).

## 상세

**한 줄**: 「자동차·항공 산업에서는 새 설계나 공정을 내기 전에 어디서 고장이 날지를 볼 때 FMEA 를 쓴다. 핵심 논리는 고장 모드마다 심각도(S)·발생도(O)·검출도(D)를 매겨 곱한 위험 우선순위(RPN)로 먼저 고칠 것을 고르고, 고친 뒤 다시 매긴다는 것이다. 「부품·공정 단계」를 장비 서브시스템·레시피 단계로 바꿔 대입하면 장비 보전 조치 기록(Inform Note)을 FMEA 표로 자동 정리하는 문제에 적용된다. 지금 방식(조치 기록이 자유 텍스트로 쌓임)과 비교해 「RPN 상위 고장 모드의 재발 건수」로 개선을 보일 수 있다.」
- **과제 문구 신호**(추론): 「조치 기록 정리」「고장 모드」「재발 방지」「신규 레시피 도입 전 점검」「장비 보전 지식 도우미」
- **가정 변환**

| 원 분야 | 반도체 |
|---|---|
| 부품 | 챔버·펌프·RF 발생기·MFC(유량 제어기) |
| 고장 모드 | 압력 이탈, 아킹, 파티클, 리크 |
| 검출 수단 | FDC 모델, 인라인 계측, 웨이퍼 검사 |
| 고객 영향 | 수율 손실, 영향 LOT 수, 고객 클레임 |
| HAZOP 안내어 "더 많이/적게" | 가스 유량·온도·압력 레시피 이탈 |

- **원 분야 사실**:
  - RPN = 심각도 × 발생 확률 × 검출 효과. FMEA 표는 16~17열이고 "살아 있는 문서"로, 새 공정 도입·운전 조건 변경·고객 불만·새 규제 때 갱신한다.
  - 반도체에서는 설계(제품) FMEA 와 공정 FMEA 가 가장 흔하다. **반도체 실사용**: SEMATECH 가 1992년 반도체 장비 업계용 FMEA 지침(기술 이전 번호 92020963B-ENG)을 냈다 — 서지는 검색 결과로만 확인했고 본문은 열지 않았다.
  - HAZOP 은 화학 플랜트에서 "흐름 많음/적음/없음/역류" 같은 안내어로 공정 이탈을 훑는 짝 기법이다(통설 — 표준 IEC 61882 원문은 유료로 열지 않음, **미확인**).
- **하이닉스 적용 예**(추론): (a) 조치 기록 → FMEA 표 자동 생성: LLM 이 자유 텍스트에서 `고장 모드·원인·조치`를 뽑고, 다운타임·발생 빈도로 O 를, 영향 LOT 수로 S 를, 사전 검출 여부로 D 를 채운다. (b) 신규 레시피 도입 전 공정 FMEA 초안.
- **기준선과 지표**: RPN 상위 10개 고장 모드의 재발 건수·평균 다운타임, "검출도 나쁨(D 높음)" 모드 수 감소.
- **6시간 최소 형태**: 데이터 `note_id, eqp_id, chamber, occurred_at, symptom_text, cause_text, action_text, downtime_min`. 계산: LLM 추출 → 고장 모드 군집 → O=건수 구간, S=다운타임 구간, D=FDC 사전 경보 있었나. 화면: RPN 정렬 표 + 각 칸 근거 note_id 링크 + "점수 수정" 버튼(HITL).
- **반론과 답**: "RPN 은 곱셈이라 심각도 10·발생 1 과 심각도 1·발생 10 이 같다" → 맞는 약점이다. 그래서 심각도 상위는 RPN 과 따로 먼저 보여 준다(추론 — 신판 자동차 FMEA 의 '조치 우선순위' 방식이 같은 문제를 다룬다고 알려져 있으나 원문 확인 안 함, **미확인**). "점수가 주관적" → 조치 기록의 실제 빈도·다운타임으로 O·S 를 채워 주관을 줄인다.
