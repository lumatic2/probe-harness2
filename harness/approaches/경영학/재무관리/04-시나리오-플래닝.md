# 시나리오 플래닝 · 스트레스 테스트 · 수출통제 영향 분석

> [재무관리](README.md) › 04 · 짝 기법: [민감도 분석](../../../methods/의사결정분석/02-민감도와-가정-바꿔-보기.md), [강건·시나리오 계획](../../../methods/확률과-시뮬레이션/04-강건-시나리오-계획.md) (+[병목 분석](../../../methods/생산과-재고-운영/01-병목-분석.md))
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 수출통제 같은 불확실한 제도 변화를 2축×2값 4칸 시나리오로 만들고, 증설 계획이 칸마다 버티는지 시험한다(추론).
- **필요한 데이터**: 시나리오 정의 YAML(축·값·파라미터 변화)과 공급 위험 데이터 또는 생산 계획. 칸마다 다시 돌릴 계획 모델이 없으면 못 쓴다.
- **6시간 최소 형태**: 계산: 시나리오마다 같은 모델 재실행. 화면: 2×2 격자, 칸마다 KPI 카드, 칸 클릭 시 가정 목록.
- **반문 하나**: 「시나리오는 아무거나 만들 수 있다」 → 축은 공개된 제도 변화에서만 고르고 출처를 칸에 붙인다(축 고르기가 가장 어렵다고 셸도 말한다).
- **하지 말 것**: 시나리오를 예측처럼 말하기 — 셸은 예측도 기대도 전략도 아니라고 쓴다. 수출통제 사실 층은 이번에 다시 열지 않아 미확인.

## 상세

**한 줄**:
  - 「석유(셸)·금융 규제에서는 미래를 예측할 수 없는데 지금 결정을 내려야 할 때 시나리오 플래닝과 스트레스 테스트를 쓴다.
  - 핵심 논리는 예측이 아니라 서로 다른 가정 묶음으로 몇 갈래의 「가능한 세계」를 만들고, 지금 전략이 각 세계에서 버티는지 시험한다는 것이다.
  - 「유가·정권 변화」를 미국 대중 장비 반입 허가 변경·지역 수출규제·고객 RE100 요구·환율로 바꿔 대입하면 중국 팹·HBM 증설 계획의 시나리오별 영향 분석 문제에 적용된다.
  - 지금 방식(기준 계획 1개 + 민감도)과 비교해 「모든 시나리오에서 손실 상한을 넘지 않는 계획인가」로 개선을 보일 수 있다.」
- **과제 문구 신호**(추론): 「수출통제」「장비 반입 허가」「만약 ~이면」「최악의 경우」「증설 계획 점검」
- **가정 변환**

| 원 분야 | 반도체 |
|---|---|
| 유가·지정학 축 | 대중 장비 반입(연간 허가 갱신/불허) × 고객 수요(HBM 강세/조정) |
| 시나리오 4칸 | 2축 × 2값 |
| 전략 스트레스 테스트 | 우시 팹 운영 계획·인디애나 패키징 일정·재고 정책이 4칸에서 버티나 |

- **원 분야 사실**:
  - 셸은 시나리오가 "다른 가정 묶음 아래 세계가 어떻게 전개될 수 있는지의 탐색"이며, 예측도 기대도 아니고 전략·사업 계획도 아니라고 쓴다(1970년대 초부터 시나리오를 만들었다).
  - 자료·모델·전문가 통찰로 만들되 "모든 시나리오는 어느 정도 맞고, 어떤 식으로든 틀릴 가능성이 높다".
  - 셸 페이지 영상에서 와튼의 Schoemaker 는 가장 흔한 용도로 **기존 전략의 스트레스 테스트**를 꼽았다(2013 셸 영상 자막).
  - 공급망 스트레스 테스트를 다룬 Simchi-Levi 의 작업이 2022 미 대통령 경제보고서에 실렸다는 사실은 [공급 위험](../생산운영관리/05-공급-위험-TTR-TTS와-집중도.md) 출처가 전한다.
  - 수출통제의 사실 층(연간 허가, 가드레일, 18nm 기준)은 외부 출처 미확인이다 — 이번에 열지 않았다.
- **하이닉스 적용 예**(추론): (a) 2축 시나리오 매트릭스 + 칸마다 민감도 분석 토네이도·강건·시나리오 계획 최악 경우 결과. (b) 수출통제 영향 분석: "장비 반입 허가가 막히면 어느 공정 단계의 어느 장비 교체가 몇 분기 뒤 병목이 되나"(병목 분석 병목과 연결).
- **기준선과 지표**: 시나리오별 손실 분포, 최악 칸 손실, "모든 칸에서 허용선 안" 여부.
- **6시간 최소 형태**: 데이터: 시나리오 정의 YAML(축·값·파라미터 변화) + [공급 위험](../생산운영관리/05-공급-위험-TTR-TTS와-집중도.md) 데이터 or 생산 계획. 계산: 시나리오마다 같은 모델 재실행. 화면: 2×2 격자, 칸마다 KPI 카드, 칸 클릭 시 가정 목록. 공급망·리스크 과제에 바로 쓰는 틀이고, 아니면 서술형 답의 「확장」 대목용이다.
- **반론과 답**: "시나리오는 아무거나 만들 수 있다" → 셸 스스로 축을 고르는 게 가장 어렵다고(Lovins 발언, 같은 영상) 한다. 축은 공개된 제도 변화에서만 고르고 출처를 칸에 붙인다. "지정학을 해커톤에서?" → 위 최소 형태 끝 문장 참조.
