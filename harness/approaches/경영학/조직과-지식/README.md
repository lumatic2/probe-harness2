# 조직과 지식 — 학문 지도

> [입구](../../README.md) › [경영학](../README.md) › **조직과-지식** · 챕터 3
> 한 줄: **조직이론**은 일을 부서로 나눈 뒤 무엇이 어긋나고 무엇으로 다시 묶는지를 보고, **지식경영**은 조직 안의 지식이 어떻게 생기고 저장되고 옮겨지는지를 본다.
> **주의**: 논문 근거 대부분은 초록 기준이고 의료·차량·사무 맥락이다. 반도체 팹에 적용한 공개 사례는 이번 범위에서 찾지 못했다(근거 없음). 반도체로 옮긴 부분은 전부 추론이다.

## 핵심 질문
**일을 어떻게 나눴고, 나눈 것을 무엇으로 다시 묶나? 이 지식은 누구 머리에 있고, 글로 옮기면 무엇이 빠지나?**

## 이럴 때 꺼낸다 / 옆 모듈로
- **꺼낸다**: 같은 데이터를 부서마다 다르게 읽을 때 · 숙련자가 떠나면 노하우가 사라질 때 · 신입 교육이 선배 따라다니기일 때.
- **옆 모듈로**
  - 사람이 AI 추천을 믿고 쓰고 고치게 하는 설계, 이상 보고 문화 → 경영학 › [조직행동](../조직행동/README.md)
  - 생산 대 기술의 장비 시간 다툼, 8D·A3, Copy Exactly → 경영학 › [생산운영관리](../생산운영관리/README.md)
  - 인계 양식, 숙련자 면담 질문법 → [구조화 교대 인계](../../공학/인간공학/03-구조화-교대-인계.md) · [핵심 결정 기법](../../공학/인간공학/05-핵심-결정-기법.md)
  - 부서 KPI 상충을 파레토로 → 경영과학 파레토 프런티어 · 질의를 카드로 → 질문을 파라미터로

## 핵심 개념어
- **지식 경계 3층**: 구문(이름)·의미(뜻)·실용(이해관계). 층마다 전달·번역·변형이 필요하다.
- **경계 객체**: 부서마다 다르게 읽히되 정체성을 잃지 않는 공용 물건.
- **암묵지·형식지**: 몸에 밴 지식과 글로 적힌 지식. 둘 사이의 대화가 조직 지식을 만든다.
- **깊은 지혜(deep smarts)**: 경험에서 나온 판단력. 서로 다른 부품 사이의 상호작용으로 고장을 추적하는 기술자가 예다.

## 관점 쌍
- **정보 문제 ↔ 이해관계 문제**: 구문·의미 경계는 정보 문제이고, 실용 경계는 누가 손해 보느냐의 문제다([01](01-지식-경계와-경계-객체.md)).
- **코드화(문서·DB) ↔ 사람 연결(누가 아는지 이어 줌)**: 지식경영 교과서 통설이고 이번에 원문을 읽지 않았다(미확인). 02 는 앞쪽의 한계를, 교류 기억은 뒤쪽을 다룬다.

## 이 분야 사람이 먼저 묻는 것 5
1. 부서가 나뉘면 무엇이 어긋나고, 무엇으로 다시 묶나?
2. 아는 사람이 떠나면 무엇이 사라지나?
3. 이 지식은 누구 머리에 있고, 글로 옮기면 무엇이 빠지나?
4. 그 차이는 이름의 문제인가, 뜻의 문제인가, 누가 손해 보느냐의 문제인가?(추론)
5. 개발에서 양산으로 넘길 때 무엇이 새나?

## 흔한 함정
- 실용 경계를 용어 통일로 풀려 한다. 사전만 만들고 회의는 그대로다(추론, [01](01-지식-경계와-경계-객체.md)).
- 「단일 진실 원천」 하나로 모든 해석을 없애려 한다([01](01-지식-경계와-경계-객체.md)).
- 숙련자 지도를 개인 평가 자료로 쓴다(추론, [02](02-암묵지와-지식-전환.md)).
