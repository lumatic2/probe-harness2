# 지도카(자働化)와 안돈 — 기계가 멈추고 사람을 부른다

> [생산운영관리](README.md) › 02 · 짝 기법: [관리도와 오경보 주기](../../../methods/품질과-신뢰성-통계/01-관리도와-오경보-주기.md) · [기대손실 결정표](../../../methods/의사결정분석/01-기대손실-결정표.md) · [다기준 의사결정](../../../methods/의사결정분석/03-다기준-의사결정.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: AI 가 원인·대응을 제시하고 사람이 최종 판단한다는 원칙을 멈춤·호출·재개라는 현장 언어로 설명하게 해 준다(추론).
- **필요한 데이터**: FDC·계측 이상이 뜬 장비·로트의 이벤트 기록. 이게 없으면 이상 이벤트 큐를 만들 수 없어 못 쓴다.
- **6시간 최소 형태**: 계산: 이벤트마다 AI 판정(정지/관찰/통과)과 근거. 화면: 이상 이벤트 큐 — 판정·근거·승인 버튼·승인 이력(추론).
- **반문 하나**: 「반도체 팹에서 지도카를 쓴 사례가 있나」 → 공개 사례는 찾지 못했다(근거 없음). 손으로 먼저 재현하고 AI 로 옮겼다는 서사로 쓴다.
- **하지 말 것**: 토요타 기업 설명(E3)을 팹 효과의 근거로 말하기.

## 상세

**한 줄**: 「생산운영관리에서는 불량이 다음 공정으로 흘러가는 문제를 사람이 기계를 지켜보느라 묶여 있는 상황에서 풀 때 지도카(이상 시 자동 정지)와 안돈(이상 표시·호출)을 쓴다. 핵심 논리는 「기계가 이상을 판정해 멈추고, 사람은 이상이 났을 때만 대응한다」다. 「직기·조립 라인」을 FDC·계측 이상이 뜬 장비와 로트로, 「정지 끈」을 AI 의 홀드 제안 + 엔지니어 승인으로 바꾸면 「AI 가 원인과 대응을 제시, 사람은 최종 판단」 원칙을 운영 언어로 설명할 수 있다.」
- **과제 문구 신호**(추론): 「이상 감지 후 조치」「알람이 너무 많다」「사람이 모니터를 지켜본다」「홀드 판단」
- **가정 변환**

| 원 분야 | 반도체 |
|---|---|
| 직기·조립 라인 | FDC·계측 이상이 뜬 장비와 로트 |
| 정지 끈(이상 시 정지) | AI 의 홀드 제안 + 엔지니어 승인 |
| 안돈(이상 표시·호출) | 이상 이벤트 큐와 호출 |

- **원 분야 사실(E3, 기업 공식 설명)**:
  - 토요타는 지도카를 「automation with a human touch」라고 하고, 안돈에 대해 「People need only respond when there is an abnormality, thus eliminating the need for a person to watch over the equipment.」라고 쓴다.
  - 기계화 순서에 대해서는 「rather than starting with a machine from the beginning, you must first try doing it thoroughly by hand」라고 한다.
- **하이닉스 적용 예**(추론): AI 가 원인과 대응을 제시하고 사람이 최종 판단한다는 원칙을 제조 현장 사람이 아는 언어(멈춤·호출·재개)로 바꿔 말한다. 반도체 팹에 지도카를 그대로 쓴 공개 사례는 **찾지 못했다(근거 없음)**.
- **기준선과 지표**(추론): 지표 = 「지켜보는 시간」 절감.
- **6시간 최소 형태**(추론): 이상 이벤트 큐 화면 — 각 행에 「AI 판정(정지/관찰/통과) + 근거 + 승인 버튼 + 승인 이력」. 알람 우선순위 자체는 [알람 관리](../../공학/인간공학/01-알람-관리.md)·관리도와 오경보 주기·다기준 의사결정 을 쓴다.
- **반론과 답**(추론): 「손으로 먼저 해 보고 기계화」 원칙은 서술형 답의 흐름에 쓸 수 있다 — 「현업의 판정 절차를 먼저 손으로 재현하고, 그다음 AI 로 옮겼다」.
