# Copy Exactly! — 팹 복제와 변경 통제 (반도체 자체 사례)

> [생산운영관리](README.md) › 04 · 짝 기법: [공정능력](../../../methods/품질과-신뢰성-통계/03-공정능력.md)
> 원 분야 사실에는 근거 등급을 달았고, 반도체로 옮긴 부분은 별도 표시가 없으면 **추론**이다. 모듈 주의는 [모듈 README](README.md), 표기는 [입구](../../README.md) 「표기」.

## 바로 쓰는 칸
- **쓸 점**: 챔버 간·사이트 간 일치를 데이터로 감시해 입력 사양 차이, 출력 분포 차이, 변경 후 수율 이탈을 한 화면에 보인다(추론).
- **필요한 데이터**: chamber_spec.csv, output.csv, change.csv 세 가지(컬럼은 상세). 하나라도 없으면 그 비교(사양·출력·변경 전후)는 못 한다.
- **6시간 최소 형태**: 계산: 기준 챔버 대비 사양 차이 → 출력 평균·분산 검정 → 변경 전후 이동. 화면: 챔버×사양 열지도 + 출력 상자그림 + 변경 시간선.
- **반문 하나**: 「하이닉스도 이미 하는 것」 → 그럴 가능성이 높다(추론). 기법 소개가 아니라 「그 원칙을 데이터로 감시하는 화면」을 판다.
- **하지 말 것**: Copy Exactly 를 「변경 금지」로 설명하기 — 위키백과 인용 교육 자료는 「통제」라 했다(그 자료는 열지 않아 미확인).

## 상세

**한 줄**:
  - 「반도체(인텔)에서는 개발 팹의 공정을 새 양산 팹으로 옮길 때 수율·출력이 떨어지는 문제를 풀 때 Copy Exactly! 를 쓴다.
  - 핵심 논리는 이전·램프 기간에 통제되지 않은 공학적 「개선」이 오히려 출력을 깎으므로, 장비 구성·화학 순도·설비·배관까지 같은 사양으로 맞추고, 출력은 통계적으로 일치시키며, 변경은 합동 감사와 조정된 절차로만 한다는 것이다.
  - 이 기법은 반도체 안의 것이지만, 「사이트 간 일치」를 「챔버 간·라인 간 일치」로 바꿔 대입하면 챔버 매칭 문제에, 「변경 통제」를 「엔지니어 레시피 변경 이력」으로 바꾸면 변경-수율 영향 추적 문제에 적용된다.
  - 지금 방식(챔버별 개별 튜닝)과 비교해 「챔버 간 핵심 파라미터 분산」과 「변경 후 수율 이탈 건수」로 개선을 보일 수 있다.」
- **과제 문구 신호**(추론): 「챔버 간 품질 차이」「챔버 매칭」「레시피 변경 이력」「신규 팹 램프업」「변경 후 수율 이탈」
- **가정 변환**

| 원 분야(사이트 간) | 하이닉스 대응(추론) |
|---|---|
| 개발 팹 ↔ 양산 팹 | 이천 ↔ 청주 M15X ↔ 용인 신규 팹, 또는 같은 팹 안 챔버 A ↔ 챔버 B |
| 물리 입력 동일 사양 | 챔버 부품 버전·펌프 모델·가스 라인 길이 |
| 출력 통계 일치 | 챔버별 CD·막두께 분포 일치(공정능력 Cpk 와 연결) |
| 조정된 변경 + 합동 감사 | 레시피 변경 승인 이력 + 사이트 간 변경 동기화 |

- **원 분야 사실**:
  - 인텔의 1µm 기술 이전 경험 — 초록: 1µm 기술 검토에서 통제되지 않은 공학 혁신이 이전·램프 출력을 제한함을 보였고, 개발 팹의 학습을 복제하는 방법을 0.5·0.35·0.25µm 이전·램프 결과로 보였다.
  - 위키백과: 물리 입력(장비 구성·화학 순도·설비·장비 배관)은 같은 사양에서 나오고, 제품 성능·수율·신뢰성을 예측하는 인라인 모니터는 모든 수준에서 맞아야 하며, 조정된 변경·감사·공정 관리 시스템·합동 팹 관리 구조로 계속 맞춘다.
  - 처음엔 장비 세트와 공정 대상이었으나 팹 전체로 넓혔다.
  - 리튬 배터리 회사 A123 도 한국·중국 생산을 미국으로 옮기며 같은 전략을 썼다(위키백과 서술, E3).
- **하이닉스 적용 예**(추론): (a) 챔버 매칭 진단: 같은 레시피를 도는 챔버들의 입력 사양 차이와 출력 분포 차이를 나란히 놓고 "어떤 입력 차이가 출력 차이와 같이 움직이나"를 보여 준다. (b) 신규 팹 램프업 체크: 용인 신규 팹 같은 확장에서 "복제할 것 목록 vs 이미 달라진 것 목록".
- **기준선과 지표**: 챔버 간 핵심 출력 분산, 사양 불일치 항목 수, 변경 후 수율 이탈 건수.
- **6시간 최소 형태**: 데이터 `chamber_spec.csv(chamber_id, item, value, version)`, `output.csv(lot_id, chamber_id, metric, value)`, `change.csv(ts, chamber_id, item, before, after, approver)`. 계산: 기준 챔버 대비 사양 차이 표 → 출력 분포 차이(평균·분산 검정) → 변경 전후 출력 이동. 화면: 챔버×사양 차이 열지도 + 출력 상자그림 + 변경 시간선.
- **반론과 답**: "복제하면 개선을 못 한다" → 위키백과가 인용한 교육 자료 쪽 설명은 '변경 금지'가 아니라 '통제'다(그 자료는 스크립드 사본이라 열지 않음 — **미확인**). 오류 예산([SLO와 오류 예산](../../공학/신뢰성공학/01-SLO와-오류-예산.md))과 묶으면 "허용된 변경 예산" 안에서 개선한다. "하이닉스도 이미 하는 것" → 그럴 가능성이 높다(추론). 그래서 기법 소개가 아니라 "그 원칙을 데이터로 감시하는 화면"을 판다.
