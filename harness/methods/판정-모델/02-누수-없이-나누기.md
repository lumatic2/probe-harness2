# 누수 없이 나누기 (시간 · 그룹 · 전처리 · 순열 잡음대)
> 접근법 선반: [효과 수치 읽는 법](../../approaches/경영과학/모형을-믿어도-되나/03-효과-수치-읽는-법-기준선과-자기-신고.md)(점수를 기준선과 나란히 읽기) · [독립 검사기](../../approaches/경영과학/모형을-믿어도-되나/02-독립-검사기-계산한-쪽이-아닌-다른-코드로.md)

> 배포 때 마주할 상황(미래 시점 · 처음 보는 장비)을 흉내 내는 방식으로 나누고, 특징 선택·스케일·결측 대체를 전부 학습 접힘 안에서만 하며, 무작위 라벨 점수를 「잡음대」로 재서 점수가 진짜인지 판정한다. 설명(순열 중요도·SHAP)은 연관이지 원인이 아니라는 한 칸을 함께 둔다. 붙는 과제 유형: 전 유형 공통(모든 판정 모델). 코드: `../code/leakage_split_check.py`

## 바로 쓰는 칸
- **쓸 점**: 배포 상황(미래 시점·처음 보는 장비)대로 나누고 전처리를 접힘 안에서만 하며, 무작위 라벨 잡음대로 점수가 진짜인지 판정한다.
- **필요한 컬럼**: `t0`(판정 시점)·`group_id`(장비·로트 묶음)·`label`·t₀ 에 알려진 특징 열 — 시각과 그룹 id 가 없으면 시간·그룹 분할을 못 한다.
- **한 줄 실행**: `python code/leakage_split_check.py` (methods 폴더에서) — 합성 표로 분할별 점수·잡음대 (scikit-learn 필요). 내 데이터로 쓸 때 부를 함수: `time_splits`, `permutation_band`
- **출력**: 분할 방식별 점수표(ROC-AUC·PR-AUC·유효 접힘 수), 순열 잡음대 범위, 경고 문구.
- **하지 말 것**: 시계열 사건에 `train_test_split(shuffle=True)` 를 쓰거나 특징 선택·스케일·오버샘플링을 분할 전에 하지 않는다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 무작위 교차검증 · 시간 순 단일 홀드아웃 — 행들이 서로 독립이고 배포 때도 같은 분포의 새 행이 올 때만 무작위 분할로 충분하고, 로트·장비·시간 묶음이 있으면 점수가 부풀며, 단일 홀드아웃은 분할 하나라 양성이 적으면 흔들리고 잡음대와 비교할 수 없어 이 기법을 골랐다.

## 이럴 때 꺼낸다
- 과제 문구: "정확도 9x%", "성능 평가", "검증", "일반화", "과적합". 점수가 좋게 나와 의심스러울 때.
- 데이터 모양: 행마다 시각·장비 id·로트 id 가 있는 표(`samples(sample_id, t0, entity_id, group_id, label, features…)`).
- 꺼내지 말아야 할 때: 없다. 표본이 수십 건뿐이면 분할 자체가 불안정하니 구간(03)과 함께 읽는다.

## 입력 → 출력
| 입력 컬럼 | 의미 |
|---|---|
| `t0` | 판정 시점(시간 분할의 기준) |
| `group_id` | 같은 장비·로트·웨이퍼 묶음(그룹 분할의 기준) |
| `label` | 01 에서 만든 0/1 |
| 특징 열 | t₀ 에 알려진 것만(01 의 허용 목록) |
- 출력: 접힘 목록 `[(train_idx, test_idx)]` 와 분할 방식별 점수표(ROC-AUC · PR-AUC · 유효 접힘 수) · 순열 잡음대(평균·범위) · 경고 문구. 시험 구간 앞쪽 `gap` 은 `time_splits(t, n_splits, gap)` 가 시각 기준으로 자른다(행 수가 아니라 시각이므로 불규칙한 사건 시각에도 맞다).
- → 실행 결과는 부록
- 실행: `python code/leakage_split_check.py` (numpy·pandas·scipy·scikit-learn, 약 3초). 현장에서 바꿔 끼우는 곳: `t, g, y, X` 네 배열, `gap`, `lr_pipe()` 의 모델.

## 핵심 개념
- **전처리 누수**: scikit-learn 문서는 "The general rule is to never call fit on the test data." 라고 쓴다. 스케일·결측 대체·PCA·특징 선택·오버샘플링 모두 `Pipeline` 안에 넣어 교차검증이 접힘마다 다시 학습하게 한다.
- **분할은 배포 상황으로 정한다**: 미래 시점을 예측하면 시간 분할, 처음 보는 장비·로트를 예측하면 그룹 분할. 시간 분할은 학습 끝과 시험 시작 사이에 `gap`(= W+H)을 둔다.
- **순열 라벨 잡음대**: 라벨을 섞어 같은 절차로 20회 점수를 재면 「신호가 전혀 없을 때」 점수의 범위가 나온다. 실제 점수가 그 밖이어야 신호가 있다.
- **설명은 연관**(한 칸): 순열 중요도는 홀드아웃에서 계산하고, 상관된 특징은 묶어서 읽는다. 중요도 상위는 「이 모델이 기댄 신호」이지 근본 원인이 아니다.

## 반도체 현장에서
- 같은 로트·장비·재측정·알람 연쇄·겹치는 창이 비독립 원천이다(추론). 그래서 무작위 행 분할은 점수를 부풀린다.
- SECOM 한 비교 연구는 다른 연구들이 분할 전에 전처리(특징 선택)를 했다고 짚는다(근거 참조).
  - 이 레포 직접 시험(**한 데이터·한 분할점·튜닝 없음**의 결과, 다른 분할점이나 튜닝으로 바뀔 수 있음): 같은 모델의 ROC-AUC 가 무작위 5겹 0.73(HGB) → 시간 순 분할 0.56 이었고, 무작위 라벨에 분할 전 특징 선택을 걸면 0.57~0.67, 파이프라인 안이면 0.51~0.57 이었다.
  - 양성 104건 규모에서는 무작위 라벨도 최대 0.60 까지 나와서, 「AUC≈0.5」가 아니라 「순열 20회 잡음대 안이면 신호 없음」으로 판정한다.
- WM-811K 는 같은 로트의 25장이 공통 원인을 공유하므로 무작위 웨이퍼 분할은 비독립 누수 후보다 → 로트 단위 그룹 분할(추론). **공개 논문들의 로트 그룹 분할 관행은 확인하지 못했다(`미확인`).** PHM 2016 CMP 는 1초 시계열 행이므로 웨이퍼 단위 그룹 분할(추론; 같은 웨이퍼의 행이 학습·시험 양쪽에 들어가면 안 된다).

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론: 분할·파이프라인·점수·순열 잡음대·분할 구조 검사. 점수는 AI 가 계산하지 않는다.
- AI: 「배포 때 처음 보는 것이 장비인가 시점인가」를 사용자에게 묻는 질문, 분할 선택 사유 문장.
- 설명 틀: "배포 상황이 ○이므로 ○ 분할로 나눴습니다. 무작위 분할 점수는 ○, 이 분할은 ○입니다. 무작위 라벨 20회 점수는 ○~○ 이고 실제 점수는 그 ○쪽입니다. 중요도 상위 ○개는 모델이 기댄 신호이며 원인은 엔지니어가 확인합니다."

## 화면 한 장
- 시간축 위에 학습 / 간격 / 시험 띠 + 막대 3개(무작위 분할 · 시간 분할 · 무작위 라벨 잡음대) + 「모델이 기댄 신호 상위 5 — 원인 확인은 엔지니어」 문구.

## 함정
- `train_test_split(shuffle=True)` 를 시계열 사건에 쓰는 것. 시험셋까지 언더샘플링해 균형을 맞추는 것(정밀도가 실제 양성 비율에서보다 높게 나온다 — 추론).
- 분할 전 오버샘플링(SMOTE 등): 학습셋에서 만든 합성 표본이 시험셋에도 들어간다.
- 시험 구간을 여러 번 열어 설정을 고르고 마지막 점수를 보고하는 것.
- 중요도 함정: 불순도 중요도는 값 종류가 많은 특징에 치우친다. 순열 중요도는 나쁜 모델에서는 해석할 수 없고(먼저 홀드아웃 성능 확인), 상관된 두 특징은 각각 낮게 나온다(이 코드 시연: 단독 0.327 → 복제 시 각 0.10). SHAP 문서는 「상관을 투명하게 해도 인과가 되지는 않는다」고 쓴다.
- 누수 검사는 순열 여러 번의 평균으로 해야 보인다. 단일 순열의 누수 효과(SECOM 직접 시험 0.57~0.67)는 잡음대 상단(0.60)과 겹친다.

## 한 문장 설명 · 예상 질문
- "가장 높은 점수가 아니라, 내일도 나올 점수를 보여 드립니다."
- Q. 왜 점수가 이렇게 낮나? A. 무작위로 섞으면 같은 로트·같은 시기의 이웃이 학습과 시험에 함께 들어가 점수가 부풀려집니다. 배포 상황대로 나눈 점수와 무작위 라벨 잡음대를 같이 보여 드립니다.
- Q. SHAP 상위 특징이 근본 원인인가? A. 아닙니다. 모델이 기댄 연관이며, 원인 확인은 실험이나 장비 이력 대조로 넘깁니다.

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert:
  - ① 누수 평균 점수 > 파이프라인 안 평균 + 0.08, 파이프라인 안 평균은 0.5 ± 0.04
  - ② 그룹 교집합 0, 시간 분할은 학습 최대 시각 + gap ≤ 시험 최소 시각, 시험 접힘끼리 겹치지 않음
  - ③ 규칙적 시각에서 이 코드의 `time_splits` 가 scikit-learn `TimeSeriesSplit(gap)` 과 같은 학습·시험 집합을 냄(독립 구현 대조)
  - ④ 신호가 있는 대조 표의 점수가 순열 잡음대 상단을 넘고, 라벨을 섞은 점수는 잡음대 안
  - ⑤ 시간 구조 표에서 무작위 − 시간 > 0.05 이고 경고가 켜지며 대조 표에서는 꺼짐
  - ⑥ 그룹 구조 표에서 무작위 − 그룹 > 0.03
  - ⑦ 복제 특징을 넣으면 사본의 순열 중요도가 단독 때의 80% 미만.
- 현장 추가 경계 테스트: (a) 시험 구간에 학습 구간과 같은 로트가 없는지 (b) 임계값·하이퍼파라미터를 시험 구간으로 골랐다면 그 시험은 더 이상 시험이 아니다 — 검증 구간을 따로 둔다 (c) 시험 양성이 수십 건이면 구간을 붙인다(03).

### 합성 데이터 실행 결과
- 합성 결과(시간·그룹 구조를 심은 표, n=1500, 양성 비율 0.145): ROC-AUC · PR-AUC — 무작위 5겹 0.810 · 0.480, 그룹 5겹 0.703 · 0.298, 시간 확장 창 0.618 · 0.227, 순열 잡음대 0.416~0.540(평균 0.488).
  - 구조 없는 대조 표는 무작위 0.823 / 그룹 0.825 / 시간 0.781 로 차이가 작아 경고가 꺼진다.
  - 잡음 특징 500개에서 상위 20개를 분할 전에 고르면 무작위 라벨의 AUC 평균 0.819(최대 0.883), 파이프라인 안이면 0.517(최대 0.645).

### 손익 환산
- 분할 선택은 비용을 줄이지 않고 **배포 후 실망 비용**을 줄인다. 원천에 환산 수치가 없다. 합성 표에서 무작위 분할 0.810 이 시간 분할 0.618 로 내려가는 것은 방법 시연이며 하이닉스에서도 이만큼 내려간다는 뜻이 아니다. 현장 점수 차는 현장 데이터에서 이 코드로 다시 잰다.
