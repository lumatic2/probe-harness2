# 임계값을 비용으로 정하기 (오경보 비용 대 놓침 비용)
> 접근법 선반: [알람 관리](../../approaches/공학/인간공학/01-알람-관리.md)(오경보의 비용은 엔지니어의 주의) · [효과 수치 읽는 법](../../approaches/경영과학/모형을-믿어도-되나/03-효과-수치-읽는-법-기준선과-자기-신고.md)(단순 정책을 기준선으로) · 짝 기법: [기대손실 결정표](../의사결정분석/01-기대손실-결정표.md)

> 경보를 낼지 말지는 확률을 배우는 문제와 따로 정하는 결정 문제다. 보정된 확률이면 `p* = c_FP/(c_FP+c_FN)` 이상에서 경보, 보정이 안 됐으면 검증 구간에서 비용 곡선의 최소점을 고르며, 「전부 통과」「전부 경보」 두 정책을 못 이기면 모델을 내지 않는다. 붙는 과제 유형: ① ③ ④. 코드: `../code/imbalanced_eval.py` (03 과 같은 파일)

## 바로 쓰는 칸
- **쓸 점**: 경보 임계값을 오경보·놓침 비용 비로 정하고, 「전부 통과」「전부 경보」 두 정책을 못 이기는 모델은 내지 않는다.
- **필요한 컬럼**: 검증 구간 `y_val`·`prob_val` 과 오경보·놓침 1건 비용 `c_fp`·`c_fn`(현업 가정) — 비용 비를 말할 수도 가정할 수도 없으면 못 쓴다.
- **한 줄 실행**: `python code/imbalanced_eval.py` (methods 폴더에서) — 03 과 같은 파일, 비용비 1:10 비교 (scikit-learn 필요). 내 데이터로 쓸 때 부를 함수: `tune_threshold`, `policy_compare`
- **출력**: p*·검증에서 고른 임계값, 임계값별 비용 곡선, 모델·전부 통과·전부 경보 비용과 「채택/미채택」 판정.
- **하지 말 것**: p* 공식을 보정 안 된 확률(균형 가중·오버샘플링 학습 뒤)에 쓰지 않는다 — 시험셋으로 임계값을 고르고 같은 셋으로 보고하지도 않는다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 기본 임계값 0.5 · 하루 처리 건수 k 로 자르는 상위 k(정밀도@k) — 오경보·놓침 비용 비를 말하거나 가정할 수 있을 때 비용으로 임계값을 정하고, 처리 능력이 하루 k 건으로 이미 정해져 있으면 상위 k 가 더 단순하며, 선택지가 3개 이상이면 기대손실 결정표가 맞다.

## 이럴 때 꺼낸다
- 과제 문구: "경보 기준", "임계값 0.5 의 근거는?", "오경보가 너무 많다", "놓치면 안 된다", "출하 판정 컷".
- 데이터 모양: 검증 구간의 `scores(sample_id, prob, label)` + 오경보·놓침 비용(또는 비용 비) 두 값.
- 꺼내지 말아야 할 때: 비용 비를 전혀 말할 수 없고 가정도 못 둘 때 → 비용 비 슬라이더로 경계만 보인다. 선택지가 3개 이상(출하/재검/폐기)이면 [기대손실 결정표](../의사결정분석/01-기대손실-결정표.md).

## 입력 → 출력
| 입력 | 의미 |
|---|---|
| `y_val, prob_val` | 검증 구간 라벨·확률(학습에 쓰지 않은 구간) |
| `c_fp, c_fn` | 오경보 1건 비용 · 놓침 1건 비용(**가정** — AI 가 지어내지 않는다) |
| `y_test, prob_test` | 시험 구간(마지막에 한 번만) |
- 출력: `derived_threshold(c_fp, c_fn)` = p* · `tune_threshold` = 검증 구간 비용 최소 임계값과 그 비용 · `cost_at` = 임계값별 비용 · `policy_compare` = `{model, all_pass, all_alarm, verdict}` (모델 비용이 두 정책 중 싼 쪽보다 작을 때만 「채택」).
- → 실행 결과는 부록
- 실행: `python code/imbalanced_eval.py`. 현장에서 바꿔 끼우는 곳: `c_fp`, `c_fn`, `k` 와 `df`.

## 핵심 개념
- scikit-learn 문서는 기본 판정(확률 0.5)이 대부분의 용도에 이상적이지 않다고 쓰고, 분류를 「확률을 배우는 통계 문제」와 「그 확률로 행동을 정하는 결정 문제」로 나누라고 한다.
- Elkan(2001) 초록: 비용이 다를 때 권장하는 방법은 학습 표본을 그대로 두고 분류기의 확률 추정으로 최적 결정을 명시적으로 계산하는 것이다.
- **산식(이 문서가 표준 기대비용 계산에서 유도 — 논문 인용이 아니다)**: 맞은 판정 비용 0 일 때 경보 시 기대비용 `(1−p)·c_FP`, 통과 시 `p·c_FN`. `p ≥ c_FP/(c_FP+c_FN)` 이면 경보. 놓침이 오경보의 10배면 `p* = 1/11 ≈ 0.091`. Elkan 원문의 해당 정리 식은 본문 2절 이후라 열지 못했다(초록·1절 첫 문단만 확인).
- 확률이 **보정됐을 때만** `p*` 가 맞다. 아니면 검증 구간에서 임계값을 쓸어 실제 비용이 최소인 점을 고른다. 이 코드는 그 계산을 직접 한다(`tune_threshold`) — scikit-learn `TunedThresholdClassifierCV`(1.5 이상, 맥북 버전 `미확인`)에 기대지 않는다.

## 반도체 현장에서
- c_FN = 놓친 정지·스크랩·Q-Time 폐기 손실, c_FP = 헛경보 1건당 엔지니어 확인 시간 + 불필요한 우선 처리로 밀린 다른 로트의 지연(원천 추론). 비용 비가 바뀌면 임계값이 바뀐다는 것을 슬라이더로 보이는 것이 설명에서 설득력이 크다(추론).
- 하루 처리량 상한 k 가 있으면 비용 최소 임계값과 「상위 k」 중 더 보수적인 쪽을 쓴다(추론). 이 코드는 두 값을 같이 계산하게 하는 부품(03 의 `precision_recall_at_k`, 이 문서의 `tune_threshold`)만 주고 선택은 사람이 한다.
- SECOM 직접 시험(**한 데이터·한 분할점·튜닝 없음**): 시간 분할 시험셋에서 비용비 10:1 로 전부 통과 260, 전부 경보 445, 균형 가중 모델 272(임계 0.5)·301(임계 1/11) — 모델이 전부 통과를 못 이겼다. 비용 숫자는 가정 칸이다.

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론: p*, 임계값별 비용 곡선, 최소점, 정책 비교. 난수 없음(합성 데이터 생성 제외).
- AI: 비용 가정을 사용자에게 묻고 화면에 「가정」 으로 표시, 결과를 원화 문장으로 번역. 예) "놓침이 오경보의 20배면?" → `c_fn=20`. 비용 숫자를 AI 가 지어내지 않는다.
- 설명 틀: "놓침 1건은 오경보 ○건과 같은 비용이라 확률 ○ 이상이면 경보를 냅니다(보정된 확률일 때). 검증 구간에서 고른 임계 ○로 시험 구간 비용은 ○, 전부 통과는 ○, 전부 경보는 ○입니다. 모델이 두 정책보다 ○이므로 ○합니다."

## 화면 한 장
- 비용비 슬라이더 → 임계값 이동, 비용 곡선 위 점 3개(모델 · 전부 통과 · 전부 경보), 「하루 경보 n건 · 기대 절감(가정 단가)」 카드, 모델이 못 이기면 「모델 미채택」 배지.

## 함정
- 임계값을 0.5 로 고정, F1 최대화를 업무 최적으로 착각(F1 은 비용을 모른다).
- 시험셋으로 임계값을 고르고 같은 시험셋으로 성능 보고 — scikit-learn 문서의 경고: 분류기 학습과 임계값 조정에 같은 데이터를 쓰면 과적합 위험이 있다.
- 「전부 통과」 기준선 비교 누락.
- p* 공식을 보정 안 된 확률에 적용(균형 가중·오버샘플링 학습 후 확률 포함).
- 이 코드의 기대비용은 맞은 판정 비용 0 이라는 가정이다. 정상 통과·정확한 경보에도 비용이 있으면(경보 후 정지로 인한 손실 등) 식이 바뀐다 — 그럴 땐 [기대손실 결정표](../의사결정분석/01-기대손실-결정표.md)의 표를 직접 쓴다(추론).

## 한 문장 설명 · 예상 질문
- "임계값은 모델이 아니라 현장의 손실 비율이 정합니다 — 그리고 모델이 '아무것도 안 하기'를 못 이기면 내지 않습니다."
- Q. 비용은 어디서 나오나? A. 현업 입력 칸이며 값에 가정 표시를 붙입니다. 비용비가 바뀔 때 임계값과 결론이 어떻게 움직이는지 슬라이더로 보입니다.
- Q. 임계값 0.5 면 안 되나? A. 놓침이 오경보의 10배 비싸면 0.091 부근이 기대비용 최소입니다. 단 확률이 부풀려져 있으면 이 공식이 틀려서 검증 구간에서 직접 찾습니다.

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert:
  - ① 손계산 비용 — 점수 0.9~0.4, 임계 0.65 에서 오경보 1건 → 비용 1, 전부 통과 20, 전부 경보 4, 검증 최소 임계 0.7
  - ② **유도한 임계값 p* 의 기대비용이 참 확률 모집단 5만 개에서 2,001점 격자 탐색 최소 비용과 같음** — 비용비 1:1, 1:10, 5:1, 1:100, 3:7 다섯 가지
  - ③ 라벨을 확률로 뽑은 실제 비용에서도 p* 비용이 격자 최소의 1% 이내
  - ④ c_FN→∞ 이면 p*→0(전부 경보), c_FP→∞ 이면 p*→1(전부 통과)
  - ⑤ 신호 없는 모델은 「미채택」, 강한 모델은 「채택」
  - ⑥ 시험 구간에서 직접 고른 임계의 비용 ≤ 검증 임계의 비용(시험으로 고르면 낙관 편향이 있다는 증거)
  - ⑦ 균형 가중 확률의 Brier > 상수 예측.
- 현장 추가 경계 테스트: (a) 비용비 1:1 이면 p*=0.5 인지 (b) 임계값을 고른 구간과 성능을 보고하는 구간이 다른지 (c) 비용이 바뀌면 같은 검증 구간으로 임계만 다시 계산되는지.

### 합성 데이터 실행 결과
- 합성 결과(위 03 과 같은 데이터, 비용비 c_FP=1·c_FN=10, 시험 4,800×25% = 1,200건에 사건 약 71건): 전부 통과 710 · 전부 경보 1,129.
  - 일반 로지스틱: p*(0.091) 적용 272, 검증에서 고른 임계(0.061) 적용 264 → 채택.
  - **균형 가중 로지스틱**: p*(0.091) 적용 586 이지만 검증에서 고른 임계(0.608) 적용 252 — 확률이 부풀려져 있으면 p* 공식이 틀리고 검증 구간 탐색이 맞다.
  - 신호 없는 데이터: 검증 임계가 1.0(경보 안 함)이 되어 모델 590 = 전부 통과 590 → **미채택**.

### 손익 환산
- 원천에 비용 환산 수치가 없다. 합성 예의 비용은 단위 없는 상대값이다(c_FP=1, c_FN=10 은 가정). 시험 구간에서 일반 로지스틱의 검증 임계 비용 264 는 전부 통과 710 의 약 37% — 합성 방법 시연이며 하이닉스 효과 근거가 아니다.
- 실제 환산: c_FN 은 [기대손실 결정표](../의사결정분석/01-기대손실-결정표.md) 와 같은 방식으로 재무 추정 단가에 가정 슬라이더를 얹는다.
