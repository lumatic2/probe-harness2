# CP-SAT 잡숍/유연 잡숍 (CP-SAT Job Shop with Q-Time)
> 작업을 구간 변수로 두고 "같은 장비 겹침 금지·선후 관계·Q-Time 상한"을 하드 제약으로 걸어 완료시각을 최소화하는 제약 프로그래밍. 붙는 과제 유형: ② (①의 조치 후 재배정). 코드: `../code/cpsat_jobshop.py`

## 바로 쓰는 칸
- **쓸 점**: Q-Time·장비 겹침 금지·PM 창을 깰 수 없는 규칙으로 걸어 makespan 을 최소화한 일정과 위반 0건 증명을 얻는다.
- **필요한 컬럼**: `ops`(lot, step, machine, dur), `qtime`(lot, step, max_wait), 정지창 dict. 장비 후보별 공정시간이 없으면 못 쓴다.
- **한 줄 실행**: `python code/cpsat_jobshop.py` (methods 폴더에서) — 합성 LOT 의 FIFO 대 CP-SAT makespan·Q-Time 위반. (ortools 필요) 내 데이터로 쓸 때 부를 함수: `solve`, `check_schedule`
- **출력**: 일정표(lot, step, machine, start, end)·상태·makespan·검사기 위반 목록, 기준선 대비 makespan·Q-Time 위반 건수.
- **하지 말 것**: LOT 수천×장비 수백을 그대로 풀지 않는다(시간 제한·분해 필요). 상태가 OPTIMAL 일 때만 「최적」이라 말한다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 디스패칭 규칙 시뮬레이션 · 최소 변경 재스케줄 — 선후·겹침·Q-Time 을 깰 수 없는 규칙으로 걸고 위반 0건을 보여야 하면 이 기법을 고르고, 도착이 확률적이어서 규칙끼리 비교하는 문제면 디스패칭 규칙 시뮬레이션을, 이미 있는 일정이 교란으로 깨진 뒤의 재배정이면 최소 변경 재스케줄을 쓴다.

## 이럴 때 꺼낸다
- 과제 문구 신호: "일정을 짜라", "LOT 우선순위·배정", "Q-Time 을 넘기지 않게", "장비 PM/고장을 피해서", "위반 0건".
- 데이터 모양 신호: LOT·공정 단계·장비 후보·공정시간 컬럼, 장비별 정지(PM) 시간대, "앞 공정 종료 후 N분 안에 다음 공정 시작" 같은 규칙표.
- 꺼내지 말아야 할 때: 규칙이 선후·겹침이 아니라 확률적 도착이라면(→ 디스패칭 규칙 시뮬레이션). LOT 수천 개 × 장비 수백 대로 커지면 그대로 풀리지 않는다(시간 제한·분해·휴리스틱 필요).

## 입력 → 출력
입력 (DataFrame)

| 표 | 컬럼 | 의미 | 단위 |
|---|---|---|---|
| `ops` | `lot` | LOT 이름 | 문자열 |
| | `step` | 공정 순번(0부터, 같은 LOT 안에서 연속) | 정수 |
| | `machine` | 이 공정을 할 수 있는 장비 후보 (후보마다 한 행) | 문자열 |
| | `dur` | 그 장비에서의 공정시간 | 분 |
| `qtime` | `lot`, `step`, `max_wait` | `step` 종료 ~ `step+1` 시작 허용 대기 | 분 |
| `down` (dict) | `{장비: [(시작, 끝), ...]}` | PM·고장 정지 창 | 분 |

출력: 일정표 `lot, step, machine, start, end`, 상태(OPTIMAL/FEASIBLE), makespan, 검사기 위반 목록. KPI = makespan · LOT 완료시각 · Q-Time 위반 건수(기준선 대비).

## 핵심 개념
- 공정 하나 = 시작 s, 끝 e, 장비 후보마다 선택 변수 b 를 가진 선택 구간. 장비마다 `NoOverlap`(겹침 금지), PM 창은 고정 구간으로 넣는다.
- 선후: `s[k+1] >= e[k]`. Q-Time 은 그 위에 상한을 하나 더 얹는다: `s[k+1] - e[k] <= 허용대기`. 목적 = makespan 먼저, 그다음 총 완료시각.
- 솔버가 최적(OPTIMAL)이라고 답하면 "이 제약 아래 이보다 짧은 일정은 없다"는 증명까지 딸려 온다.

## 반도체 현장에서
- LOT×장비 배정·순서 결정, PM 창 회피, Q-Time(앞 공정 종료~다음 공정 시작 상한)을 "벌점"이 아니라 "깰 수 없는 규칙"으로 둔다 (S14 OR-Tools 공식 잡숍).
- 공식 채널 세 조직에서 Q-Time 폐기 손실·LOT 우선순위·지능형 스케줄링이 반복 등장한다 (외부 출처 미확인). 제약 위반 0건을 증명하는 일정이 이 유형의 중심 증거다.

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론: 배정·순서 결정(CP-SAT), 위반 검사(`check_schedule`), 기준선(`greedy_fifo` = 준비된 순서대로 가장 빨리 끝나는 장비) 재현.
- AI: 현업 질문 → 파라미터 변경.
  - "식각 E3 이 20분부터 80분까지 멈추면?" → `down = {"E3": [(20, 80)]}` 로 `solve()` 재실행.
  - "포토→식각 대기 한도를 5분에서 10분으로 풀면 얼마나 빨라지나?" → `qtime.max_wait = 10` 으로 재실행해 makespan 비교.
  - 설명 문장 틀: "E3 정지 시 makespan 이 X분에서 Y분으로 늘며, Q-Time 위반은 0건입니다. 늘어난 Z분은 E1·E2 에 몰린 LOT 대기 때문입니다."

## 화면 한 장
- 장비별 간트(x = 시간, y = 장비). 공정 사이 대기가 허용치의 80% 를 넘는 구간은 빨간 테두리, 기준선 일정은 연한 색으로 위/아래 비교. 화면 모서리에 "검사기 위반 0건" 배지.

## 함정
- Q-Time 을 하드로 걸면 INFEASIBLE 이 나올 수 있다. "어느 제약이 충돌하나"를 보이려면 Q-Time 을 벌점으로 바꾼 변형을 함께 돌린다.
- 시간 단위 혼용(분/초)과 정수화: CP-SAT 은 정수만 받는다. 소수 공정시간은 한 단위로 반올림해 넣고, 검사기는 같은 단위로 본다.
- `horizon` 이 너무 작으면 INFEASIBLE, 너무 크면 느려진다. 기준선 makespan 의 1.5배 정도로 시작한다.
- 재진입 공정은 `step` 으로 구분한다(같은 장비를 한 LOT 이 두 번 쓴다). `step` 을 LOT 안에서 유일하게 만든다.

## 한 문장 설명 · 예상 질문
- 한 문장: "규칙 위반 0건을 증명하는 일정입니다 — 사람이 짠 일정과 같은 데이터로 비교했습니다."
- Q. 솔버가 최적이라는 걸 어떻게 믿나? → 상태가 OPTIMAL 일 때만 "최적"이라 말하고, 별도 검사기가 위반 0건을 다시 센다.
- Q. 데이터가 10배 커지면? → 시간 제한 안의 FEASIBLE 해를 쓰고 상태를 화면에 그대로 표기한다. 분해(스테이션별)·휴리스틱 초기해로 확장한다(추론).

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert: ① `check_schedule` 이 솔버 코드와 무관하게 일정표만 읽어 장비/공정시간 일치·선후·Q-Time·겹침·정지창 침범을 센다(위반 0). ② 일부러 한 행의 종료를 늘린 변조 일정을 검사기가 잡는다(검사기 자체 시험). ③ 정지 제약을 더하면 최적 makespan 이 줄지 않는다.
- 현장에서 추가할 경계값 테스트 2개: `max_wait=0`(공정 사이 대기 불허 — 합성 데이터에서는 OPTIMAL, makespan 152→154 로 소폭 증가; 해가 없으면 INFEASIBLE 이 정직하게 나와야 한다), LOT 1개(해가 자명 = 장비별 최단 공정시간 합, 합성 66분).

### 손익 환산
- 공식: 회피 LOT 수 × LOT 당 손실. LOT 당 Q-Time 위반 손실 = 원가 기준 약 1.45억 ~ 기회비용 기준 약 8.6억원(추정; 25장/LOT 가정, 근거 참조). 병목 장비 정지 1시간 = 8.9억~14.3억원(추정, EUV 220 wph 원문 미확인).
- 예시(합성 데이터, 추정): 기준선 FIFO 의 위반 7건이 0건이 되고 그중 폐기·재작업이 되는 비율을 100% 로 보면 7 × 1.45 = 10.2억 ~ 7 × 8.6 = 60.2억원. 실제로는 위반 전부가 폐기는 아니므로 상한이다. 금액은 슬라이더로 두고 단정하지 않는다.
