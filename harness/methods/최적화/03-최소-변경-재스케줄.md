# 최소 변경 재스케줄 (Minimal-Change Rescheduling / Disruption Recovery)
> 장비 다운 같은 교란 뒤, 남은 일정의 makespan 과 "기존 일정에서 바뀐 LOT 수"를 함께 최소화하는 CP-SAT. 붙는 과제 유형: ② (보조 ①, ⑥ 설비 트립). 코드: `../code/minimal_change_reschedule.py`

## 바로 쓰는 칸
- **쓸 점**: 장비가 멈춘 뒤 makespan 과 바뀌는 LOT 수를 함께 줄이는 재스케줄을 λ 별 트레이드오프 표로 보인다.
- **필요한 컬럼**: `ops`(lot, step, machine, dur)와 현행 일정 `base`(lot, step, machine, start, end). 현행 일정이 없으면 못 쓴다.
- **한 줄 실행**: `python code/minimal_change_reschedule.py` (methods 폴더에서) — 합성 일정에 E2 정지를 주고 재풀이 해와 최소 변경 해 비교. (ortools 필요) 내 데이터로 쓸 때 부를 함수: `solve`, `disturb`
- **출력**: λ 별 표(상태, makespan, 변경LOT, 위반)와 재스케줄 일정, 기존/신규 간트에서 바뀐 LOT 강조.
- **하지 말 것**: 합성 수치(변경 14→4 LOT, +3분)를 효과 근거로 말하지 않는다 — 시간 제한 해라 실행마다 달라 방향만 믿는다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 강건·시나리오 계획 · 제약 프로그래밍 일정(처음부터 다시 풀기) — 교란이 이미 났고 현행 일정에서 바뀌는 LOT 수를 줄여야 하면 이 기법을 고르고, 교란 전에 여유를 만들어 두는 문제면 강건·시나리오 계획을, 현장 변경 비용이 0 에 가까우면 그냥 제약 프로그래밍 일정으로 다시 푸는 쪽이 더 단순하다.

## 이럴 때 꺼낸다
- 과제 문구: "장비가 멈췄다", "긴급 LOT 이 들어왔다", "기존 일정을 최대한 유지", "현장 혼란을 줄여라", "다시 짜면 다 바뀐다".
- 데이터 모양: 현행 일정표(LOT·공정·장비·시작) + 공정시간 표 + 교란 사건(장비·시각·길이). "지금 시각 이전에 이미 시작한 공정"을 구분할 수 있어야 한다.
- 꺼내지 말아야 할 때: 교란 **전에** 여유를 만들어 두는 문제(→ 강건·시나리오 계획 강건 최적화), 처음 짜는 일정(→ 제약 프로그래밍 일정), 변경 비용이 0 에 가까운 경우(그냥 다시 푼다).

## 입력 → 출력
| 입력 | 컬럼/키 | 의미 · 단위 |
|---|---|---|
| `ops`(LOT×공정×장비 후보) | `lot`, `step`, `machine`, `dur` | LOT id · 공정 번호 · 장비 후보 · 공정시간(분) |
| `base`(현행 일정) | `lot, step, machine, start, end` | `solve()` 결과 또는 현장 MES 일정 |
| 교란 | `disturb(base, "E2", t_now=100, length=120)` | 정지 장비 · 현재 시각 · 정지 길이(분) |
- 출력: λ 별 표(`상태, makespan, 변경LOT, 위반`) · 재스케줄 일정 DataFrame.
- → 실행 결과는 부록

## 핵심 개념 (5줄 이내 + 수식 1~2개)
- `min  makespan + λ · (변경 LOT 수)`. 변경 = LOT 의 어느 공정이든 **장비가 바뀌었거나 시작이 TOL(10분) 넘게 움직임**.
- 동결: `start < t_now` 인 공정은 그대로(이미 진행 중). 정지창은 그 장비의 진행 중 공정이 끝난 뒤부터.
- 모형 = 제약 프로그래밍 일정 유연 잡숍 + 공정별 `same` 불리언(같은 장비·시작 이동 ≤ TOL ⇒ same=1), `same=0 ⇒ changed_LOT=1`. 기존 일정은 `AddHint`.
- λ 는 "변경 LOT 1개를 makespan 몇 분과 맞바꾸는가". λ=0 이 처음부터 다시 푼 해, λ→∞ 가 최소 변경 해. λ 를 쓸어 트레이드오프 곡선을 그린다.

## 반도체 현장에서 (용도 2~3줄, 사례 수치는 출처와 함께)
- 장비 다운·긴급 LOT 투입 뒤 현행 일정에서 가장 적게 바꾸는 재배정(목적 = KPI + 변경 벌점). 근거 사례는 비반도체: Lufthansa/SWISS 의 운항 교란 복구 시스템이 SWISS 에서 €12M 절감·CO2 14,000t 감축(R4, 결선 발표 자기 신고, 방법 세부 미확인), American Airlines HEAT 는 결항 약 1,000편 방지(R2, 자기 신고).
- 그 수치는 시스템 전체 효과이지 "변경 최소화" 항 단독 효과가 아니다. 팹으로의 이식은 추론.

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론: CP-SAT 풀이, 동결·정지창 처리, pandas 로 변경 수 재집계, 위반 검사기.
- AI: 질문 → 파라미터. 예 1) "장비 E3 이 4시간 멈추면?" → `{down: {E3: [t_now, 240]}}`. 예 2) "현장이 변경 3건까지만 받아들인다" → λ 를 키우거나 `changed ≤ 3` 제약 추가.
- 설명 틀: "E2 가 ○분 멈춰, 처음부터 다시 짜면 makespan ○분이지만 ○개 LOT 의 장비·시각이 바뀝니다. 최소 변경안은 makespan ○분(+○분)에 바뀌는 LOT 가 ○개뿐입니다. 동결한 진행 중 공정 ○개는 그대로입니다."

## 화면 한 장
- 트레이드오프 선 그래프(가로 변경 LOT 수, 세로 makespan, 점 = λ) + 기존/신규 간트를 위아래로 두고 바뀐 LOT 만 강조색. 슬라이더로 λ 를 움직이면 간트가 바뀐다.

## 함정
- "변경"의 정의가 결과를 좌우한다(TOL, 장비 변경만 셀지). 정의를 화면에 적고 TOL 슬라이더를 둔다.
- 진행 중 공정 처리: 정지 장비의 진행 중 LOT 를 중단시킬지 마칠지는 현업 규칙이다. 코드는 "마친 뒤 정지"로 가정했다.
- 동결을 빼먹으면 이미 시작한 공정을 되돌리는 불가능한 해가 나온다 — 검사기의 동결 항이 이를 잡는다.
- λ 단조성 assert 는 OPTIMAL 상태에서만 성립한다. 시간 제한으로 FEASIBLE 이면 곡선이 들쭉날쭉할 수 있다.

## 한 문장 설명 · 예상 질문
- "장비가 멈췄을 때 가장 좋은 일정이 아니라, 현장이 가장 덜 흔들리면서 충분히 좋은 일정을 드립니다 — 흔들림 값을 슬라이더로 정하게 해서요."
- Q. 그냥 다시 풀면 더 빠른 일정 아닌가? → A. 맞다(실행 예 291분). 그 대신 14개 LOT 가 바뀐다. 표에서 +0~3분에 변경 4개인 최소 변경안을 같이 보여 주고 선택은 현업이 한다.
- Q. λ 는 어떻게 정하나? → A. 병목 장비를 건드리는지로 정한다(손익 환산 절). 기본값은 현업 확인이 필요한 가정이다.

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert 가 독립 재검사: ① 모든 λ 해가 `check()` 로 겹침·정지창 침범·선후·동결 공정 변경 위반 0건, 상태 OPTIMAL ② 변경 수를 솔버 변수와 무관하게 pandas 병합으로 재집계(`count_changes`) ③ λ 가 커질수록 변경 수 비증가·makespan 비감소(스칼라화 최적해의 단조성) ④ 교란이 없으면 최소 변경 해의 변경이 0 이고 makespan 이 기존과 같다 ⑤ 시작을 +1000 깨뜨린 일정을 검사기가 잡음.
- 현장 추가 경계 테스트: (a) 정지 길이 0 → 변경 0 (b) `t_now` 를 일정 끝 근처로 두어 거의 전부 동결 → 문제가 사실상 무자유, 상태와 변경 수가 정상인지.

### 합성 데이터 실행 결과
- 합성 실행(24 LOT, 식각 3대·CMP 2대, E2 가 113분부터 120분 정지, 동결 공정 20개): 처음부터 다시 푼 해(λ=0) makespan 291·**변경 14 LOT** / 최소 변경 해(λ≥5) makespan 294·**변경 4 LOT**, 전부 위반 0. 즉 makespan +3분으로 변경 LOT −10.
  - 기존 일정이 시간 제한 안에 최적 증명이 안 된 해라 수치가 실행마다 다르다 — 재실행에서는 289 대 289(+0분)·변경 14 → 4 였다.
  - 변경 LOT 가 크게 줄고 makespan 은 0~3분만 늘어난다는 방향만 믿는다.

### 손익 환산
- 공식: `λ(분) = 변경 1건 비용 ÷ makespan 1분의 가치`. 변경 1건 비용 = 재확인·재투입 시간 × 엔지니어 시간당 급여 약 8.9만원(1.85억원 ÷ 2,080시간, 복리후생 제외 추정; 15분/건은 알람 분류 예의 가정 차용). makespan 1분의 가치는 **병목이면** 병목 장비 1시간 8.9억~14.3억원(추정, 220 wph 원문 미확인) ÷ 60, 비병목이면 거의 0(TOC 논리, 추론).
- 예시(추정): 변경 1건 ≈ 0.25h × 8.9만 ≈ 2.2만원. 병목이면 1분 ≈ 1,480만~2,380만원이라 λ ≈ 0.0015분 — **병목 장비의 지연은 변경 건수보다 훨씬 비싸다**(그때는 λ=0 에 가깝다). 비병목이면 λ 가 커져 최소 변경이 정답. λ 를 정하는 것은 "그 장비가 병목이냐"다.
