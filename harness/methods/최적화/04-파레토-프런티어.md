# 파레토 프런티어 (Pareto Frontier, ε-constraint)
> 한 목표를 좋게 하면 다른 목표가 나빠지는 해들의 경계를 ε-제약 반복으로 그리고, 현행 운영 점이 그 안쪽인지 판정한다. 붙는 과제 유형: ② ⑥. 코드: `../code/pareto_frontier.py`

## 바로 쓰는 칸
- **쓸 점**: 처리량과 대기 LOT 위험의 경계(ε-제약)를 그려 현행 운영 점이 그 안쪽인지와 개선폭을 판정한다.
- **필요한 컬럼**: `lots`(lot, slots, throughput, qtime_risk)와 교대 용량 `cap`. LOT 별 점유 시간·처리량 점수가 없으면 못 쓴다.
- **한 줄 실행**: `python code/pareto_frontier.py` (methods 폴더에서) — 합성 LOT 24개 프런티어와 현행 점 지배 여부. (ortools 필요) 내 데이터로 쓸 때 부를 함수: `frontier`, `fifo_point`, `dominated_by`
- **출력**: 프런티어 점 목록(처리량·잔여위험·선택 LOT), 현행 점의 지배 여부와 같은 위험/같은 처리량의 개선폭.
- **하지 말 것**: 위험 점수를 확률처럼 원화 환산하지 않는다 — 상대 순위라 보정이 먼저. 합성 +19% 는 합성 데이터의 결과일 뿐이다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 민감도 분석 · 다기준 의사결정 — 목표가 둘이고 현업이 점을 직접 골라야 하면 이 기법을 고르고, 목표가 셋 이상으로 얽히면 2차원 그림이 안 되므로 가중치를 공개하는 다기준 의사결정을, 한 목표의 우선순위가 이미 정해져 있으면 그 목표 하나만 최적화하고 민감도 분석으로 가정을 흔든다.

## 이럴 때 꺼낸다
- 과제 문구: "트레이드오프", "처리량과 위험 사이", "에너지 절감 vs 온습도 여유", "어떤 점을 고를지 현업이 정하게", "두 KPI 를 동시에".
- 데이터 모양: 선택지(LOT·운전 설정)마다 KPI 두 개(처리량 점수, 위험 점수)와 자원 사용량.
- 꺼내지 말아야 할 때: KPI 가 셋 이상이고 서로 얽힐 때(2차원 그림으로 못 보여 줌 → 가중합이나 지배 개수), 현업이 이미 한 목표 우선순위를 정해 둔 경우(그냥 계층 최적화).

## 입력 → 출력
| 컬럼 (`lots` DataFrame) | 의미 | 단위 |
|---|---|---|
| `lot` | LOT 이름(행 순서 = 도착 순서 = 현행 FIFO) | - |
| `slots` | 장비 점유 시간 | 30분 단위 정수 |
| `throughput` | 돌리면 얻는 처리량 점수 | 정수 |
| `qtime_risk` | 이번 교대에 못 돌리고 대기시킬 때 Q-Time 위반 위험 점수 | 정수 1~20 |
- `CAP_SLOTS`(교대 용량) 인자. 목표1=처리량 최대, 목표2=대기 LOT 위험 합 최소.
- 출력: 프런티어 점 목록(처리량·잔여위험·선택 LOT), 현행 점의 지배 여부와 개선폭.
- → 실행 결과는 부록
- 현장에서 끼우기(`code/` 에서 `import pareto_frontier`):
```python
fr = frontier(lots, cap=48)
v, left = fifo_point(lots, 48); dominated_by(fr, v, left)   # 비어 있지 않으면 현행은 안쪽
```

## 핵심 개념 (5줄 이내 + 수식 1~2개)
- 점 A 가 점 B 를 지배: A 가 모든 목표에서 B 이상이고 하나는 엄격히 낫다. 어느 점에도 지배되지 않는 해들의 집합 = 파레토 프런티어.
- ε-제약: `max f₁(x)  s.t.  f₂(x) ≤ ε` 를 ε 를 조이며 반복한다. 정수 KPI 면 같은 f₁ 에서 f₂ 를 최소화하는 2차 풀이로 약지배 점을 걸러 내고, `ε ← f₂ − 1` 로 다음 점을 찾는다.
- 가중합과 달리 비볼록(오목한) 프런티어 점도 찾는다.
- 현행 점이 프런티어 안쪽이면 "같은 위험으로 더 많이, 또는 같은 처리량으로 덜 위험하게" 갈 수 있다는 증거.

## 반도체 현장에서 (용도 2~3줄, 사례 수치는 출처와 함께)
- 처리량 vs Q-Time 위험(②), 에너지 절감 vs 온습도 여유(⑥). 이 기법의 반도체 효과 수치는 출처가 없다(추론) — 아래 수치는 합성 실행값.
- 수상 사례들이 효과를 "선택지와 대가"로 말한 방식(Intel S1, Microsoft S20, 경계·민감도 S12)을 그림 한 장으로 옮기는 장치.

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론: CP-SAT 두 단계 풀이(처리량 최대 → 위험 최소) 반복. 프런티어 점마다 선택 LOT 이 나온다.
- AI: 질문 → 파라미터. 예 1) "교대 용량이 12시간으로 줄면?" → `{CAP_SLOTS: 24}`. 예 2) "위험을 150 이하로 묶으면 최대 처리량은?" → `{epsilon: 150}`(프런티어 표에서 바로 조회).
- 설명 틀: "현행은 처리량 ○, 위험 ○입니다. 같은 위험이면 처리량 ○까지(+○%), 같은 처리량이면 위험 ○까지(−○%) 갈 수 있는 점이 있습니다. 어느 점을 고를지는 현업이 정합니다."

## 화면 한 장
- 산점도: x=처리량, y=잔여 위험(작을수록 좋음). 프런티어 계단선 + 현행 점(빨강) + "같은 위험/같은 처리량" 점선 화살표. 점 클릭 시 해당 점의 LOT 선택 목록.

## 함정
- 목표 축의 방향을 헷갈리지 않는다(위험은 작을수록 좋다). 지배 판정 부호가 뒤집히면 프런티어가 틀린다.
- ε 반복에서 같은 처리량의 약지배 점이 섞이지 않게 2차 풀이로 위험을 최소화한다(코드가 수행).
- KPI 가 실수면 `ε ← f₂ − δ` 의 δ 를 정해야 하고, 너무 작으면 반복이 길어진다.
- 위험 점수는 상대 순위지 확률이 아니다. 원화 환산 전에 보정이 필요하다.

## 한 문장 설명 · 예상 질문
- "현행 운영은 이 곡선 안쪽에 있습니다 — 같은 위험으로 처리량을 19% 더 내는 점이 여기 있습니다(합성 데이터)."
- Q. 왜 가중합이 아니라 ε-제약인가? → A. 가중치를 미리 정하지 않아도 되고, 오목한 구간의 점도 찾는다. 가중치는 현업이 점을 고르는 것으로 대신한다.
- Q. 점이 14개뿐인가? → A. 정수 KPI 의 서로 다른 지배되지 않는 값 전부다. DP 전수 계산과 개수·값이 같다.

### 검증 (하드체크)
- 코드 끝 assert 가 독립 재검사: ① 2차원 배낭 DP(용량×커버 위험)로 가능한 모든 (처리량, 위험) 쌍을 전수 계산해 파레토 집합을 구하고 CP-SAT 프런티어와 집합 일치 ② 각 점의 선택 LOT 을 행렬곱으로 다시 세어 용량·처리량·위험이 보고값과 일치 ③ 처리량과 잔여위험이 모두 단조 감소.
- 현장 추가 경계 테스트: (a) 용량을 LOT 전체 합 이상으로 키우면 프런티어가 점 1개(전부 선택)가 되는지 (b) 용량 0 이면 처리량 0, 위험 합 전체인 점 1개인지.

### 합성 데이터 실행 결과
- 합성 실행: LOT 24개·48슬롯에서 프런티어 14점. 현행 FIFO(569, 위험 184)는 안쪽: 같은 위험에서 처리량 +19.0%(677), 같은 처리량에서 위험 −39.7%(111).

### 손익 환산
- 공식: 처리량 증분 → 웨이퍼 수 × 웨이퍼당 T (완전변동비 6.3%, 추정). 위험 감소 → 기대 위반 랏 수 감소 × 랏당 비용 1.45억(원가)~8.6억(기회비용)원 (추정, 25장/랏 가정).
- 예시(가정 위의 가정): 위험 점수가 1점당 위반 확률 0.1%p 라고 보정되면, 위험 184→111(73점) = 기대 위반 0.073랏/교대 × 8.6억 ≈ 0.63억원/교대. 보정 계수는 현업 값으로 교체하는 칸이며 화면에서는 슬라이더로 둔다.
