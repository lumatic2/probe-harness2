# LLM 질의→파라미터 (OptiGuide 패턴)
> 현업 질문을 LLM 이 솔버 입력 변경(파라미터 diff)으로 바꾸고, 솔버가 다시 계산한 전후 KPI 를 LLM 이 문장으로 설명한다. 데이터 원본은 LLM 에 보내지 않는다. 붙는 과제 유형: ①~⑥ 전부(제약 프로그래밍 일정~강건·시나리오 계획 화면의 앞단). 코드: `../code/llm_to_solver.py`

## 바로 쓰는 칸
- **쓸 점**: 현업 질문을 솔버 파라미터 diff 로 바꿔 재계산하고 전후 KPI 를 설명문으로 만든다. 데이터 원본은 LLM 에 보내지 않는다.
- **필요한 컬럼**: `lots`(lot, minutes, due, weight)와 파라미터로 재계산할 솔버 모형. 재계산할 솔버 모형이 없으면 못 쓴다.
- **한 줄 실행**: `python code/llm_to_solver.py` (methods 폴더에서) — 목 LLM 으로 합성 질문 → 파라미터 diff → 전후 KPI·설명문. (ortools 필요) 내 데이터로 쓸 때 부를 함수: `ask`, `solve`, `validate_diff`
- **출력**: 질문별 파라미터 diff 칩, 전후 KPI(총 지연·지연 LOT 수·종료 시각), 설명문, LLM 으로 나간 payload 로그.
- **하지 말 것**: LLM 이 숫자·수식을 만들게 하지 않는다(계산은 솔버). 민감 데이터를 질문에 붙이지 않고 `Gateway.ALLOWED` 로 나가는 값을 고정한다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 민감도 분석 · 정해 둔 질문 버튼(고정 what-if 슬라이더) — 이미 돌아가는 솔버가 있고 현업이 조건을 말로 바꿔 보게 해야 하면 이 기법을 고르고, 바꿀 조건이 몇 개로 정해져 있으면 슬라이더·버튼이 더 단순하고 틀릴 일이 없으며, 솔버 자체가 없으면 앞단만 만든 껍데기가 되므로 쓰지 않는다.

## 이럴 때 꺼낸다
- 과제 문구: "자연어로 질문하면", "AI 가 의사결정을 지원", "what-if", "설명 가능한", "현업이 직접 조건을 바꿔 보게".
- 데이터 모양: 이미 돌아가는 솔버/계산 함수 + 바꿀 수 있는 파라미터 목록(스키마). 결과가 KPI 몇 개로 요약되면 잘 맞는다.
- 꺼내지 말아야 할 때: 솔버가 아직 없을 때(앞단만 만들면 껍데기), LLM 이 수식 모형 자체를 새로 만들어야 하는 문제 — 산업 규모에서는 성능이 크게 떨어진다(S18). 모형은 사람이 검토해 고정한다.

## 입력 → 출력
| 입력 | 의미 | 단위 |
|---|---|---|
| `lots` DataFrame | `lot` LOT 이름 · `minutes` 처리시간(분) · `due` 납기(분) · `weight` 가중 | - |
| `PARAM_SCHEMA` | LLM 에 알려 주는 변경 가능 파라미터: `down {장비:[시작h,끝h]}` · `speed {장비:배율}` · `rush [LOT]` | h |
- 출력: 질문별 파라미터 diff, 전후 KPI(총 지연·지연 LOT 수·종료 시각·긴급 LOT 지연), 설명문, LLM 으로 나간 payload 기록.
- → 실행 결과는 부록
- 현장에서 끼우기(`code/` 에서 `import llm_to_solver`):
```python
gw = Gateway(lots)                                # 모든 LLM 입출력은 여기를 지난다
res, text = ask('장비 E3 이 4시간 멈추면?', lots, gw, solve(lots, BASE_PARAMS))
```

## 핵심 개념 (5줄 이내 + 수식 1~2개)
- 흐름: 질문 → (LLM) 파라미터 diff → 스키마 검증 → 솔버 재실행 → 전후 KPI → (LLM) 설명문. 계산과 판정은 솔버, 질문 해석과 문장화만 LLM.
- 개인 데이터 경계: LLM 에는 `질문 + 파라미터 스키마 + 장비 ID 목록` 과 `diff + 집계 KPI` 만 보낸다. LOT 이름·처리시간·납기 같은 행 값은 나가지 않는다(코드의 `Gateway`).
- 검증: LLM 이 낸 diff 는 스키마·범위·실재 여부로 걸러 낸다(`validate_diff`). 해석 못 한 질문은 "답을 지어내지 않는다".
- LLM 자리는 규칙 기반 목 함수(`mock_llm`·`mock_explain`)가 맡아 네트워크 없이 같은 흐름이 돈다. 실제 모델을 붙일 때는 `mock_llm` 과 같은 입출력(payload → 파라미터 diff)의 함수로 갈아 끼운다. 어느 쪽이든 입출력은 `Gateway` 를 지난다.

## 반도체 현장에서 (용도 2~3줄, 사례 수치는 출처와 함께)
- OptiGuide(S4)는 독점 데이터를 LLM 에 보내지 않는 설계로, what-if 는 LLM 이 솔버 입력을 고쳐 다시 푼다. 이 구조의 Microsoft IFS 가 2026 Edelman 을 받았고 이행팀 업무량 23% 감소·결정 주기 수일→수분이다(S20, 자사 신고, E2).
- "생산 데이터 원본 무접촉" 원칙과 그대로 연결: "AI 는 파라미터만 봅니다".

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론: 장비 4대 병렬 CP-SAT(겹침 금지·다운 구간 회피·가중 지연 최소), 스키마 검증, KPI 재계산, 유출 차단 게이트.
- AI: 질문 → diff. 예 1) "장비 E3 이 4시간 멈추면?" → `{down: {E3: [0,4]}}`. 예 2) "E2 속도가 40% 느려지면?" → `{speed: {E2: 0.6}}`. 목 LLM 은 정규식 규칙이고 실제 LLM 은 같은 payload 를 받아 JSON 만 내야 한다.
- 설명 틀(코드 `mock_explain`): "'<질문>' 조건(<diff>)으로 솔버를 다시 돌렸습니다. 총 지연 ○→○분(±○), 지연 LOT ○→○건, 종료 ○→○분."

## 화면 한 장
- 좌: 채팅 입력. 중앙: "바뀐 파라미터" diff 칩(예 `E3 down 0~4h`). 우: 전후 KPI 카드와 간트 두 장(전/후). 하단: 설명문. 설정 패널에 "LLM 에 나간 내용" 로그를 열어 보이게 하면 데이터 무접촉이 한눈에 증명된다.

## 함정
- 질문 문자열 자체에 LOT 이름 등 데이터가 있을 수 있다. 코드는 질문에 사용자가 직접 쓴 이름만 허용하지만, 민감 데이터를 질문에 붙여 넣지 않도록 화면에 안내한다.
- 집계 KPI 도 규정상 민감할 수 있다. 현업과 "무엇이 LLM 에 나가는지"를 먼저 합의하고 `Gateway.ALLOWED` 로 고정한다.
- 목 LLM 은 몇 개 문형만 안다. 시연에서 목이 모르는 문형이 나오면 거절 문구가 나오므로 질문 예시를 화면에 적어 둔다.
- 실제 모델로 갈아 끼운 함수는 이 코드로 시험하지 않았다. 그 함수는 같은 payload 를 받아 JSON diff 만 내야 하고, 낸 diff 는 `validate_diff` 가 거른다.

## 한 문장 설명 · 예상 질문
- "AI 가 답을 지어내지 않습니다 — AI 는 질문을 조건으로 바꾸고, 계산은 검증된 솔버가 합니다. 그리고 AI 에게 나간 내용은 이 로그가 전부입니다."
- Q. LLM 이 틀린 파라미터를 만들면? → A. 스키마·범위·실재 여부를 코드가 먼저 거르고, 통과한 diff 만 화면에 칩으로 보여 사람이 확인한다. 없는 장비·LOT 은 제거된다.
- Q. LLM 이 수식을 만들면 되지 않나? → A. 산업 규모 문제에서는 성능이 크게 떨어진다(S18). 모형은 고정하고 LLM 은 입력과 설명에만 쓴다. Microsoft 의 수상 구조와 같다(S20).

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert 가 독립 재검사: ① 솔버 변수를 쓰지 않고 스케줄만으로 모든 LOT 이 한 번씩, 장비 겹침·다운 구간 침범 없음, 소요시간=ceil(분/속도) 재계산, KPI 일치 ② 다운·감속에서 총 지연이 개선되지 않음(자원 감소의 단조성), 긴급 지정 LOT 지연이 늘지 않음 ③ LLM 으로 나간 payload 전부에 질문에 쓴 이름 외 LOT 이름 0건, 데이터 컬럼명 0건 ④ 유출 시도 payload 는 `Gateway` 가 차단 ⑤ 없는 장비·LOT 의 diff 는 제거.
- 현장 추가 경계 테스트: (a) 파라미터에 없는 질문("날씨는?")에 빈 diff 와 거절 문구가 나오는지 (b) 실제 모델로 갈아 끼운 함수가 JSON 이 아닌 응답을 냈을 때 멈추는지(현재 코드에는 그 경로가 없다 — 미시험).

### 합성 데이터 실행 결과
- 합성 실행: "E3 이 4시간 멈추면?" → `{down: {E3: [0, 4]}}` → 총 지연 74→232분. 가장 늦는 LOT 을 긴급으로 올리면 그 LOT 지연 67→0분, 총 지연 +27분.

### 손익 환산
- 공식: 절감 엔지니어 시간 = 질문 수 × (수작업 분석 시간 − 재계산 시간) × 시간당 급여 8.9만원 (1.85억원 ÷ 2,080시간, 복리후생 제외 추정). 현금이 줄어드는 것이 아니라 다른 일로 옮겨 가는 시간이다(활동기준원가 계산의 단서).
- 예시(추정): 하루 10건 × (30분→1분) ≈ 4.8h/일 × 365 × 8.9만원 ≈ 연 1.6억원. 질문 수·시간은 가정이다. 수상 사례의 "결정 주기 수일→수분"(S20)과 같은 방향의 주장이며 우리 수치는 아니다.
