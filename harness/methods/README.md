# 방법론 지도 — 문제를 보고 꺼내 쓰는 경영과학 선반

> 과제 유형이 정해졌으면 접근법 선반의 [경로 카드](../approaches/경로-카드.md) `뼈대 — 계산` 줄을 따른다(정본). 이 파일은 카드에 없는 기법을 찾을 때 쓴다 — §2 신호 표부터.
> 기법 문서 맨 위 `## 바로 쓰는 칸`(필요한 컬럼 · 한 줄 실행 · 출력 · 하지 말 것)만 먼저 읽고 본문을 열지 정한다. 그 칸 맨 끝의 「대신 쓸 수 있었던 것 / 안 쓴 이유」 한 줄은 서술형 「왜 이 기법을 골랐나, 대안은」 답의 재료다(조건부로 쓴 것이니 내 데이터에 맞는지 확인해 옮긴다).
> 과제를 읽고 맞는 기법을 고른다. 원칙: **결정론 계산은 솔버·코드가, 질문을 파라미터로 바꾸는 일과 결과 설명은 AI 가.**
> 각 문서는 같은 틀(이럴 때 꺼낸다 · 핵심 개념 · 반도체 현장에서 · 입력→출력 · 솔버/AI 경계 · 하드체크 · 화면 한 장 · 손익 환산 · 한 문장 설명 · 함정 · 근거)이다.
> 코드는 `code/*.py`(대기행렬과 운영 곡선 는 실행 위치에 `operating_curve.csv` 를 쓴다) — 이 폴더(`methods/`)에서 합성 데이터로 `python code/<이름>.py` 한 줄에 돌고, 끝의 독립 하드체크가 통과해야 `HARD CHECK OK`(신뢰성과 보전 주기~다기준 의사결정 은 `하드체크 통과`)가 찍힌다. 실행 검증 2026-11-10(Windows): ortools·simpy·highspy 를 쓰지 않는 코드 24개 전부 종료코드 0, 각 40초 이내. 데이터만 바꿔 끼우게 함수로 나뉘어 있다(입력 컬럼은 각 문서 「입력 → 출력」).
> 의존성 `requirements.txt`(numpy·scipy·pandas·ortools·simpy·highspy·pm4py·scikit-learn). 원천: 경영과학·OR 트렌드와 반도체 적용 사례 조사(기법 16개), OR 수상사례 방법론 추가 조사(최소 변경 재스케줄~계측 샘플 배분), 손익 칸은 재무 환산 근거 수치 조사.
> 설치는 `pip install -r requirements.txt`. 무거운 것은 `ortools`(`cpsat_jobshop`·`llm_to_solver`·`minimal_change_reschedule`·`pareto_frontier`·`robust_scenario` 가 필요)와 `pm4py`(어느 코드도 import 하지 않는다 — 적합도 비교용). `simpy` 는 `dispatch_simulation.py`, `highspy` 는 `lp_mip.py`, scikit-learn 은 `anomaly_score_eval`·`imbalanced_eval`·`leakage_split_check`·`event_label_builder`(마지막은 하드체크의 AUC 만)가 쓴다.
> 나머지 코드 20개는 numpy·scipy·pandas(와 표준 라이브러리)만으로 돈다. 같은 대응 목록이 `requirements.txt` 맨 위 주석에 있다.

## 5. 쓸 때 지킬 것

- 문서의 합성 수치·원화 예시는 **가정**이다. 현장 데이터로 다시 돌린 숫자만 README·제출물에 쓴다. 원화는 하한(원가 기준)과 상한(기회비용 기준)을 같이 보인다.
- 하드체크는 지우지 않는다. 데이터를 바꿔 끼운 뒤에도 통과 문구가 나와야 "위반 0건" 같은 주장을 쓸 수 있다.
- CP-SAT 에 시간 제한이 걸린 코드(제약 프로그래밍 일정·최소 변경 재스케줄)는 실행마다 수치가 조금 다르다. 방향만 말하고, 제출물에 쓰는 숫자는 마지막 실행 값으로 고정한다.
- 기법 하나로 끝내지 않는다 — 주 무기 1개 + 민감도 분석(가정이 틀리면?) + 질문을 파라미터로(질문→조건) 조합이 기본형이다.

## 6. 도메인 킥(회계·재무·경영)을 거는 곳

장표 한 장이 아니라 **판정 기준 자체**에 넣는다 — 모든 결과를 원화·위험으로 판정한다.

| 어디서 | 킥 | 붙는 기법 |
|---|---|---|
| 임팩트 | 「시간 X% 절감」에서 멈추지 않고 원화 하한(원가 기준)·상한(기회비용 기준)을 가른다. 하한만 확정치로 말한다(보수주의). 기준 수치는 DART | 모든 문서의 「손익 환산」 칸 |
| 문제 정의 | 「누가 무슨 결정을, 틀리면 얼마」로 정의. Q-Time·WIP 문제에 재공품(운전자본)이 묶인다는 관점 | 제약 프로그래밍 일정 · 디스패칭 규칙 시뮬레이션 · 재고 정책 |
| 우선순위·판정 | 빈도가 아니라 **금액 중요성**으로 정렬. 오경보/놓침을 감사의 1종·2종 위험처럼 비용으로 맞바꾼다 | 관리도와 오경보 주기 · 기대손실 결정표 · 다기준 의사결정 |
| 계측 샘플링 | 감사 표본추출과 같은 구조 — 위험 높은 군에 표본을 더 준다 | 계측 샘플 배분 · 공정능력 |
| 병목·제품 믹스 | 처리량 회계: 원가 배분이 아니라 병목 1시간당 공헌이익. 쌍대가격 = 자원 1단위의 가치 | 병목 분석 · 선형·정수계획 |
| 현장 적용 | 원본 무접촉·읽기 전용·감사 로그·사람 승인을 내부통제(ITGC) 언어로 설명 | 킷 데이터 층 |
| 서술형 답·질문 대비 | 「ROI 는?」「가정이 틀리면?」에 손익분기 가정·민감도·EVPI(더 알아볼 가치)를 원화로 답한다 | 민감도 분석 · 기대손실 결정표 |
