# SPC 관리도 + WECO 규칙 + ARL (Control Chart, Western Electric Rules, Average Run Length)
> 3σ 관리한계와 패턴 규칙으로 이상 신호를 내고, 평균 런 길이(ARL)로 "관리 상태에서 오경보가 몇 점마다 나는가"를 잰다. 붙는 과제 유형: ④ (①의 이상 감지 앞단). 코드: `../code/spc_weco_arl.py`

## 바로 쓰는 칸
- **쓸 점**: 3σ 한계와 WECO 규칙으로 이상 신호를 내고, 규칙을 켤 때 정상 상태 오경보가 몇 점마다 나는지(ARL) 같이 보인다.
- **필요한 컬럼**: `time`, `value` 시계열 한 변수와 기준선 점 수 `baseline_n`. 사람이 확인한 정상 기준선 구간이 없으면 못 쓴다.
- **한 줄 실행**: `python code/spc_weco_arl.py` (methods 폴더에서) — 합성 240점 시계열의 R1~R4 신호와 시뮬레이션 ARL 을 출력. 내 데이터로 쓸 때 부를 함수: `spc_chart`, `simulate_arl`
- **출력**: 점별 z·R1~R4 플래그·alarm, 한계값, 규칙별 첫 신호, 「정상에서도 ○점마다 1번 오경보」.
- **하지 말 것**: ARL 371/92 를 실제 알람 주기로 단정하지 않는다 — 독립·정규·σ 참값 가정이다. 기준선에 이상 구간을 섞지 않는다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: EWMA·CUSUM 관리도, [라벨이 없을 때 이상 점수](../판정-모델/05-라벨이-없을-때-이상-점수와-그-평가.md) — 사람이 확인한 정상 기준선이 있고 규칙을 켤 때 오경보가 몇 점마다 나는지를 숫자로 보여야 해서 3σ·WECO 를 골랐고, 값이 심하게 자기상관이거나 다변량이 핵심이면 잔차 관리도·다변량 기법이 먼저다.

## 이럴 때 꺼낸다
- 과제 문구: "알람이 너무 많다", "오경보", "FDC/SPC 알람 판정", "이상 징후를 일찍 잡아라", "관리한계", "알람 우선순위".
- 데이터 모양: 시간순 센서·계측값 1열(+장비·레시피 컬럼) / 정상 기간이 앞쪽에 있는 로그 / 알람 로그와 실제 이상 라벨.
- 꺼내지 말아야 할 때: 값이 심하게 자기상관(느린 센서)이거나 다변량 상관이 핵심일 때(→ 잔차 관리도·다변량 기법이 먼저, 아래 함정). 규격 만족 여부가 질문이면 공정능력.

## 입력 → 출력
| 컬럼 | 의미 | 단위 |
|---|---|---|
| `time` | 측정 시각 또는 순서 | 시각/정수 |
| `value` | 측정값(개별값) | 변수 단위 |
| `baseline_n` (인자) | 기준선(관리 상태로 보는) 앞쪽 점 수 | 개 |

- → 실행 결과는 부록
- 실행: `python code/spc_weco_arl.py` (numpy·scipy·pandas, 약 8초). 현장에서 바꿔 끼우는 곳: `spc_chart(df, baseline_n)` 에 실제 시계열, `simulate_arl(rules)` 에 켤 규칙 조합.
- 장비·변수가 여러 개면 `groupby` 로 변수마다 `spc_chart` 를 돌리고 알람 표를 이어 붙인다(다기준 의사결정 우선순위 입력).

## 핵심 개념 (5줄 이내 + 수식 1~2개)
- 개별값 관리도: 기준선 구간의 중심 `μ`, 산포 `σ = MR̄/1.128`(이동범위 평균), 관리한계 `μ ± 3σ`. 관리한계는 공정의 목소리이고 규격한계(고객 요구)와 다르다.
- WECO 4규칙: R1 3σ 밖 1점 · R2 2σ 밖 2/3점(같은 쪽) · R3 1σ 밖 4/5점(같은 쪽) · R4 중심선 한쪽 연속 8점.
- ARL₀ = 관리 상태에서 첫 오경보까지 평균 점 수. 3σ 단독이면 `1/(2·(1−Φ(3))) ≈ 370.4`. 규칙을 더하면 작은 이동은 빨리 잡지만 ARL₀ 가 줄어든다.

## 반도체 현장에서 (용도 2~3줄, 사례 수치는 출처와 함께)
- 챔버 압력·온도·RF 파워 같은 FDC 변수의 알람 판정. 규칙을 켜는 만큼 오경보가 늘기 때문에 "알람에 우선순위가 필요한 이유"를 정량으로 말할 수 있다(다기준 의사결정 TOPSIS 로 이어짐).
- NIST 핸드북(S17): 3σ 단독 ARL 371, 4규칙 전부 추가 시 약 91.75 (E2). 이 코드는 이를 시뮬레이션으로 근사 재현한다.

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론: 이동범위 σ 추정, 4규칙 판정(누적합 창 연산), ARL 몬테카를로(관리 상태 N(0,1) 2만 번).
- AI: 질문을 규칙 선택·기준선으로 바꾼다. 예 1) "R3 는 끄고 보면?" → `rules=("R1","R2","R4")` 로 ARL 재계산. 예 2) "정비 직후 40점만 기준으로 하면?" → `{baseline_n: 40}`.
- 설명 틀: "기준선 ○점으로 중심 ○, 관리한계 ○~○. 시각 ○에서 R○(규칙명)이 처음 울렸고 ○점 연속입니다. 규칙을 모두 켠 상태의 정상 오경보는 약 ○점마다 1번이라, 이 신호는 ○번째 오경보 주기에 해당합니다."

## 화면 한 장
- 시계열 관리도: 중심선·±1/2/3σ 띠, 점은 규칙별 색(R1 빨강·R2 주황·R3 노랑·R4 파랑), 우상단 카운터 "정상 상태에서도 약 92점마다 오경보" + 규칙 on/off 토글(토글하면 ARL 값이 바뀜).

## 함정
- ARL 371/92 는 독립·정규·σ 가 참값일 때의 수치다. σ 를 짧은 기준선에서 추정하거나 자기상관이 있으면 오경보가 더 잦다.
- 규칙을 켜는 대로 감도와 오경보가 함께 는다. 어느 쪽이 중요한지(미검출 비용 vs 알람 피로)를 기대손실 결정표 로 정한다.
- 관리한계를 규격한계로 오해하지 않는다(공정능력). 관리 이탈이 곧 불량이 아니다.
- 기준선에 이상 구간이 섞이면 σ 가 부풀어 한계가 넓어진다 — 기준선은 사람이 확인한 정상 구간으로.

## 한 문장 설명 · 예상 질문
- "규칙을 다 켜면 오경보가 371점마다 1번에서 약 92점마다 1번으로 늘어납니다 — 그래서 알람에 우선순위가 필요합니다."
- Q. 왜 3σ 만 쓰지 않나? A. 3σ 단독은 1σ 안팎의 작은 이동을 늦게 잡습니다. 합성에서 R3 가 R1 보다 8점 먼저 울렸습니다(R3 104번째, R1 112번째). 대신 오경보 대가를 ARL 로 보입니다.
- Q. 오경보 주기가 실제 데이터에도 맞나? A. 독립·정규 가정의 값이라 실제 FDC 는 더 자주 울릴 수 있어, 자기상관은 잔차로 바꿔 쓰고 실제 알람 로그로 재측정하는 칸을 둡니다(추론).

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert: ① 벡터화 규칙 판정을 순수 파이썬 루프 구현과 점별로 비교 ② 3σ 이론 ARL 370.4 ③ R1 단독 시뮬 ARL 이 이론의 4SE 안 ④ 4규칙 합 시뮬 ARL 이 91.75 ±(4SE+1) 안(NIST 근사 재현) ⑤ 4규칙 ARL < R1 ARL/3 ⑥ 심어 둔 이동(100~140)·스파이크(170)를 잡음.
- 현장 추가 경계 테스트: (a) 정확히 ±3.0σ 값이 `>` 로 신호가 아닌지(경계 포함 여부 합의) (b) 앞 7점 한쪽 + 8번째 중심선 위 값 → R4 미발생.

### 합성 데이터 실행 결과
- 합성 실행 결과(240점, 기준선 60점): 알람 49점 중 R1 단독은 10점. ARL₀ 시뮬 R1 단독 376.7±5.9(이론 370.4), 4규칙 합 92.29±0.63(NIST 약 91.75).

### 손익 환산
- 알람 처리 시간 = 알람 수 × 건당 처리시간 × 엔지니어 시급 (활동기준원가 환산: 하루 200건·15분·시급 8.9만원 가정 → 연 16.2억원, 오경보 60% 제거 시 시간 기준 연 9.7억원, 추정. 시급은 사업보고서의 직원 1인 평균급여 1.85억원을 연 2,080시간으로 나눈 값). 이 돈은 현금 절감이 아니라 다른 일로 옮겨 가는 엔지니어 시간이다.
- 예: 정상 상태 오경보 간격이 371점→92점이 되면 같은 센서 알람 건수는 약 4.0배(371/92) — 이 증가분 × 건당 15분이 규칙 추가의 숨은 비용(추정).
