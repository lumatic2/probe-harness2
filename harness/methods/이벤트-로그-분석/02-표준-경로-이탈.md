# 표준 경로 이탈 찾기 (Route Variants, Conformance Checking)
> 로트가 실제로 지난 공정 순서를 경로 변형으로 묶어 빈도를 세고, 제품별 표준 라우트와 대조해 적합도와 이탈 유형을 뽑는다. 이탈 로트와 정상 로트의 결과 지표 차이는 상관이지 원인이 아님을 층화로 보인다. 붙는 과제 유형: ③ ⑤ (② 대기 구간은 01). 코드: `../code/route_conformance.py`
> 접근법 선반: [프로세스 마이닝](../../approaches/회계학/회계감사/02-프로세스-마이닝.md) · [흐름·생산 관점](../../approaches/반도체-현장/흐름-설비-계획/01-흐름-생산.md)

## 바로 쓰는 칸
- **쓸 점**: 로트가 실제로 지난 공정 순서를 경로 변형으로 세어 제품별 표준 라우트와 대조하고 적합도·이탈 유형을 뽑는다.
- **필요한 컬럼**: `lot_hist`(`lot_id, step, track_in`)·제품별 표준 라우트·`outcome`(`lot_id, product, yield_pct, ct_h`) — 로트별 스텝 이력이 없으면 못 쓴다.
- **한 줄 실행**: `python code/route_conformance.py` (methods 폴더에서) — 합성 로트 600개로 이탈 26건·층화 비교. 내 데이터로 쓸 때 부를 함수: `conformance_table`, `outcome_compare`
- **출력**: 제품별 경로 변형 빈도표, 로트별 적합도·이탈 유형·빠진/더 나온 step, 이탈 대 정상 수율 차이(단순/제품 층화) 두 줄.
- **하지 말 것**: 이탈 로트의 수율 차이를 원인으로 말하지 않는다 — 단순 차이는 제품 구성이 만든 상관이니 층화한 값과 함께 보인다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: pm4py 적합도 · 표준 다음 스텝 표만 비교하는 전이 점검 — 로트별 스텝 이력과 제품별 표준 라우트가 있어 이탈 목록을 뽑을 때 이 코드의 적합도를 쓰고, 모델 발견이 필요한 큰 로그는 pm4py 를 쓰되 값의 정의가 달라 서로 바꿔 인용하지 않으며, 전이 점검만으로는 통째 생략을 놓친다.

## 이럴 때 꺼낸다
- 과제 문구: "표준 라우트 이탈", "재작업 루프", "공정 순서 위반", "규정 대조", "이탈 로트의 수율 차이", "절차를 건너뛴 로트".
- 데이터 모양: 로트별 공정 스텝 이력(로트·step·시각, 장비는 있으면 좋다) + 제품별 표준 라우트 표 + 로트 결과(수율·사이클타임).
- 꺼내지 말아야 할 때: 로트별 스텝 이력이 없으면 못 쓴다. 이탈의 원인을 말해야 하면 이 문서만으로는 안 된다(상관만 준다 — 아래 함정). 대기 구간 자체가 질문이면 로트 이력 구간 대기.

## 입력 → 출력
컬럼 대응표

| 데이터 | 이 코드 컬럼 | 원천의 이름 | 비고 |
|---|---|---|---|
| 로트 이력 `lot_hist` | `lot_id, step, track_in` (+`eqp_id`) | `case_id(lot), activity(step), resource(eqp), timestamp` | 순서는 `track_in` 으로 만든다. 같은 시각이면 입력 순서 유지 |
| 표준 라우트 `std` | `{product: [step, ...]}` (표로는 `product, seq_no, step`) | 「표준 모형 = 제품별 표준 라우트」 | 재진입이면 같은 이름이 여러 번. 공정 엔지니어가 확인한 버전이어야 한다 |
| 제품 마스터 | `lot_id, product` | (원천에 없음, 추론) | 로트 → 제품 매핑이 있어야 표준 라우트를 붙인다 |
| 로트 결과 `outcome` | `lot_id, product, yield_pct, ct_h` | 지표: 이탈 경로별 수율·사이클타임 차이 | 수율 열 이름은 `unique()` 로 확인 |

조인 키

| 무엇과 무엇 | 키 | 방법 |
|---|---|---|
| 이력 → 제품 | `lot_id` | 제품 마스터 병합 |
| 제품 → 표준 라우트 | `product` | 사전 조회 |
| 이력 ↔ 결과 | `lot_id` | 이탈 여부를 결과 표에 붙여 비교 |
| 이탈 ↔ 대기 구간(선택) | `lot_id` + `(from_step, to_step)` | 로트 이력 구간 대기의 구간 표와 병합 |

- 절차: ① `lot_variants` 로 로트별 step 튜플 → ② `variant_table`(제품별 빈도·누적 비중·표준 여부) → ③ `conformance_table`(로트별 적합도·이탈 유형·빠진 step·더 나온 step) → ④ `transition_table`(표준에 없는 전이 빈도) → ⑤ `outcome_compare`(단순 차이와 제품 층화 차이).
- → 실행 결과는 부록
- 실행: `python code/route_conformance.py` (numpy·pandas, 수 초). 현장에서 바꿔 끼우는 곳: `STD`(표준 라우트 사전), `lot_variants(h)` 에 실제 이력, `outcome_compare(conf, outcome, col)` 의 `col`.

## 핵심 개념 (5줄 이내 + 수식 1~2개)
- 경로 변형(variant) = 한 로트의 step 순서 전체(튜플). 같은 순서끼리 세어 빈도·누적 비중을 낸다. 이탈은 표준 순서와 다른 변형이다. 전수 로그라 표본 오차가 없다(원천 핵심 논리).
- 적합도(이 코드의 단순 정의, 추론): `fitness = 1 − (|실제| + |표준| − 2·LCS) / (|실제| + |표준|)`, LCS 는 최장 공통 부분수열. 완전 일치면 1. pm4py 의 정렬·토큰 재생 적합도와는 **다른 값**이다.
- 이탈 유형(규칙 기반, 추론): 생략(표준 step 이 빠짐) · 재방문(표준 step 이 더 나옴) · 미등록 step · 순서 바뀜 · 복합.
- 전이 점검: 표준 라우트의 인접 쌍 집합에 없는 전이를 가진 로트를 후보로 잡는다. 빠르지만 인접 쌍이 모두 합법인 통째 생략은 못 본다.

## 반도체 현장에서 (용도 2~3줄, 사례 수치는 원천 출처와 함께)
- 원천의 하이닉스 적용 예(추론): (a) 표준 라우트를 벗어난 로트 비율과 그 로트의 수율 차이(유형 ③), (c) 규정 대조 과제의 절차 순서 위반 전수 탐지(유형 ⑤). 반도체 사례는 스위스 OST 대학·Intellion 의 Fab Analytic Miner 데모뿐이며 학생 프로젝트 초록이라 성과 수치가 없다(E4) — 성과 사례로 말하지 않는다.
- 반론 「재진입 공정이라 그래프가 스파게티가 된다」에는 원천의 답을 따른다: 제품 1개·구간 1개(예: 포토→식각 루프)로 좁힌다. 코드에서는 로트 이력과 표준 라우트를 같은 step 구간으로 잘라 넣으면 된다.
- 원천의 6시간 최소 형태: pm4py 귀납 마이너 적합도(pm4py 는 `requirements.txt` 에 있지만 설치가 무겁다) 또는 pandas 로 표준 다음 스텝 표와 실제 전이를 비교하는 규칙 기반 적합도. 이 코드는 후자다.

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론: 변형 집계, LCS 적합도, 이탈 유형 규칙, 전이 점검, 층화 비교(부트스트랩만 시드 고정 난수).
- AI: 질문을 구간·제품 필터로 바꾼다. 예 1) "포토→식각 루프만 보면?" → 이력과 `STD[p]` 를 같은 step 구간으로 잘라 재실행. 예 2) "재방문은 허용 루프로 보자" → 표준 라우트에 그 루프를 넣거나 전이 허용 쌍에 추가. 이탈 유형 이름을 현업 용어(재작업·스킵)로 바꿔 설명한다.
- 설명 틀: "제품 ○의 표준 라우트(○스텝)와 정확히 같은 로트는 ○%, 이탈 ○로트의 주된 유형은 ○(○건)이고 평균 적합도는 ○입니다. 이탈 로트의 수율은 정상보다 ○%p 낮지만, 제품으로 나눠 보면 ○%p 이므로 이탈이 원인이라고 말할 수 없습니다."

## 화면 한 장
- 제품별 경로 변형 막대(많은 순, 표준은 파랑·이탈은 빨강)와 누적 비중 선. 옆에 이탈 로트 표(적합도·유형·빠진/더 나온 step)와, 이탈 vs 정상 수율 비교 두 줄(단순 / 제품 층화)에 「상관이며 원인 아님」 배지.

## 함정
- 이탈 로트와 결과 지표의 차이는 **상관**이다. 이탈이 특정 제품·장비·기간에 몰려 있으면 그것이 수율을 설명한다. 층화는 관측된 층만 맞춘다 — 보이지 않는 요인은 남는다. 원인을 말하려면 실험·현업 검증이 따로 필요하다(실험 설계는 이 모듈 범위 밖).
- 표준 라우트가 틀리거나 구버전이면 정상이 이탈로 나온다. 제품·레시피 버전을 확인한다.
- 정상 재작업 루프는 표준 모형에 넣지 않으면 모두 이탈이다. 허용 범위를 현업과 정한다.
- 인접 쌍 점검(전이)은 통째 생략·블록 순서 변경을 놓친다. LCS 적합도와 같이 쓴다.
- 적합도 숫자는 정의에 의존한다. 이 코드의 값을 pm4py 값처럼 인용하지 않는다.
- 로그 누락과 실제 생략을 구분하지 못한다. 전수라는 말은 로그가 모집단일 때만 성립한다(추론).
- OST 데모를 성과 사례로 말하지 않는다(원천).

## 한 문장 설명 · 예상 질문
- "표본이 아니라 로그 전수를 표준 라우트에 대 보고, 어느 로트가 어떻게 벗어났는지 목록으로 드립니다. 수율이 낮다는 말은 제품을 나눠 보기 전까지 원인으로 주장하지 않습니다."
- Q. 이탈이 수율을 깎는 것 아닌가? A. 합성에서 효과 0 으로 심었는데도 단순 비교는 −3.8%p 가 나왔다 — 그래서 층화한 값과 같이 보이고, 원인 판정은 실험·현업 확인의 몫이다(방법 시연).
- Q. pm4py 쓰나? A. 설치가 무거워 규칙 기반 적합도로 시작하고, 시간이 되면 pm4py 적합도와 나란히 놓는다. 두 값은 정의가 달라 서로 바꿔 인용하지 않는다.

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert:
  - ① 심어 둔 이탈 26로트를 전부, 과검출 없이 찾고 유형도 일치
  - ② 손계산 적합도 일치 — 제품 A(표준 11): 생략 20/21 · 재방문 22/23 · 순서 바뀜 10/11 · 미등록 22/23 · 층 통째 생략 12/17, 제품 B(표준 6): 10/11 · 12/13 · 5/6 · 12/13
  - ③ LCS 적합도 == 삽입·삭제 편집거리(재귀, 다른 알고리즘)로 다시 계산한 값, 전 로트
  - ④ 전이 점검은 인접 쌍이 모두 합법인 층 통째 생략 2건을 놓치고 나머지 24건은 모두 잡는다(알려진 한계를 단언으로 고정)
  - ⑤ 변형 로트 수 합 = 전체, 제품별 1위 변형 = 표준
  - ⑥ 이탈 효과 0 으로 심었는데 단순 비교 구간은 0 을 포함하지 않고(속는다), 층화 차이는 3SE 안에 들어온다.
- 현장 추가 경계 테스트: (a) 같은 시각 두 이벤트의 순서가 결과를 바꾸지 않는지 (b) 표준 라우트에 허용 루프(정상 재작업)를 넣었을 때 이탈 수가 줄어드는지 (c) 로그 누락(step 이 한 행 빠짐)과 실제 생략을 어떻게 구분할지 현업에 묻기.

### 합성 데이터 실행 결과
- 합성 결과(로트 600개·제품 A 11스텝 2층 재진입·B 6스텝, 방법 시연): 경로 변형 11종, 정상 574·이탈 26. 이탈 유형별 로트 수·평균 적합도: 생략 8(0.898)·재방문 6(0.929)·순서 바뀜 6(0.846)·미등록 step 6(0.929). 표준에 없는 전이 상위: B 의 ETCH→DEP 10건 등. 이탈이 B 에 몰려 있고 수율은 제품이 정한다(A 90·B 80, 이탈 자체의 효과는 0 으로 심음).
- 같은 이탈 로트를 두 방식으로 비교: 수율 단순 차이 −3.84%p(95% 부트스트랩 −5.61~−1.94), 제품으로 층화한 차이 +0.34%p(SE 0.47). 단순 비교는 「이탈하면 수율이 낮다」로 읽히지만 제품 구성이 만든 것이다.

### 손익 환산
- 이탈의 값은 (이탈 로트 수 × 결과 차이) 가 아니라 **원인이 확인된 뒤** 정해진다. 층화 후 차이가 0 근처면 이탈 자체의 비용은 여기서 환산하지 않는다. 재작업 루프가 장비 시간을 쓰는 비용은 재처리 횟수 × 장비 시간 × 시간당 가치(현업 입력) — 단가는 근거 없음.
- 사이클타임은 step 수가 달라 단순 차이가 제품 구성에 지배된다(합성 단순 −22.9h 대 층화 −0.9h). 사이클타임 쪽 환산은 로트 이력 구간 대기의 리틀 환산을 쓴다.
