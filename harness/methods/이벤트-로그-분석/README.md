## 핵심 개념어
- **이벤트 로그**: (사건 id, 활동, 자원, 시각) 행. 원천 가정 변환: 사건 = 로트 · 활동 = 공정 스텝 · 자원 = 장비.
- **구간(segment)**: 한 로트의 이웃한 두 이벤트 사이. 구간 대기 = 뒤 시작 − 앞 끝.
- **Q-time**: 앞 공정을 끝낸 뒤 정해진 시간 안에 뒤 공정을 시작해야 하는 제약. 위반하면 앞 공정부터 다시 한다(원천).
- **경로 변형**: 한 로트가 지난 step 순서 전체. **적합도**: 표준 순서와의 일치도(정의에 따라 값이 다르다).
- **상태 시간**: 생산·대기·엔지니어링·계획 정지·비계획 정지·Non-scheduled. 가용도 4종은 분자·분모 선택이 다르다.
- **사건(episode)**: 시간·장비로 묶은 알람 무리. **떨림·홍수·stale**: 알람 건강 지표.
- **리틀의 법칙**: 평균 재공 = 처리율 × 평균 체류시간.

## 관점 쌍
- **정의 ↔ 숫자**: 같은 이름의 지표도 분자·분모·시작·끝 정의가 다르면 값이 다르다. 숫자를 비교하기 전에 정의를 묻는다([장비 상태 이력 가용도](03-장비-상태-이력-가용도.md)).
- **전수 ↔ 로그 품질**: 로그가 모집단이면 표본 오차가 없지만 누락·시계 불일치는 그대로 숫자에 들어온다. 리틀 검산·겹침·빈틈 점검이 먼저다([로트 이력 구간 대기](01-로트-이력-구간-대기.md)).
- **겹침 ↔ 원인**: 같은 시각에 같은 장비가 서 있었다는 것은 후보이지 인과가 아니다. 이탈과 수율의 차이도 층화 전에는 상관이다([표준 경로 이탈](02-표준-경로-이탈.md)).
- **묶음 ↔ 원인 제거**: 사건으로 묶으면 건수가 준다. 알람이 울리는 이유는 그대로다([알람을 사건으로 묶기](04-알람을-사건으로-묶기.md)).

## 이 분야 사람이 먼저 묻는 것 5
1. 이 시각은 무엇의 시각인가(도착·투입·종료·기록)? 시스템마다 시계가 같은가?
2. 한 행이 무엇인가(한 번의 공정 처리? 상태 변화? 알람 켜짐)? 같은 사건이 여러 행으로 쪼개져 있나?
3. 로그가 모집단인가, 누락이 있나? 별도 출처(WIP, 합계)와 맞춰 봤나?
4. 이 숫자의 분자·분모 정의는 누구의 정의인가?
5. 겹쳐 보이는 두 가지 중 어느 쪽이 원인인지를 무엇으로 가렸나?

## 흔한 함정
- 정의 확인 없이 팀 간 숫자를 비교한다(가용도 4종, 대기의 시작·끝)([장비 상태 이력 가용도](03-장비-상태-이력-가용도.md)).
- 시각 정렬·시간대·같은 시각 이벤트의 순서를 점검하지 않는다([로트 이력 구간 대기](01-로트-이력-구간-대기.md)).
- 재진입 공정에서 step 이름만으로 규칙·재작업을 붙인다([로트 이력 구간 대기](01-로트-이력-구간-대기.md)).
- 이탈 로트의 수율 차이를 원인으로 말한다([표준 경로 이탈](02-표준-경로-이탈.md)).
- 상태 시간 합 = 창 길이만 보고 겹침과 빈틈의 상쇄를 놓친다([장비 상태 이력 가용도](03-장비-상태-이력-가용도.md)).
- 묶는 간격을 하나로 못 박고 알람 건수 감소를 성과로 말한다([알람을 사건으로 묶기](04-알람을-사건으로-묶기.md)).
- 합성 로그에서 나온 수치를 현장 효과 근거로 말한다 — 모든 수치는 방법 시연이다.
