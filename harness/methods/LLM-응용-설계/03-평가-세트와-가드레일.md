# 평가 세트와 가드레일 — 맞았는지 어떻게 아나
> 접근법 선반: [그림자 모드와 승격 기준](../../approaches/컴퓨터과학/자율성-설계/03-그림자-모드와-승격-기준.md)(AI-사람 일치율로 단계를 올린다) · [독립 검사기](../../approaches/경영과학/모형을-믿어도-되나/02-독립-검사기-계산한-쪽이-아닌-다른-코드로.md) · [효과 수치 읽는 법](../../approaches/경영과학/모형을-믿어도-되나/03-효과-수치-읽는-법-기준선과-자기-신고.md)(기준선과 자기 신고)

> 고정 질문 세트로 통과율을 재고, 코드로 잴 수 있는 것(스키마·수치·근거 id·유출)을 먼저 보고, 남는 것만 루브릭 판정에 맡긴다. 가드레일은 입력·출력·유출 세 층. 붙는 과제 유형: 전 유형. 코드: 하네스는 `../code/retrieval_citation_eval.py`(검색·인용·답 없음 지표) 와 `../code/structured_output_validate.py`(출력 검증)

## 바로 쓰는 칸
- **쓸 점**: 고정 질문 세트로 층별 통과율을 재고, 코드로 잴 수 있는 것을 먼저 본 뒤 남는 것만 루브릭 판정에 맡긴다.
- **필요한 컬럼**: 질문 20개 안팎과 기대 판정(정답 근거 id·기대 경로·기대 숫자) — 사람이 정한 기대 판정이 없으면 못 쓴다.
- **한 줄 실행**: 전용 코드 없음 — 실물 예는 `code/retrieval_citation_eval.py`·`code/structured_output_validate.py`. 부를 함수: `wilson`, `citation_metrics`, `validate`
- **출력**: 층별 통과율 표(검색·인용·답 없음·숫자·형식·유출·문장 충실도)와 실패 케이스 목록, 「n개 중 k 통과, 95% 구간」 배지.
- **하지 말 것**: LLM 판정 점수를 「정확도」라 부르지 않는다 — 「루브릭 판정 통과율(판정자: 모델 X)」로 쓰고, 같은 세트로 고친 뒤 보고하지 않는다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 사람이 몇 건 직접 훑는 수동 점검, LLM 판정 점수만 보고하는 방식 — 코드로 잴 수 있는 층(스키마·수치·근거 id·유출)을 먼저 통과시키고 남는 문장 충실도만 루브릭 판정에 맡겨야 통과율과 구간을 같은 세트로 되풀이해 보일 수 있어 골랐고(사람 테스트는 병행), 판정 점수만 쓰면 판정자와 생성자가 같을 때 후하게 줄 수 있어 「정확도」로 부르기 어렵다.

## 이럴 때 꺼낸다
- 과제 문구: "정확도", "믿을 수 있나", "환각", "검증", "성능 평가", "안전장치", "근거", "현장 도입 기준".
- 데이터 모양: 대표 질의 20개 안팎 + 기대 판정(정답 근거 id·기대 경로·기대 숫자). 합성이면 심어 둔 정답이 있는 쪽이 쉽다.
- 꺼내지 말아야 할 때: 없다 — 다만 세트를 만들 시간이 없으면 **세트 없이 「정확도 9x%」를 말하지 않는다.** 20개짜리 작은 세트라도 먼저 만든다.

## 입력 → 출력
**평가 세트 형식(`eval/cases.jsonl` 제안, 추론)** — 한 줄 한 케이스:

| 컬럼 | 의미 |
|---|---|
| `id`, `question` | 현업 말투(약어·영문·조사 변이) 그대로 |
| `kind` | `retrieval`(답 가능) · `unanswerable`(답 없음) · `compute`(숫자) · `injection`(기록에 심은 지시문) · `out_of_scope`(도구 밖 요청) |
| `gold_ids` | 정답 근거 기록 id 집합 — 사람이 라벨, 검색기 출력으로 만들지 않는다 |
| `expected_route` | 검색 / 표 계산 / 거절 |
| `expected_numbers` | 계산 질문의 기대 값(코드가 따로 센 값) |

- 출력: 층별 통과율 표 + 실패 케이스 목록.

| 층 | 지표(코드로 잰다) | 어디서 |
|---|---|---|
| 검색 | Top-k 적중 · MRR | [근거를 붙여 답하기](01-근거를-붙여-답하기.md) |
| 인용 | 인용 정확도 · 근거 없는 답 비율 | 01 |
| 답 없음 | 답함 · 거절 정확도 | 01 |
| 숫자 | 계산 값 일치율 · 문장 속 출처 없는 숫자 0건 | [출력을 타입으로 묶기](02-출력을-타입으로-묶기.md) |
| 형식 | 스키마 통과율 | 02 |
| 유출 | LLM 으로 나간 payload 의 원본 행 값 0건 | [질문을 파라미터로](../최적화/05-질문을-파라미터로.md) 의 `Gateway` 가 이미 함 |
| 문장 충실도 | 루브릭 판정 통과율(코드로 못 잰 것만) | LLM 판정 |

- **시험에서 나온 공백 — 한국어 자유 텍스트 조치 기록 검색의 평가법 (인용한 출처에 없음, 추론)**: 지표 정의와 합성 결과는 01 에 있다. 평가 세트 쪽에서는 ① 질문에 **조사·띄어쓰기 변이·영문 혼용·동의어 우회**를 섞는다 ② **답 불가 질문 20% 안팎**(없는 공정, 합계 질문)을 넣는다 ③ 정답 id 를 사람이 정하고 ④ 임계값을 고른 세트와 보고하는 세트를 나눈다.
- **답 없음 처리 (추론)**: 「답 없음」도 기대 판정이다. 케이스에 `expected_route=거절` 을 두고 거절 정확도를 잰다. 합성 세트에서는 1위 점수 분포가 답 가능(0.08~0.58)·불가(0.00~0.23)로 겹쳐, 임계값 하나로는 완벽히 못 가렸다. 이 겹침 자체가 보고할 내용이다.
- **숫자 경계 (추론)**: `compute` 케이스의 기대 값은 코드가 표에서 센 값이다. LLM 이 문장에 쓴 숫자가 그 집합에 없으면 실패. 이 경계가 깨지면 다른 지표가 좋아도 통과로 치지 않는다(실패 조건으로 둔다).
- 작은 표본의 불확실성: 20개 중 19개 통과는 95% Wilson 구간으로 **0.764~0.991** 이다(코드 `wilson`, 손계산과 일치 확인). 「95% 통과」를 점 추정으로만 말하지 않는다.

## 핵심 개념
- **작은 표본으로 즉시 시작.** Anthropic 다중 에이전트 리서치 글의 평가 교훈: 실사용 대표 질의 약 20개로 시작, LLM 판정은 루브릭 하나·단일 호출(0~1 점수 + 통과/실패)이 사람 판단과 가장 일치, 사람 테스트가 자동 평가가 못 잡는 것(예: SEO 콘텐츠 농장 선호)을 잡음, 상태를 바꾸는 에이전트는 **최종 상태**로 평가. (자사 내부 평가, E2 — 수치의 방법이 약해 핵심 근거로는 E3 취급)
- **하드체크 먼저, 판정은 그다음.** 코드로 잴 수 있는 것(스키마·수치 일치·근거 id 실재·유출 0건)을 먼저 통과시키고 남는 것만 루브릭 판정에 맡긴다(실밸개발자 세미나 영상의 「하드체크 먼저, 판정은 그다음」, E4).
- 툴 지형: OpenAI 문서에 graders·trace grading·Promptfoo·red teaming·Agents SDK guardrails·human review 가이드가 있다. Claude Code 는 플러그인을 테스트 케이스로 채점하고 「플러그인 없는 기준선」과 비교하는 `claude plugin eval` 을 2026-09(W37)에 냈다 — 쓰기 전에 스킬이 실제로 돕는지 기준선과 비교해 확인하라는 권고다. promptfoo 0.125.1(2026-10-25, eval CLI).
- 가드레일 3층(6시간 최소형): ① **입력** — 도구 목록 밖 요청 거절 ② **출력** — 스키마·범위 검사 ③ **유출** — payload 에 원본 행 값 0건 assert.
- 과장 위험: LLM 판정 점수를 「정확도」로 부르는 것. **「루브릭 판정 통과율(판정자: 모델 X)」**로 쓴다.

## 반도체 현장에서
- 합성 데이터는 **정답을 아는 시험지**다. 고장 직전 상승·드리프트·주기를 심어 넣고 「모델이 심어 둔 것을 찾나」를 검증하면 정확도 주장 없이도 방법이 맞는지 보인다(추론). 화면에 「합성 데이터」 배지를 고정한다.
- 평가 결과는 **승격 기준**(누락 0건·일치율 하한 등)과 연결해야 쓸모가 있다(추론, 접근법 선반 링크의 그림자 모드 챕터).

## 솔버/코드가 하는 것 · AI 가 하는 것
- 코드: 위 표의 모든 지표, 음성 대조(정답 id 를 섞으면 지표가 떨어지는지), 유출 assert, 통과율과 구간.
- AI(판정자): 코드로 재기 어려운 것 — 「요약이 근거 기록의 내용을 충실히 옮겼나」 — 만. 루브릭 하나, 호출 하나, 0~1 점수와 통과/실패(Anthropic 리서치 시스템 글의 교훈). 판정자 모델 이름을 같이 적는다.
- 사람: 데모 전에 직접 써 본다. 자동 평가가 못 잡는 것을 사람 테스트가 잡았다는 위 글의 교훈.
- 화면 표시: **eval 통과율을 결과물 일부로** 보인다 — 「고정 질문 20개 중 19개 통과, 실패 1건은 이것」. 실패를 숨기지 않는다.

## 화면 한 장
- 구석 배지: 「고정 질문 n개 · 통과 k · 95% 구간 a~b · 합성」 + 층별 통과율 막대 + 실패 케이스 한 줄 목록(클릭하면 질문·응답·오류 코드). 계산 칸/LLM 칸 색 구분은 02 와 같다.

## 함정
- LLM 판정 점수를 정확도라고 부르기. 판정자와 생성자가 같은 모델이면 후하게 줄 수 있다(추론).
- 임계값·프롬프트를 평가 세트에 맞춰 고친 뒤 같은 세트로 보고하기.
- 평가 세트가 쉬운 질문뿐 — 동의어 우회·답 불가·계산 질문이 없으면 통과율이 부풀려진다.
- 가드레일 층 하나로 안전하다고 말하기. 온프렘이어도 로컬 모델은 유출 경로 하나를 없앨 뿐 접근 통제·감사는 따로다(추론).
- 합성 데이터 성능을 현장 성능처럼 말하기(과장 주의).

## 한 문장 설명 · 예상 질문
- "최신 도구를 쓰는 것보다, 어디까지 믿을 수 있는지 재 두는 데 시간을 썼습니다 — 고정 질문 n개의 통과율과 실패 사례를 화면에 두었습니다."(추론)
- Q. 정확도는? A. 한 숫자가 아니라 층별 통과율입니다. 판정 점수는 「루브릭 판정 통과율(판정자: 모델 X)」이고, 숫자는 전부 코드가 계산 값과 대조합니다.
- Q. 질문이 20개뿐인데? A. 그래서 구간을 같이 적습니다(19/20 → 0.76~0.99). 현업 질문이 들어오면 세트를 늘립니다.
- Q. 합성 데이터 점수가 현장 점수인가? A. 아닙니다. 합성 점수는 방법이 맞는지 보는 시험지이고 배지로 표시했습니다.

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 이 문서는 코드가 따로 없다. 하네스 자체의 하드체크는 두 코드에 있다: 손계산 지표(Hit@k·MRR·인용 지표) · Wilson 손계산 · **음성 대조**(정답을 섞으면 Hit@3 이 0.3 이상 하락) · 임계값 극단(0 이면 거절 정확도 0, 1.01 이면 아무것도 답 안 함) · 변이 시험(필수 필드 삭제·수치 ±) · 응답 14종의 오류 코드가 리터럴과 일치.
- 현장 추가 경계 테스트: (a) 평가 세트가 20개 미만이면 구간이 너무 넓다고 화면에 표시되는가 (b) 모델·프롬프트를 바꾼 뒤 같은 세트로 통과율이 어떻게 변했는가(기준선 대비) (c) 실패 케이스가 사람 눈으로 재현되는가.

### 손익 환산
- 평가는 비용을 줄이는 기능이 아니라 **도입 허가 조건**이다. 숫자로 연결하려면 일치율·누락률 하한을 자율성 승격 기준에 넣고(접근법 선반 링크), 누락 1건의 손실을 [기대손실 결정표](../의사결정분석/01-기대손실-결정표.md) 의 비용으로 둔다(추론). 인용한 출처에는 환산 수치가 없다.
- 공개 사례의 효과는 대부분 사람 시간 절감이고 수율 % 는 드물다 — 「검토 시간·결정 주기」로 말하는 것이 사례와 맞다(추론).
