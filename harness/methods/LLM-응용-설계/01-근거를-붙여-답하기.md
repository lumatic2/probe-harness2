# 근거를 붙여 답하기 — 검색 증강 생성(RAG)과 인용
> 접근법 선반: [권한 상속 RAG](../../approaches/컴퓨터과학/정보보안/02-권한-상속-RAG.md)(조치 기록 검색의 권한) · [간접 프롬프트 주입 방어](../../approaches/컴퓨터과학/정보보안/05-간접-프롬프트-주입-방어.md)(검색된 텍스트는 지시가 아니다) · [엔지니어 업무](../../approaches/반도체-현장/업무-유틸리티-사람/01-엔지니어-업무.md)(조치 기록·Inform Note)

> 질문과 비슷한 기록을 찾아 답에 붙이고, 인용한 기록 id 가 맞는지·근거가 없으면 답하지 않는지를 숫자로 잰다. 붙는 과제 유형: ① ⑤. 코드: `../code/retrieval_citation_eval.py`

## 바로 쓰는 칸
- **쓸 점**: 조치 기록을 검색해 근거 기록 id 를 붙여 답하고, 인용이 맞는지·근거가 없으면 거절하는지를 숫자로 재 준다.
- **필요한 컬럼**: 기록 표(`note_id`·증상·원인·조치 텍스트)와 사람이 정답 근거 id 를 라벨한 질문 20~30개 — 정답 근거 id 라벨이 없으면 못 쓴다.
- **한 줄 실행**: `python code/retrieval_citation_eval.py` (methods 폴더에서) — 합성 기록 40건·질문 32개로 지표 출력. 내 데이터로 쓸 때 부를 함수: `Retriever`, `citation_metrics`, `wilson`
- **출력**: 질문별 순위, 지표 4개(Top-k 적중·인용 정확도·근거 없는 답 비율·답 없음 처리), 임계값 슬라이더, Wilson 구간.
- **하지 말 것**: 정답 id 를 검색기 출력으로 만들지 않는다(평가가 순환한다) — 코사인 점수를 「확신도」라 부르지도 않는다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 문서를 통째로 넣는 단일 호출, GraphRAG — 질문이 특정 조치 기록에 가까운 국소 질의이고 기록이 많아 한 번에 못 넣을 때 검색과 인용을 골랐고, 문서가 한 번에 들어갈 만큼 작으면 단일 호출로 충분하며 「데이터 전체의 주제」 같은 전역 질문이나 건수·평균을 묻는 질문이면 GraphRAG·표 계산이 맞다.

## 이럴 때 꺼낸다
- 과제 문구: "조치 기록", "Inform Note", "유사 사례", "원인·조치 후보", "SOP·규정 질의", "근거를 보여 줘", "노하우 검색".
- 데이터 모양: 자유 텍스트 기록(증상·원인·조치 칸, 한국어에 영문·약어가 섞임) + 기록 id. 문서가 10개 안팎이면 더 쉽다.
- 꺼내지 말아야 할 때: ① 질문이 건수·평균·합계·추세처럼 **숫자를 묻는** 경우 — 검색이 아니라 표 계산이다(아래 「숫자 경계」). ② 「데이터 전체의 주제」 같은 전역 질문 — GraphRAG 쪽 질문이다(벡터 RAG 는 국소 질의에 강하다, 아래 인용). ③ 단일 LLM 호출에 문서를 그대로 넣으면 충분한 크기.

## 입력 → 출력
| 입력 | 의미 | 단위 |
|---|---|---|
| 기록 표 | `note_id` · 증상·원인·조치 텍스트 | 건 |
| 평가 세트 | 질문 · **정답 근거 id 집합**(사람이 라벨) · 답 가능 여부 | 20~30개 |
| 임계값 | 1위 점수가 이보다 낮으면 「답 없음」 | 0~1 |
- 출력: 질문별 순위, 지표 4개, 임계값 선택 근거, Wilson 구간.
- **평가법 — 시험에서 나온 공백. 아래 정의 전부 인용한 출처에 없다(추론).**

| 지표 | 정의 | 무엇을 막나 |
|---|---|---|
| Top-k 적중(Hit@k) | 답 가능 질문 중 정답 근거 id 가 상위 k 에 하나라도 있는 비율. MRR 은 첫 정답 순위의 역수 평균 | 검색이 못 찾음 |
| 인용 정확도 | 답한 답 가능 질문들이 인용한 id 중 정답 근거인 비율 | 엉뚱한 기록을 근거로 붙임 |
| 근거 없는 답 비율 | 답을 낸 질문 중 (답 없음이어야 하는데 답함 + 정답 근거를 하나도 인용 못 함) 비율 | 지어낸 답 |
| 답 없음 처리 | 거절 정확도 = 답 불가 질문을 거절한 비율, 답함 = 답 가능 질문 중 답한 비율 | 거절 과다·과소 |

- 평가 세트 만드는 법(추론): 현업 말투로 20~30개. 약어·영문·조사 변이와 동의어 우회 질문을 섞는다. 답 불가 질문(데이터에 없는 공정, 숫자 합계)을 20% 안팎 넣는다. 정답 id 는 검색기 출력이 아니라 사람이 정한다(순환 금지). 합성이면 화면에 「합성」.
- → 실행 결과는 부록
- 관찰: 1위 점수가 답 가능 질문은 0.08~0.58, 답 불가 질문은 0.00~0.23 으로 **겹친다**. 임계값 하나로는 오답 아니면 거절 과다 둘 중 하나를 고른다 → 임계값을 슬라이더로 두고 「답함·거절 정확도」를 같이 보이는 것이 정직하다(추론).
- 실행: `python code/retrieval_citation_eval.py` (numpy). 현장에서 바꿔 끼우는 곳: `RAW`·`QUESTIONS`. **LLM 이 인용한 id 를 평가하려면** `citation_metrics(answers, golds, answerable)` 에 질문별 인용 id 리스트(빈 리스트 = 답 없음)를 넣는다.

## 핵심 개념
- 흐름: 질문 → 검색(Top-k) → (LLM) 기록 id 를 붙인 답 → 코드가 인용 id 실재·정답 근거 여부를 검사 → 근거가 없으면 「답 없음」.
- 이길 조건과 한계. 축자 인용(Microsoft Research LazyGraphRAG 글):
  > "vector RAG excels for local queries where the answer resembles the query and can be found within specific text regions"

  반대로 GraphRAG 의 장점은 「데이터 전체를 다루는 전역 질의」다. LazyGraphRAG(2024-11-25, **오래된 글**)가 인덱싱 비용을 낮췄다고 하나 「인덱싱 비용이 전체 GraphRAG 의 0.1%」 수치는 받은 원문 문단에 없고 검색 요약에만 있었다(원문 미확인 — 단정 금지).
- 단순 해법부터. 축자 인용(Anthropic, Building effective agents, 2024-12 **오래된 글**):
  > "For many applications, however, optimizing single LLM calls with retrieval and in-context examples is usually enough."
- 6시간 안에는 GraphRAG 인덱스를 새로 만들기보다 **정해진 문서 몇 개에 대한 검색 + 인용(Claude Citations·OpenAI file search) + 「근거 없으면 답 안 함」**이 싸다(추론, 다단계 검색을 쓴 Anthropic 리서치 시스템 글에 근거). 규정·SOP PDF 10개 이하가 이 최소형의 대상이다.
- 한국어 자유 텍스트의 특성(추론): 조사·어미가 붙어 같은 말이 다른 토큰이 되고, 띄어쓰기가 흔들리고, 「He」↔「헬륨」, 「removal rate」↔「제거율」처럼 영문·약어가 섞인다. 형태소 분석기 없이 **문자 n-gram TF-IDF** 로 앞 둘을 견디게 하고, 셋째(동의어·언어 혼용)는 못 견디므로 의미 검색(임베딩)이 필요하다(이 문서의 코드는 임베딩을 포함하지 않았고 비교하지 않았다 — 미시험).

## 반도체 현장에서
- 장비 이상 때 「비슷한 증상의 과거 조치」를 찾아 원인·조치 후보를 근거 기록과 함께 보이는 카드. SK하이닉스 GaiA 는 「네이티브 RAG+LLM(2023) → 에이전트」 로드맵을 공개했다(SK하이닉스 뉴스룸, 자사 발표, E2).
- 반도체 특화 LLM SemiKong(Aitomatic·Tokyo Electron 등, arXiv 2411.13802)이 일반 대형 모델보다 반도체 과제에서 낫다고 주장한다 — 검색 요약 기준, 본문 미판독, 개발사 자기 주장(E3).
- 「온톨로지 기반 지식 그래프 구축」이라고 부르지 않는다. 6시간에 만든 것은 수작업 관계표다(과장 주의).

## 솔버/코드가 하는 것 · AI 가 하는 것
- 코드: 검색(Top-k), 임계값 판정, 인용 id 가 실재하는지·정답 근거인지 검사, 지표 계산. 난수 없음.
- AI: 검색된 기록으로 원인·조치 후보를 문장으로 정리하고 각 문장에 기록 id 를 붙인다. 시스템 지시는 「근거 기록에 없으면 답하지 않는다」.
- **숫자 경계(시험에서 나온 공백 — 인용한 출처에 없음, 추론)**: 건수·평균 다운타임·비율은 **코드가 표에서 직접 계산해 값으로 넘기고 LLM 은 문장에 옮겨 적기만 한다.** 검색된 기록 속의 숫자(「0.5% 이하」「3매」)도 근거 문장으로 인용할 뿐 합산·평균하지 않는다.
  - 옮겨 적은 값이 계산 값과 다르면 서버가 거른다 → [출력을 타입으로 묶기](02-출력을-타입으로-묶기.md) 와 `../code/structured_output_validate.py`.
  - 질문이 검색용인지 계산용인지 거절 대상인지 가르는 분류는 02 의 `choice` 타입 후보다.
- 검색된 텍스트는 **데이터이지 지시가 아니다**. 기록 안에 「이 지시를 따르라」 같은 문장이 들어 있을 수 있다(접근법 선반 링크).

## 화면 한 장
- 질문 입력 → 추천 조치 카드 3장(각 카드에 근거 기록 펼치기 + 일치 점수) + 근거가 부족하면 「관련 기록을 찾지 못했습니다」 카드. 구석에 평가 지표 4개와 임계값 슬라이더. 합성 데이터면 「합성」 배지.

## 함정
- 임계값을 평가 질문 전체로 고르고 같은 세트로 보고하면 낙관적이다(코드는 개발/시험을 나눠 보인다). 질문 26개짜리의 한 건은 약 4%p 다.
- 정답 id 를 검색기 출력으로 만들면 평가가 순환한다.
- 합성 세트의 질문은 기록과 어휘가 겹치게 써서 쉬워진다. 현업이 실제로 쓴 질문으로 한 번 더 잰다.
- 점수(코사인)는 확률이 아니다. 「확신도」라고 부르지 않는다.
- 기록 단위로 자르면 한 기록 안의 원인·조치가 갈라지지 않지만, 긴 SOP 는 청크 경계에서 문맥이 잘린다(추론).

## 한 문장 설명 · 예상 질문
- "이 답의 모든 문장에는 근거 기록 번호가 붙어 있고, 근거가 없으면 답하지 않습니다 — 그리고 그 비율을 이 질문 세트로 재 두었습니다."
- Q. 정확도는? A. 정확도 한 숫자가 아니라 Top-3 적중·인용 정확도·근거 없는 답 비율 세 개로 봅니다. 질문 수가 적어 구간도 같이 보입니다(합성 세트 25/26 → 0.81~0.99).
- Q. 데이터에 없는 걸 물으면? A. 점수가 임계값 아래면 답 없음 카드가 나옵니다. 임계값은 슬라이더이고, 점수 분포가 겹쳐서 완벽히 가르지는 못한다는 것도 화면에 보입니다.
- Q. 합계 같은 숫자는 LLM 이 계산하나? A. 아니요, 코드가 표에서 셉니다. LLM 은 옮겨 적고 서버가 일치를 검사합니다.

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert:
  - ① 기록 본문 전체를 질문으로 넣으면 자기 자신이 반드시 1위(점수 1.0, 40건 전부)
  - ② 손으로 푼 소형 사례: 문서 3개·2-gram, 질문 「가나다」와 둘째 문서의 코사인 = idf2²/(idf1²+idf2²) = 0.36645, 셋째와는 0
  - ③ 지표 손계산(순위 [1,3,없음] → Hit@1 1/3 · Hit@3 2/3 · MRR 4/9, 인용 지표 4질문 사례)
  - ④ Wilson 19/20 → 0.7639~0.9911
  - ⑤ 기록 순서를 섞어도 1위 점수 불변
  - ⑥ **음성 대조**: 정답 id 를 무작위로 바꾸면 Hit@3 이 0.3 이상 떨어짐
  - ⑦ 임계값 0 이면 거절 정확도 0, 1.01 이면 아무것도 답하지 않음.
- 현장 추가 경계 테스트: (a) 평가 세트의 정답 id 가 실제 기록에 있는지 (b) 같은 질문을 조사만 바꿔 넣었을 때 순위가 유지되는지 (c) 답 불가 질문 중 「합계·평균」 질문이 검색 경로로 새어 들어오지 않는지.

### 합성 데이터 실행 결과
- 합성 결과(조치 기록 40건 · 질문 32개[답 가능 26·불가 6], 문자 2·3-gram TF-IDF, 임계값 0.154 를 개발 세트=짝수 번호로 고름): 시험 세트(홀수 번호) Hit@1 0.923 · Hit@3 1.000 · MRR 0.962 · 인용 정확도 0.941 · 근거 없는 답 0.083 · 거절 정확도 0.667.
  - 전체로 보면 Hit@3 0.962(25/26, 95% Wilson 구간 0.811~0.993), 거절 정확도 0.833.
  - 동의어로 우회한 질문 하나(「센서 기준점이 틀어져서」→ 「영점」)는 7위였다. **합성 세트의 값이며 현장 성능이 아니다.**

### 손익 환산
- 공식(인용한 출처에 환산 수치 없음 — 변수만 둔다): 절감 시간 = 조회 건수 × (수작업으로 과거 조치를 찾는 시간 − 검색 결과를 확인하는 시간) × 시간당 단가. 단가는 [질문을 파라미터로](../최적화/05-질문을-파라미터로.md) 의 손익 환산 칸의 추정값을 쓰거나 현업 값으로 바꾼다. 가정 표시를 붙인다.
- 공개 사례의 효과는 「사람 시간·계산 시간」 절감이 대부분이고 수율 % 는 드물다(추론). 효과를 「검토 시간·결정 주기」로 말하는 것이 사례와 맞다. TSMC 의 「엔지니어 재검토 시간 90% 감소」는 매체 경유(E3)라 핵심 근거로 쓰지 않는다.
