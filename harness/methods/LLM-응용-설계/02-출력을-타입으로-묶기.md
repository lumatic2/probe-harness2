# 출력을 타입으로 묶기 — 구조화 출력과 Decisions API
> 접근법 선반: [행동별 자율성 단계표](../../approaches/컴퓨터과학/자율성-설계/01-행동별-자율성-단계표.md)(AI 제시·사람 판단을 칸으로) · [독립 검사기](../../approaches/경영과학/모형을-믿어도-되나/02-독립-검사기-계산한-쪽이-아닌-다른-코드로.md)(계산한 쪽이 아닌 다른 코드로 다시 센다)

> LLM 출력을 글이 아니라 타입 있는 값(JSON 스키마·확률)으로 받고, 서버가 스키마·범위·근거 id·수치 일치를 다시 검사한다. 붙는 과제 유형: ①~⑤ 전부의 앞단·뒷단. 코드: `../code/structured_output_validate.py`

## 바로 쓰는 칸
- **쓸 점**: LLM 출력을 타입 있는 값(JSON 스키마)으로 받고, 서버가 스키마·범위·근거 id·수치 일치를 다시 검사해 어긋나면 화면에 올리지 않는다.
- **필요한 컬럼**: LLM 응답 원문(JSON)·`SCHEMA`·코드가 표에서 직접 센 계산 결과 `facts`·실재하는 기록 id 집합 `known_ids` — 계산 결과가 없으면 수치 대조를 못 한다.
- **한 줄 실행**: `python code/structured_output_validate.py` (methods 폴더에서) — 응답 14종의 오류 코드 출력. 내 데이터로 쓸 때 부를 함수: `validate`, `check_schema`, `compute_facts`
- **출력**: 오류 코드 리스트(`SCHEMA:`·`RANGE:`·`CITE:`·`FACT:`·`NUMBER_IN_TEXT:`·`REFUSAL:`·`PARSE:`), 빈 리스트 = 통과.
- **하지 말 것**: 스키마 통과를 값이 맞다는 뜻으로 읽지 않는다 — 형이 맞아도 건수 4 대 3 처럼 틀릴 수 있어 수치는 계산 값과 대조한다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 자유 서술 출력을 정규식으로 파싱, [임계값을 비용으로 정하기](../판정-모델/04-임계값을-비용으로-정하기.md)의 분류 모델 — 출력이 조치 enum·근거 id·건수 같은 칸으로 쪼개지고 숫자 칸을 계산 값과 대조해야 해서 스키마와 서버 재검증을 골랐고, 출력이 긴 글이어야 하면 숫자 칸만 분리한 자유 서술이, 확신도를 보정된 확률로 써야 하면 보정을 따로 확인한 분류 모델이 맞다.

## 이럴 때 꺼낸다
- 과제 문구: "AI 가 판정", "분류", "트리아지", "우선순위", "보고서 자동 작성", "알람·로그 원인 후보 라우팅", "담당 공정 배정".
- 데이터 모양: 출력이 칸(조치 enum·근거 id·건수·확신도·이유)으로 쪼개지는 업무. 결과가 「예/아니오·카테고리·등급」이고 건수가 많으면 Decisions 타입이 맞는다.
- 꺼내지 말아야 할 때: 출력이 자유로운 긴 글이어야 하는 경우(그때도 숫자 칸만은 분리한다). 확신도를 보정된 확률처럼 쓰려는 경우 — 보정 근거를 확인하지 못했다.

## 입력 → 출력
| 입력 | 의미 | 단위 |
|---|---|---|
| LLM 응답 원문 | 문자열(JSON 이어야 함) | - |
| `SCHEMA` | 허용 필드·형·enum·범위·길이 | - |
| 계산 결과 `facts` | 코드가 표에서 직접 센 건수·평균·합계 | 건/분 |
| `known_ids` | 실재하는 기록 id 집합 | - |
- 출력: 오류 코드 리스트(`SCHEMA:` 스키마 · `RANGE:` 범위 · `CITE:` 근거 id · `FACT:` 수치 불일치 · `NUMBER_IN_TEXT:` 문장 속 출처 없는 숫자 · `REFUSAL:` 답 없음 모순 · `PARSE:` 잘린 JSON). 빈 리스트 = 통과.
- → 실행 결과는 부록
- 실행: `python code/structured_output_validate.py` (pandas). 현장에서 바꿔 끼우는 곳: `SCHEMA`, `compute_facts`(원인 태그 대신 현장 집계 함수), `CALC_FIELDS`(계산 값 필드와 허용 오차).

## 핵심 개념
- 구조화 출력은 모델이 내 JSON 스키마에 맞는 값만 내게 강제하는 기능이다. Claude 는 constrained decoding 으로 스키마 일치를 보장하고 GA(베타 헤더 불필요) — Claude 문서, **WebFetch 요약 기준, 원문 축자 미대조**. OpenAI 는 GPT-6 계열에서도 Structured Outputs 를 지원한다(Using GPT-6 문서).
- **Claude 쪽 한계(같은 요약 기준)**: 숫자 `minimum/maximum`·문자열 길이 제약·재귀 스키마 미지원, 거절·`max_tokens` 절단 시 스키마 불일치 가능. → **범위 검사는 서버 코드가 다시 한다.** 이 문서의 코드가 그 자리다.
- Decisions API(OpenAI Docs, 원문 판독): `POST /v1/decisions`, 모델은 `gpt-6-luna` 만. 축자:
  > "The Decisions API evaluates text, images, and JSON and returns typed answers about 10x faster than the Responses API."

  > "The Decisions API is now generally available."

  - `predicate`(참일 확률) · `choice`(선택지 하나 + 확률 분포) · `score`(순서 있는 단계의 확률가중 평균) 세 타입. 한 요청 최대 400문항. JSON 은 `input_json` 으로 문자열 변환 없이 넣는다.
  - 같은 문서가 언제 쓰지 말지도 적는다 — 자기 스키마의 객체를 생성할 땐 Structured Outputs, 도구 호출이 필요하면 function calling.
- 확률이 나오므로 **임계값으로 사람 검토 큐를 자를 수 있다**. 경영과학 언어로는 오분류 비용표와 바로 연결된다(추론) → [기대손실 결정표](../의사결정분석/01-기대손실-결정표.md).

## 반도체 현장에서
- 장비 Inform Note·알람 메시지의 담당 공정/긴급도 분류, 웨이퍼맵 이미지의 「이 패턴이 가장자리형인가」 predicate(추론).
- 분류를 구조화 출력의 enum 과 Decisions 의 `choice` 로 각각 돌려 결과·시간을 비교해 볼 수 있다.
- 6시간 최소형:
  - ① LLM 을 부르는 서버 어댑터의 응답을 JSON 스키마로 고정 → 서버에서 스키마 재검증(이중 확인) → 화면엔 표/카드로만. 스키마 예 `{"action": enum, "params": {...}, "reason": string}` 로 [질문을 파라미터로](../최적화/05-질문을-파라미터로.md) 의 diff 생성을 바꿔 볼 수 있다.
  - ② 알람·로그·작업지시 텍스트 N건 → `choice`(담당 공정)·`score`(심각도) → 확률이 낮은 것만 사람 큐로, 확률 임계값은 슬라이더.
- ⚠ Decisions 지원 모델은 `gpt-6-luna` 하나다(OpenAI 문서 기준). 응시 환경이 주는 모델·도구에서 구조화 출력을 쓸 수 있는지 먼저 확인하고, 안 되면 JSON 스키마 검증 코드(`validate`)로 대신한다.

## 솔버/코드가 하는 것 · AI 가 하는 것
- 코드: 스키마·범위 검증, 근거 id 실재, **수치 필드를 계산 결과와 대조**, 문장 속 숫자 출처 검사, 답 없음 일관성. 난수 없음.
- AI: 칸을 채운다 — 조치 후보 enum 선택, 근거 id 고르기, 이유 한 문장. **숫자 칸은 코드가 준 값을 옮겨 적을 뿐 만들지 않는다**(시험에서 나온 공백 — 인용한 출처에 없음, 추론).
- 허용 오차는 LLM 이 소수 첫째 자리로 반올림해 적는 정도(±0.05분)만 둔다. 건수는 정확 일치.
- 검증 실패 처리(추론): 실패한 필드를 오류 코드와 함께 LLM 에 한 번만 되돌려 재생성 → 또 실패하면 카드 대신 「확인 필요」 표시. 계산 값으로 **자동 덮어쓰기** 하는 방식도 있으나, 문장 속 숫자까지 덮어쓰면 문장이 어긋나므로 이 코드는 거르기까지만 한다.

## 화면 한 장
- 카드 한 장을 **색으로 갈라** 보인다: LLM 칸(조치 enum·이유·확신도, 연한 색)과 계산 칸(건수·평균 다운타임·근거 기록 수, 진한 색 + 「계산 값」 라벨). 하단에 「서버 검증 통과」 또는 오류 코드. 트리아지면 확률 임계값 슬라이더와 「사람 큐 n건」 카운터.

## 함정
- Decisions 의 확률을 정확도·보정된 확률로 부르지 않는다.
- 스키마 통과를 값의 정답으로 착각한다. 형이 맞아도 값은 틀릴 수 있다(건수 4 vs 3).
- `max_tokens` 로 JSON 이 잘리면 스키마 불일치가 난다 — 파싱 실패 경로를 만들어 둔다.
- 숫자 필드만 검사하고 문장 속 숫자를 놓친다. 이 코드는 문장 속 숫자도 계산 값 목록에 있는지 본다. 단 「3건」처럼 허용 값과 우연히 같은 숫자는 통과한다(추론: 한계).
- 문장 속 숫자 검사의 허용 목록은 계산 결과에서만 채운다. 허용 목록에 LLM 이 쓴 값을 넣으면 검사가 무의미하다.

## 한 문장 설명 · 예상 질문
- "LLM 이 낸 칸과 계산이 낸 칸을 색으로 갈랐습니다 — 숫자 칸은 서버가 계산 값과 대조해서 다르면 화면에 올리지 않습니다."
- Q. 구조화 출력이면 안전하지 않나? A. 스키마 일치는 보장되지만 값이 맞는다는 보장은 아닙니다. 범위·근거 id·계산 값 대조는 서버가 합니다.
- Q. 확률은 믿을 만한가? A. 「모델이 낸 확신도」입니다. 보정됐다는 근거를 확인하지 못했습니다. 임계값은 현업과 함께 비용으로 정합니다.
- Q. 속도는? A. 말하지 않습니다 — OpenAI 의 「약 10배 빠름」과 독립 측정(중앙값 1.46초, 검색 요약 기준·미판독)이 갈립니다(`contested`).

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert:
  - ① 손으로 센 계산 결과(A: 190+150+210=550 → 평균 183.333, B 210, C 145, 없는 태그는 0건·None)
  - ② 14개 응답 사례의 오류 코드 집합이 **손으로 쓴 리터럴과 정확히 일치**(과검출·미검출 둘 다)
  - ③ 변이 시험: 필수 필드를 하나씩 지우면 그 필드의 `required` 오류
  - ④ 평균을 ±0.04 흔들면 통과, ±0.2 면 `FACT`
  - ⑤ 경계값: confidence 0·1 통과, 1.0000001·−0.0001 실패, reason 200자 통과·201자 실패, **파이썬 bool 은 정수가 아니다**
  - ⑥ 문장 속 숫자 추출(기록 id 의 숫자는 제외)
  - ⑦ 검증기가 입력을 바꾸지 않음
  - ⑧ 근거가 있는데 「답 없음」으로 거절한 응답도 계산 결과와 어긋나 걸림
  - ⑨ 같은 응답이 다른 계산 결과(태그 B)에서는 거절됨 — 검증이 응답이 아니라 계산 결과에 묶여 있다는 증거.
- 현장 추가 경계 테스트: (a) 공급사가 실제로 낸 응답 20개를 이 검증기에 통과시켜 오류 코드 분포를 본다 (b) 스키마에 숫자 min/max 를 넣었을 때 공급사가 거부하는지, 그러면 코드 쪽만 남기는지.

### 합성 데이터 실행 결과
- 합성 실행(조치 기록 10건 표, 원인 태그 A: 3건·평균 183.33분): 14개 응답 사례 중 정상 2건이 통과하고 나머지 12건이 의도한 오류 코드로 정확히 걸렸다. 예: 건수를 4 로 적은 응답 → `FACT:n_similar` + `NUMBER_IN_TEXT:4`, 문장에 「35% 감소」를 지어낸 응답 → `NUMBER_IN_TEXT:35`, 없는 근거 N999 → `CITE:unknown:N999`.

### 손익 환산
- 공식(인용한 출처에 환산 수치 없음): 사람 검토 시간 절감 = 전체 건수 × (1 − 사람 큐로 간 비율) × 건당 검토 시간 × 시간당 단가. 임계값 아래로 자동 처리된 건 중 놓친 중요건은 별도 비용 — 오분류 비용표를 [기대손실 결정표](../의사결정분석/01-기대손실-결정표.md) 로 두고 임계값을 비용으로 고른다(추론). 단가는 현업 값 또는 [질문을 파라미터로](../최적화/05-질문을-파라미터로.md) 의 추정값.
