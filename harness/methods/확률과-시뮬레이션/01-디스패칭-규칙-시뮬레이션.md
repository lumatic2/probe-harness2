# 디스패칭 규칙 + 이산사건 시뮬레이션 (Dispatching Rules & Discrete-Event Simulation)
> 장비가 비면 대기 LOT 중 무엇을 고를지 정하는 규칙(FIFO·EDD·CR)을 같은 도착·공정시간 위에서 시뮬레이션으로 비교한다. 붙는 과제 유형: ②. 코드: `../code/dispatch_simulation.py`

## 바로 쓰는 칸
- **쓸 점**: 같은 도착·공정시간 위에서 FIFO·EDD·CR 규칙을 시뮬레이션으로 비교해 규칙별 KPI 차이를 보인다.
- **필요한 컬럼**: `lots`(lot, arrive, due), `ops`(lot, step, station, proc), 스테이션별 장비 수 dict. 도착·공정시간 데이터가 없으면 못 쓴다.
- **한 줄 실행**: `python code/dispatch_simulation.py` (methods 폴더에서) — 합성 데이터 8시드에서 FIFO·EDD·CR 규칙별 KPI 를 비교. (simpy 필요) 내 데이터로 쓸 때 부를 함수: `simulate`, `kpis`, `verify`
- **출력**: 규칙별 KPI 표(평균·p90 사이클타임, 납기 지연율·평균 지연, Q-Time 초과 건)와 Q-Time 초과 LOT 목록.
- **하지 말 것**: 시드 하나로 규칙 순위를 단정하지 않는다 — 8시드 이상 평균과 산포로, KPI 마다 승자가 다르다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 제약 프로그래밍 일정 · 강화학습 디스패칭 — 도착이 계속되고 현행 규칙과 바꾼 규칙을 같은 입력에서 비교해야 하면 이 기법을 고르고, LOT 전체와 시간창이 이미 주어진 정적 문제면 제약 프로그래밍 일정이 맞으며, 강화학습 디스패칭은 실데이터 개선이 한 자릿수 %이고 학습 비용이 커서 응시 환경에서는 쓰지 않는다.

## 이럴 때 꺼낸다
- 과제 문구 신호: "우선순위 규칙", "현행 방식 대비 개선", "납기 지연", "대기시간·사이클타임", "장비 한 대가 빠지면?", "LOT 이 계속 들어온다".
- 데이터 모양 신호: LOT 도착시각·납기, 공정 경로(재진입 포함)와 단계별 공정시간, 스테이션별 장비 수.
- 꺼내지 말아야 할 때: LOT 전체와 시간창이 주어진 정적 일정 문제(→ 제약 프로그래밍 일정). 도착이 없는 일회성 배치 문제.

## 핵심 개념
- 스테이션마다 대기열 + 병렬 장비. 장비가 비는 순간 `규칙(LOT, 지금)` 값이 가장 작은 LOT 을 고른다.
- FIFO: 큐 진입이 이른 순. EDD: 납기가 이른 순. CR(Critical Ratio) = `(납기 - 지금) / 남은 공정시간` 이 작은 순(1 미만 = 늦음).
- 비교의 공정성: 같은 시드의 도착·공정시간(공통 난수)에 규칙만 바꾼다. 규칙 효과 = 난수 차이가 아니라 규칙 차이.

## 반도체 현장에서
- 현장 디스패처는 이런 규칙(과 가중 조합)으로 돈다. 규칙 가중치 조정이 가장 현실적인 개선안이다 (S15 SimPy 공유 자원, S3 전통적 계층형 디스패칭이 비교 기준선).
- RL 디스패칭은 Infineon 실데이터에서도 Flow Factor 0.6~5%, 실데이터 후속에서 납기지연 최대 4% 개선에 그쳐 짧은 시간 안에 만들기에 맞지 않는다 (S9·S11). 그래서 "규칙 비교 + 제약 만족"이 정직한 효과다.

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론: SimPy 시뮬레이션, 규칙별 KPI 계산, 같은 시드로 반복.
- AI: 현업 질문 → 파라미터 변경.
  - "CMP 장비를 1대 더 두면?" → `stations={"PHOTO":2,"ETCH":3,"CMP":2}` (합성 시드 0: 평균 CT 125 → 98 분).
  - "긴급 LOT(핫 로트) 5%가 섞이면?" → `lots.due` 를 줄인 행 추가 후 규칙 재비교.
  - 설명 문장 틀: "현행 FIFO 대비 EDD 는 납기 지연율을 A%에서 B%로 줄였지만 평균 사이클타임은 C분 변했습니다. 지연이 줄어드는 대신 Q-Time 초과 건은 D로 달라졌습니다."

## 화면 한 장
- 규칙별 KPI 표(행 = 규칙, 열 = 평균·p90 CT, 지연율, Q-Time 초과) 와 Q-Time 초과 LOT 목록. 현행 규칙 행을 기준선으로 고정하고 나머지는 변화율(색)로 표시. 우측에 "장비 수/정지" 입력 칸.

## 함정
- 규칙 순위를 단정하지 않는다. 합성에서도 지연율은 CR 이 낮고 평균 CT 는 EDD 가 낮았다 — KPI 마다 승자가 다르다.
- 시드 하나로 말하지 않는다. 최소 8시드 평균과 산포. 공통 난수를 안 쓰면 규칙 차이가 잡음에 묻힌다.
- 시작/종료 편향: 도착 0 시점 빈 공장에서 시작한다. 정상상태 KPI 가 목적이면 앞부분을 버리거나 길게 돌린다.
- 과부하(가동률 ≥ 100%)면 어떤 규칙도 큐가 무한히 는다. 먼저 대기행렬과 운영 곡선 로 가동률을 본다.

## 한 문장 설명 · 예상 질문
- 한 문장: "현장 규칙을 바꾸지 않고 그대로 재현한 뒤, 무엇 하나만 바꿨을 때 차이를 보여 드립니다."
- Q. 규칙 순위가 데이터마다 바뀌지 않나? → 바뀐다. 그래서 같은 난수로 시드를 늘려 평균·산포를 함께 보이고, 현업 데이터로 바꿔 끼우는 칸을 연다.
- Q. 시뮬레이션이 현실을 맞게 흉내 내나? → 로그 단위 검사(겹침·리틀·규칙 의미)로 시뮬레이터 자체를 검증한다. 현실 일치는 현업 로그와의 보정이 필요하다(추론).

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert(`verify`, 시뮬레이터 내부와 다른 방식으로 로그만 읽어 검사):
  - ① 장비별 공정 구간 겹침 없음.
  - ② 처리 시간 = 입력 `proc`, 전 공정 완료, 도착 전 시작 없음.
  - ③ 리틀의 법칙: 도착/완료 사건 스윕으로 계산한 시간적분 WIP = 사이클타임의 합.
  - ④ 규칙 의미: 어떤 LOT 이 시작할 때 그 순간 대기 중이던 다른 LOT 이 규칙상 더 우선이면 실패(FIFO·EDD·CR 각각, 로그의 진입·시작 시각으로 따로 재계산).
  - ⑤ 검사기 자체 시험: FIFO 로그를 EDD 로 검증하면 걸린다.
  - ⑥ 병목 증설 시 CT 감소.
- 현장에서 추가할 경계값 테스트 2개: 도착 간격을 매우 크게(대기 0 — 모든 규칙이 같은 결과), 장비 1대·LOT 1건(CT = 공정시간 합).

### 합성 데이터 실행 결과
- 합성 8시드 평균 결과 예: FIFO 지연율 13.5% → EDD 5.5% → CR 4.3%, Q-Time 초과 건은 127.9 → 101.0 → 117.9 (분산이 크므로 시드를 늘려 본다).

### 손익 환산
- 공식: 사이클타임 단축 → WIP 현금 = 하루 매출원가 흐름 × (ΔCT 일) × WIP 원가 반영률(0.5~1.0). 하루 매출원가 흐름 1,054억원(FY25), 일회성 현금이며 자본비용 8% 가정 시 연 효과 (리틀의 법칙, 반영률·자본비용은 가정).
- 예시(추정): 대상 라인이 회사 원가 흐름의 5% 이고 CT 가 0.1일 줄면 1,054억 × 0.05 × 0.1 × (0.5~1.0) = 약 2.6억~5.3억원 일회성. 이 숫자는 데모 결과가 아니라 공식 예시다 — 합성 시뮬레이션의 분 단위 차이를 곧바로 원화로 바꾸지 않는다.
