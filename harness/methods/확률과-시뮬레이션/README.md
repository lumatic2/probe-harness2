# 확률과 시뮬레이션 — 학문 지도

> [기법 선반](../README.md) › **확률과 시뮬레이션** · 문서 4
> 한 줄: 입력이 흔들릴 때 결과를 **한 숫자가 아니라 분포**로 말한다. 닫힌 식(대기행렬)으로 그리거나, 컴퓨터로 수천 번 돌려(시뮬레이션·몬테카를로) 구한다.

## 핵심 질문
**입력이 흔들리면 결과는 평균이 아니라 얼마의 범위로 나오고, 가동률이나 규칙을 바꾸면 그 범위가 어떻게 움직이나?**

## 이럴 때 꺼낸다 / 옆 모듈로
- **꺼낸다**: LOT 이 계속 들어오고 우선순위 규칙을 비교할 때 · 「가동률을 높이면 좋은가」「목표 WIP 는」 · 「얼마나 걸리나」「열 번 중 아홉 번」 같은 불확실성 · 장비 고장에도 무너지지 않는 배정을 고를 때.
- **옆 모듈로**
  - LOT 전체와 시간창이 주어진 정적 일정 → [최적화](../최적화/README.md) 제약 프로그래밍 일정
  - 병목이 어디인가, 제품 믹스 → [생산과 재고·운영](../생산과-재고-운영/README.md) 병목 분석
  - 어느 가정이 결과를 가장 흔드나 → [의사결정분석](../의사결정분석/README.md) 민감도 분석
  - 이상 감지·고장 시간 분포(Weibull) → [품질과 신뢰성·통계](../품질과-신뢰성-통계/README.md) 신뢰성과 보전 주기 · 관리도와 오경보 주기

## 핵심 개념어
- **리틀의 법칙**: WIP = 처리율 × 사이클타임. 어느 한 변을 알면 나머지를 읽는다([대기행렬과 운영 곡선](02-대기행렬과-운영-곡선.md)).
- **가동률 u**: 용량 대비 투입. 1 에 가까울수록 대기가 비선형으로 늘어난다.
- **p50 / p90**: 중앙값과 「열 번 중 아홉 번은 이 안」 값. 평균과 구분해서 말한다([몬테카를로](03-몬테카를로.md)).
- **시드**: 난수 시작값. 안 고정하면 화면 숫자가 새로고침마다 달라진다.
- **평균 최적 / 최악 최적 / 후회 최소**: 시나리오를 묶는 세 기준([강건·시나리오 계획](04-강건-시나리오-계획.md)).
- **웜업 구간**: 빈 공장에서 시작하는 시뮬레이션의 앞부분. 정상상태가 목적이면 버린다([디스패칭 규칙 시뮬레이션](01-디스패칭-규칙-시뮬레이션.md)).

## 관점 쌍
- **평균 ↔ 분포**: 평균 하나는 꼬리를 숨긴다. p90 으로 말한다([몬테카를로](03-몬테카를로.md)).
- **가동률 높임 ↔ 사이클타임**: 가동률을 100% 로 채우면 오히려 늦어진다. Intel 램프업 논문의 권고가 「용량 여유를 포기하지 말라」였다(S12).
- **규칙 비교 ↔ 최적 일정**: 규칙은 도착이 계속될 때, 최적 일정은 LOT 이 이미 정해졌을 때 맞다([디스패칭 규칙 시뮬레이션](01-디스패칭-규칙-시뮬레이션.md)).
- **사전 대비(강건) ↔ 사후 복구**: 강건 최적화는 교란 전에, 최소 변경 재스케줄은 교란 뒤에 쓴다.

## 이 분야 사람이 먼저 묻는 것 5
1. 입력 분포의 근거는 무엇인가? 근거가 없으면 범위만이라도 현업에 확인했나?
2. 시드 몇 개로 돌렸고 산포는 얼마인가?
3. 빈 공장에서 시작한 앞부분을 버렸나?
4. 평균인가 p50 인가 p90 인가?
5. 새 시나리오에서 다시 평가했나? 계획 시나리오 안에서만 좋은 것은 아닌가?

## 흔한 함정
- 규칙 순위를 단정한다. KPI 마다 승자가 다르다([디스패칭 규칙 시뮬레이션](01-디스패칭-규칙-시뮬레이션.md)).
- 공시 가동률을 장비 OEE 로 쓴다([대기행렬과 운영 곡선](02-대기행렬과-운영-곡선.md)).
- 최빈값으로 계획하면 평균보다 짧다([몬테카를로](03-몬테카를로.md)).
- 입력 사이 상관을 무시하면 꼬리가 얇아진다([몬테카를로](03-몬테카를로.md)).
- 시나리오가 적으면 평균 최적이 과적합한다. 평가는 새 시나리오로 한다([강건·시나리오 계획](04-강건-시나리오-계획.md)).
- 오픈 벤치마크 효과를 실데이터 효과처럼 말한다. 강화학습 디스패칭은 오픈 모델에서 두 자릿수 %, 실데이터에서 한 자릿수 %다(S9·S11).
