# 몬테카를로 시뮬레이션 (Monte Carlo)
> 불확실한 입력(작업 기간·고장·손실 단가)을 분포에서 수천~수만 번 뽑아 결과의 분포(p50/p90)를 얻는다. 붙는 과제 유형: ② ③ ⑥. 코드: `../code/monte_carlo.py`

## 바로 쓰는 칸
- **쓸 점**: 불확실한 작업 기간·고장·손실 단가를 분포에서 뽑아 일정 지연과 절감액을 p10/p50/p90 분포로 말한다.
- **필요한 컬럼**: `tasks`(task, pred, opt, mode, pess, p_fail, mttr)와 절감 가정 dict. 입력의 최소·최빈·최대 범위가 없으면 못 쓴다.
- **한 줄 실행**: `python code/monte_carlo.py` (methods 폴더에서) — 합성 일정·절감 가정에서 지연일과 연 절감액 분포를 출력. 내 데이터로 쓸 때 부를 함수: `simulate_schedule`, `simulate_savings`, `summarize`
- **출력**: 완료일·지연일의 p10/p50/p90·평균·지연 확률, 연 절감액의 p10/p50/p90·평균, 시드·N.
- **하지 말 것**: 합성 절감액(p50 16.1억 등)은 가정 입력의 결과라 효과 근거로 말하지 않는다. 최빈값 계획을 평균처럼 말하지 않는다.
- **대신 쓸 수 있었던 것 / 안 쓴 이유**: 강건·시나리오 계획 · 민감도 분석 — 입력이 흔들릴 때 결과의 범위(p50/p90)를 말하려면 이 기법을 고르고, 불확실성 속에서 배정 자체를 골라야 하면 강건·시나리오 계획을, 어느 가정이 결론을 뒤집는지만 보려면 민감도 분석을 쓰며 입력 분포의 근거가 전혀 없으면 분포 모양이 결론을 정하므로 쓰지 않는다.

## 이럴 때 꺼낸다
- 과제 문구 신호: "얼마나 걸리나", "불확실성", "최악의 경우", "신뢰구간", "절감 효과가 확실한가", "영향받는 LOT 수가 몇 건?".
- 데이터 모양 신호: 작업 목록 + 선행 관계 + (최소·최빈·최대) 소요일, 고장 확률·평균 수리시간, 단가·발생 건수의 범위.
- 꺼내지 말아야 할 때: 입력 분포의 근거가 전혀 없을 때(분포 모양이 결론을 정한다 — 먼저 범위만이라도 현업에 확인). 정확한 일정 하나가 필요하면(→ 제약 프로그래밍 일정).

## 입력 → 출력
입력 (DataFrame / dict)

| 표 | 컬럼 | 의미 | 단위 |
|---|---|---|---|
| `tasks` | `task` | 작업 이름 | 문자열 |
| | `pred` | 선행 작업(`;` 구분, 없으면 빈 문자열) | 문자열 |
| | `opt`, `mode`, `pess` | 소요일 최소·최빈·최대 | 일 |
| | `p_fail`, `mttr` | 작업 중 고장 확률, 평균 수리일(지수분포) | 확률, 일 |
| `savings` dict | `viol_per_year` | 연 Q-Time 위험 LOT 수 평균 | LOT/년 |
| | `reduction` | 감소율 (하·최빈·상 삼각분포) | 비율 |
| | `cost_per_lot` | LOT 당 손실 (하·최빈·상) | 억원 |

출력: 완료일·지연일 분포(p10/p50/p90/평균, 지연 확률), 연 절감액 분포(p10/p50/p90/평균).
- → 실행 결과는 부록

## 핵심 개념
- 입력 `X ~ 분포` 를 N 번 뽑아 `Y = f(X)` 를 계산하고 `Y` 의 분위수를 읽는다. 표준오차는 `σ/√N` 로 줄어든다.
- 삼각분포(opt, mode, pess)의 평균은 `(opt+mode+pess)/3` — 최빈값으로 짠 계획은 비관 쪽 꼬리 때문에 평균보다 빠르다(계획 오류).
- 방향 규약: 지연은 p90 이 "나쁜 쪽"(열 번 중 아홉 번은 이 안에), 절감액은 p10 이 "나쁜 쪽"(90% 확률로 이 이상).

## 반도체 현장에서
- 장비 고장·공정시간 변동 아래 일정의 p90 지연, 설비 이설·검증 작업망의 완료일 분포, Q-Time 위반 방지 효과의 연 절감액 신뢰구간. 반도체 특화 확률 계획 사례는 확인하지 못했다 — 표준 기법으로만 쓴다 (외부 출처 미확인).
- 강건·확률 계획은 Edelman 결선작 ECCO 가 대규모 확률 MIP 로 핵심 운영비 1.09% 절감을 보고한 사례가 있다 (S20, 자기 신고, 소매업).

## 솔버/코드가 하는 것 · AI 가 하는 것
- 결정론(시드 고정): 샘플링, 선행 관계 전파, 분위수 계산, 결과 재현.
- AI: 현업 질문 → 파라미터 변경.
  - "D 시운전이 최대 12일까지 걸릴 수 있다면?" → `tasks.loc[task=="D_시운전","pess"] = 12`.
  - "연 위험 LOT 가 6건이 아니라 10건이면?" → `savings["viol_per_year"] = 10`.
  - 설명 문장 틀: "계획은 21일이지만 열 번 중 아홉 번은 30일 안에 끝납니다. 가장 큰 요인은 설치(B)·배관(C) 병행 구간의 비관 꼬리입니다."

## 화면 한 장
- 결과 분포 히스토그램 + p50(실선)·p90(점선) 세로선, 계획선(회색)과 그 오른쪽 "계획 초과 확률" 문구. 입력 슬라이더(비관일·고장 확률) 변경 시 즉시 재계산, 같은 화면에 절감액 분포를 두 번째 패널로.

## 함정
- 최빈값으로 계획하면 평균보다 짧다(계획 오류). 평균과 p50 을 구분해 말한다.
- 입력 사이 상관을 무시하면 꼬리가 얇아진다. 같은 원인(예: 공통 설비)으로 함께 늘어나는 작업은 같은 난수를 공유시킨다.
- 포아송·감소율을 곱한 연 건수는 정수 이산 분포다. 평균 하나로 줄이면 0건 확률(합성 2.3%)이 사라진다.
- 시드를 안 고정하면 화면 숫자가 새로고침마다 달라진다. 시드와 N 을 화면 모서리에 같이 적는다.

## 한 문장 설명 · 예상 질문
- 한 문장: "평균이 아니라 '열 번 중 아홉 번은 이 안에 든다'로 말씀드립니다."
- Q. 분포 모양은 어디서 났나? → 삼각분포(최소·최빈·최대)는 현업 인터뷰로 채우는 칸이고, 근거가 없으면 합성이라고 명시한다. 모양 변경(예: 균등)의 민감도도 돌린다.
- Q. 몇 번 돌리면 믿을 만한가? → N=2만과 N=40만의 p10 차이를 보여 수렴을 확인했다(8% 이내).

## 부록 — 검증 기록과 근거

### 검증 (하드체크)
- 코드 끝 assert: ① 완료일이 낙관·비관 임계경로(재귀로 따로 계산) 경계 안(고장 제외). ② 같은 시드 → 같은 결과. ③ 단일 작업이면 p50/p90 이 `scipy.stats.triang.ppf` 해석값과 1% 안에서 일치. ④ 순수 파이썬 반복문으로 6,000건 한 건씩 돌린 평균이 벡터 시뮬레이션 평균과 4 표준오차 안. ⑤ 절감액 평균이 독립 곱 해석값(연 위반 × 평균 감소율 × 평균 단가)과 일치. ⑥ N=2만과 N=40만의 p10 차이가 8% 이내(수렴).
- 현장에서 추가할 경계값 테스트 2개: 모든 `p_fail` = 0, `opt=mode=pess`(분산 0 → 지연 정확히 0), N 을 100 으로 줄였을 때 p90 이 요동치는지 확인(표본 부족 경고 문구).

### 합성 데이터 실행 결과
- 합성 예: 계획 21일, 지연 p50 4.5일·p90 9.0일, 절감액 p10 5.5 · p50 16.1 · p90 34.1억원/년 (가정 입력).

### 손익 환산
- 공식: 절감액 = 회피 LOT 수 × LOT 당 손실 (Q-Time 위반 예측 서비스 예, LOT 당 1.45억~8.6억원 추정). 말하는 법: 보수값 하나 + 범위 + 가정 슬라이더.
- 예시(전부 가정): 연 위험 6건, 감소율 0.4~0.9, LOT 당 1.45~8.6억원 삼각분포 → p10 5.5억 / p50 16.1억 / p90 34.1억원. "90% 확률로 연 5.5억 이상, 중앙값 16.1억"이라 말한다. 위 입력 값은 모두 임의 가정이며 NPV 계산 예의 단일 점 가정(연 4랏 회피)과 다르다.
