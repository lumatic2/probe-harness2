# README-TEMPLATE — 실행 안내 골격 (어디에 쓰는지는 `docs/과제설정.md` 2절이 정한다)

> **먼저 과제설정 2절을 본다.** 과제가 실행 안내 파일과 양식을 지정했으면(예 `HOW_TO_RUN.md` 7절) **그 양식이 우선**이고 이 틀은 「된다 표 · 안 된다 · 환경 변수 · AI 활용 기록」을 그 양식의 알맞은 절에 끼워 넣는 참고다. 루트 README 취급이 「보존」이면 루트 README 를 건드리지 않는다. 「교체」일 때만 이 틀로 루트 README 를 쓰고 원문은 `docs/task/README.md` 로 옮긴다.
> 과장 금지가 형식이다. 되는 것과 안 되는 것을 같은 무게로 쓴다. 테스트가 덮지 않는 조건은 덮는다고 쓰지 않는다. 대표 수치는 지금 커밋에서 뽑은 값만.
> 다 채운 뒤 `python3 harness/tools/evidence_check.py README.md` 가 통과해야 한다(증거 없는 칸 0개, 없는 파일 인용 0개, 「된다」·「안 된다」 어디에도 없는 요구 ID 0개). 모듈 폴더마다 `src/<모듈>/README.md`(이 파일 맨 아래 「모듈 README 틀」)도 쓴다 — 루트 「구조와 설계 근거」 표의 모듈과 1:1.

## 된다 (각 행 = 증거 있음)

> 행 ID(R1·R2…)는 `docs/PROBLEM.md` 3절 요구 표와 같은 것을 쓴다. 테스트 이름에도 같은 ID(`test_r1_…`)를 넣는다 — 요구 ↔ 코드 ↔ 테스트 ↔ 이 표가 같은 이름으로 서로 가리켜야 채점기가 찾는다.
> 최적화 과제는 **「유효하다」와 「좋다」를 다른 행**으로 쓴다: 「제약 위반 0건(검사기 이름)」 행과 「목표값 M — 하한 N 대비 +x% / 기존 대비 −y%」 행. 둘을 한 행에 섞으면 어느 쪽이 검증됐는지 채점기가 못 가른다.

## 구조와 설계 근거

| 모듈 (`src/…`) | 하는 일 | 받는 것 → 내는 것 (데이터 계약 — 타입·스키마 위치 `파일:줄`) |

- **왜 이렇게 나눴나**: … (나눈 기준과 이유)

- **실제/모의 경계와 교체 지점**: … (아래 「환경 변수」 표에 빠짐없이)

## 환경 변수

| 이름 | 용도 | 없으면 |
|---|---|---|
| `PORT` | 서버 포트(빌드 UI + API 단일 서버) | `3000` |
| `DATABASE_URL` 류 | DB 접속(종류는 자유) | 빈 DB 로 시작해 스키마·초기 데이터 생성 |
| 초기 계정 변수(이름만) | 운영자·구성원 초기 로그인 | 없으면 기동 실패 또는 안전한 기본 — 어느 쪽인지 적는다 |
| 과제가 준 AI 변수(쓸 때만) | 제품 안 AI 호출. **서버 환경에만** | 모의 응답 + 화면에 「모의」 표시. 판정은 규칙 코드라 키와 무관 |

> 코드가 읽는 변수(`grep -rhoE "os.environ|getenv|process.env" src/`)가 이 표에 전부 있어야 한다. 쓰지 않는 스타터 변수·AI 데모 변수는 표에 남기지 않는다.

## AI 활용 기록

> 심사자가 「AI 를 어떻게 나눠 썼나」를 한눈에 보는 절. 제출 문서를 쓸 때(M6 점검 기준 고정) 오케가 `docs/세션.txt` · `docs/DECISIONS.md` · `git log` · `docs/PLAN.md` 「시간 기준선」 를 세어 **5~8줄**로 채운다. 센 값만 쓴다(지어내지 않는다) — 제출 점검이 같은 곳을 다시 센다.

- 세션 수: 오케 1 · DM 1 · 설명 1 · 통합 1 · 구현 워커 <n> · 서브에이전트 <n>회 (리서치 · 스캐폴드 · 독립 검산·재계산 · 보안 · 평가 · 제출 점검)
- 위임 수: <N> 건 · 재작업 <N> 건 (재작업 사유 한 줄: …)
- 병렬로 겹친 일: <무엇이 돌 때 무엇을 했나 — 예: 구현 탭 2개가 도는 동안 오케가 피드백 DM 질문 준비> (PLAN 시간 기준선 「기다리는 동안 한 일」)
- 사람이 직접 본 검증: <사용자가 화면에서 본 것(`docs/QA.md` 에서) · 실무자 확인 답변 N> (같은 모델 서브에이전트의 검산과 구분해서)
- 모델 선택: <어디에 어떤 모델을 왜 — 사용자가 실제로 고른 것>
- 기준선과 가장 크게 어긋난 구간: <구간 · 무슨 판단을 했나> (PLAN 시간 기준선 「실제 시각」 · DECISIONS)
- 근거: `docs/세션.txt` · `docs/DECISIONS.md` · `git log` · `docs/PLAN.md` 「시간 기준선」
