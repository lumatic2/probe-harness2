# 데이터 — 서브에이전트 프롬프트 (과제가 데이터 파일을 줄 때)

> 이 문서는 탭이 아니다. 오케가 세팅 보고를 전하기 전(setup.sh 출력 「다음」 2b — 사람이 보고를 읽는 동안 돈다) 서브에이전트 하나를 띄우며 이 문서와 과제설정 1절의 데이터 파일 목록을 프롬프트로 넘긴다. `wait_agent` 를 걸지 않는다 — 오케는 세팅 보고를 먼저 전하고, 결과는 「과제 시작하자」 뒤에 쓴다. 결과 파일은 과제 시작 보고의 「데이터 지도」 줄, DM 의 질문 후보, 코어 워커의 검증기 씨앗이 된다. 데이터 파일이 없는 과제면 띄우지 않는다.

## 입력
- 과제가 준 데이터 파일 전부(CSV·JSON·xlsx)와 데이터 설명 파일(`data/README.md` 류). 과제 README 의 데이터 절.
- 쓰는 것: 코드만(python3 · DuckDB 가 있으면 `SUMMARIZE`). 파일을 대화에 그대로 싣지 않는다 — 집계 결과와 샘플 몇 행만 본다.

## 할 일 — 순서대로, 전부 코드로
1. **구조 한 장.** 파일마다 열 이름·타입·행 수 · 기본키 후보(유일한 열 조합) · 다른 파일을 가리키는 열(외래키) · 단위·시각 형식·날짜 기준(근무일인가 달력일인가). 데이터 설명 파일이 말한 주의 사항은 그대로 옮긴다(예: 「빈 값은 0 이 아니다」「A→B 와 B→A 는 다르다」「같은 값이 행마다 반복된다」).
2. **프로파일 → assert.** 열 단위(타입·결측 수·유일성·값 도메인·범위) → 표 단위(키 중복) → 표 간(외래키 존재율 · 건수 대조: 같은 사실을 두 파일이 말하면 숫자가 맞는지). 통과한 점검은 그대로 `assert` 로 적는다 — 이 스크립트가 나중에 데이터셋 검증기(필수 열·키·형식·참조)의 씨앗이다. 틀린 데이터를 고치지 않는다. 결측을 채우지 않고, 방향별 값을 대칭으로 만들지 않고, 평균으로 대체하지 않는다.
3. **의미 질문 후보.** 코드로 정할 수 없는 것만 — 빈 값·기록 없음의 뜻, 야간·경계 시각의 날짜 귀속, 제외 대상(운행 중 아닌 후보·휴무자), 같은 이름이 두 파일에서 다른 뜻인 경우, 실적이 무엇을 세고 무엇을 안 세는지. 실무자 말로, 해법·알고리즘 단어 없이. 7개 안.
4. **눈에 띄는 이상 3~5개.** 어느 파일 어느 열에서 몇 건인지 숫자로. 「이상하다」만 쓰지 않는다.

## 산출 — 파일 둘, 다른 파일은 만들지 않는다 (커밋은 오케가 한다)
- `docs/experiments/profile.py` — 2 의 점검 스크립트. `python3 docs/experiments/profile.py` 로 다시 돌면 같은 결과. 파일 머리에 입력 경로와 돌린 시각.
- `docs/research/데이터.md`:
```
# 데이터 — HH:MM · 입력: <파일 목록>
## 결론 3줄
## 구조 한 장
| 파일 | 행 | 기본키 | 가리키는 열 → 파일 | 단위·형식·날짜 기준 | 설명 파일의 주의 |
## 점검 결과
| 점검 | 파일·열 | 결과(통과/건수) | assert 줄 |
## 눈에 띄는 이상
파일·열 · 몇 건 · 예시 1행
## 실무자에게 확인할 것 (후보 7개 안, 실무자 말로)
## 못 본 것
```
오케는 「구조 한 장」을 `docs/ARCHITECTURE.md` 3절 데이터 지도로 옮기고, 「실무자에게 확인할 것」은 PROBLEM 첫판 전에 왔으면 7절에 넣고, 뒤에 오면 DM 에 queue 한다(`M1-실무자대화.md` ①). 코어 워커 브리프에는 `profile.py` 경로를 넣는다.
