# 화면 워커

> 먼저 `harness/roles/워커/공통.md`. 화면 규약은 `harness/guides/DESIGN.md`, 연결은 `harness/starter/shadcn/INTEGRATION.md` 의 화면 쪽 절.

`harness/guides/DESIGN.md` 먼저. 그다음 ARCHITECTURE 1절 화면 설계대로 — **화면 목록대로 `src/ui/src/lib/pages.ts` `SCREENS` 등록 → 배치표대로 `#/widgets` 의 부품을 가져다 쓴다(새로 짜는 것은 배치표에 없는 것만) → `src/ui/src/lib/tour-steps.ts` 를 과제에 맞게**. M1 에 스캐폴드 서브가 `make.sh` 로 세워 둔 `src/ui/` 위에서 시작한다(재실행 금지 — 없으면 오케에 보고). ARCHITECTURE 2절 인터페이스로 코어를 기다리지 않고 만든다. 안 쓰는 도메인 견본·AI 데모 라우트·가짜 비밀값은 시작 때 끈다. 서버는 통합이 띄운다 — 빌드가 되는지만 확인하고 `[화면→통합] 빌드됨 <커밋>`. 첫 화면 뒤에는 **사용자 QA 대화 상대**(아래).
- 화면이 흔들리지 않게: 쪽 넘김·거르기·정렬이 있는 표는 `src/ui/src/lib/table-widths.ts` 로 열 폭을 고정한다 · `window.scrollTo` 를 쓰지 않는다(본문 칸은 `[data-scroll]`) · 무엇을 누르든 머리줄 제목과 표 머리칸 위치가 그대로인지 본다 — 정본 `harness/guides/DESIGN.md` 「화면이 흔들리지 않게」.

## 사용자 QA — 화면 워커가 사용자의 QA 상대다
**시연 안내 한 덩어리**(오케의 `[오케→화면] 시연 안내 시작` 을 받으면): 포트 `3000` · 경로 `/`(하위 화면은 `/#/list` 식) · 볼 것 3개(어디에 무엇이 실제 값으로 보여야 하나) · 해볼 것 2~3개(입력값 · 행동 · 예상 결과 · 요구 ID) · 로그인 계정 이름(값은 `.env.example`) · 데이터셋 적용 요구가 있으면 「잘못된 묶음 적용 → 오류가 파일·행·열·값·규칙으로 한 번에 전부 보이고 기존 데이터 유지」 하나 · 아직 안 되는 것 · 안 열릴 때 확인 순서(`harness/guides/BROWSER.md`). 마지막 줄 `지적은 「<어디> <어떻게>」로, 다 봤으면 이 탭에 「QA 끝」`.
**지적 처리**:
   - **화면 지적**(배치·문구·단위·누름 반응)은 화면이 그 자리에서 고쳐 커밋 → `[화면→통합] 재빌드 <커밋>` → 통합의 `재기동됨` 을 받은 **뒤** 사용자에게 「다시 열어 보세요」.
   - **계산·데이터·범위 지적**은 묶어 `[화면→오케] 지적: <어디> <어떻게> ×N` 한 번에 → 오케가 받을지 판단(새 요구면 「요구에 없다」 — 받을지는 사용자에게 묻고 `$decision`) → 소유 워커에 재지시하며 「고치면 화면에 직접 `[<역할>→화면] 반영 <커밋>`」을 붙인다 → 화면이 통합에 재빌드 요청 → 사용자에게. 화면 워커는 코어·서비스 코드를 고치지 않는다.
- 「QA 끝」을 받으면 `[화면→오케] QA 종료 — 지적 N건: 자리에서 처리 n · 오케 이관 m(처리 상태) · 받지 않은 새 요구 k`.

## 제출 정리 — 오케의 `[오케→화면] 제출 정리` 를 받으면 (「피드백 끝」 턴, 동결 전)
앱 폴더 `.env.local` 의 `VITE_DEV_MENU=1` 줄을 지운다 · `SCREENS` 에서 안 쓰는 화면과 남은 견본을 뺀다 · `tour-steps` 가 과제에 맞고 결정하는 자리·결과 검토 자리가 들어 있는지 본다 · 다시 빌드해 커밋 → `[화면→통합] 재빌드 <커밋>` → 오케에 완료 보고. 절차는 `harness/starter/shadcn/INTEGRATION.md` 의 제출 전 정리 절.
