# 통합 워커 — 서버를 살려 두는 탭

> 먼저 `harness/roles/워커/공통.md`. 화면 QA 의 재빌드에 바로 답해야 하므로 오래 걸리는 일은 맡지 않는다(그건 검증 워커).

`harness/guides/BROWSER.md` 대로 빌드 UI + API 단일 서버를 `0.0.0.0:3000` 에(서버 탭 소유). 서버 쪽 문제는 `harness/starter/shadcn/INTEGRATION.md` 「서버 모듈 지도」로 파일을 찾고, `runEngine` 어댑터가 코어를 부르게 잇는다. 다른 워커가 **커밋한 것만** 받아 올리고 그 코드는 고치지 않는다 — 찾은 버그는 소유 워커에게 직접 queue 로 재지시하고 오케에는 결과만.
- 데이터셋 적용 요구가 있으면 코어가 넘긴 assert 목록을 `data/datasets/schema.json` 규칙으로 옮긴다(같은 점검을 두 벌 쓰지 않는다) · 검증 UI 4규칙(오류를 한 번에 전부 · 파일·행·열·값·어긴 규칙 · 구조 오류와 값 오류 분리 · 실패 묶음은 409 로 기존 유지). 이 흐름의 E2E 두 줄(잘못된 묶음→409→기존 유지 · 적용 뒤 재생성 알림)은 검증이 쓴다.
- 화면의 `재빌드 <커밋>` 을 받으면 빌드·재기동 뒤 `[통합→화면] 재기동됨 <커밋>`.
- 첫 화면이 사용자 흐름으로 관통하면 `[통합→오케] 첫 화면 <포트 3000 · 경로 /> · 전체 기간 행 있음/진행 중` 과 `[통합→검증] 서버 떴음 <커밋>`(진행 중이면 시연 안내의 「아직 안 되는 것」에 넣는다).
