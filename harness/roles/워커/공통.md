# 워커 공통 — 모든 워커가 시작할 때 읽는다

> 그다음 자기 역할 파일(`harness/roles/워커/<역할>.md`) 하나만 읽는다. 다른 역할 파일은 읽지 않는다. 오케의 절차는 `harness/guides/STAGES/M4.md`(워커는 읽지 않는다).

- 시작: `AGENTS.md` · `.agents/skills/handoff/SKILL.md` · `docs/brief/<역할>.md` 를 읽고 `docs/세션.txt` 에 등록 → 오케에 `[<역할>→오케] 준비됨 <UUID>` → **기다리지 않고 바로 시작**. 브리프에 적힌 계약 절과 요구 ID 만 만든다. 브리프가 없을 때만 「브리프 대기 중」 한 줄.
- 자기 소유 경로만 쓰고 커밋도 자기 경로만(다른 탭의 staged 파일이 보이면 멈추고 알린다). `tests/contract/` 는 고치지 않는다 — 틀렸다고 보면(출력 계약 파일과 어긋남 포함) 보고한다. 경계값·오류 입력 테스트는 SOLUTION 4절 엣지 표의 행 이름 그대로 3개 이상. 실패는 `.agents/skills/systematic-debugging/SKILL.md` 대로 재현 → 원인 → 최소 수정 → 같은 명령 재통과.
- 기능 커밋 본문에 `설명: <파일:줄> · <왜 이렇게> · <어디서 깨지나>` 를 1~3줄 넣는다. 오케가 `git log --grep='^설명:' --format=%b` 로 모아 `docs/서술형-대비.md` 「구조」 칸의 재료로 쓴다(보고로 다시 보내지 않는다).
- **보고는 셋뿐 (정본 — handoff·오케.md 는 이 문서를 가리킨다)**: ① **완료 1회** — 기준 커밋 · 바뀐 것 · 검증 명령과 출력(`harness/verify.sh "<명령>"` · `python3 harness/tools/security_check.py` — 워커가 직접 돌려 붙인다) · 우려 · 필요한 결정 0~1개 · 「된다」 표 줄(요구 ID → 코드 경로 → 테스트 이름) ② **결정이 필요한 질문**(막힘 · 인터페이스 변경 필요 포함) ③ **새 오류**(보안 · 데이터 손실 위험 포함). 「대기 중」 · 「지시 반영했음」 · 같은 상태의 재보고 · 진행률은 보내지 않는다(오케 턴을 먹는다). 파일에 있는 장문을 다시 보내지 않는다.
- **못 정하는 것은 위로**: 워커 → 오케. 오케가 기술 판단은 정하고, 실무자만 아는 업무 사실은 DM 에, 가치 · 범위 · 받아들일 한계는 사용자에게 올린다(`harness/guides/STAGES/M4.md` 오케 절).
