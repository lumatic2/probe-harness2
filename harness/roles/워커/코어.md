# 코어 워커

> 먼저 `harness/roles/워커/공통.md`.

`src/<모듈>/` 의 순수 계산(HTTP·DB·화면 없이 입력→결과)만. `server/engine.mjs` 의 `runEngine` 은 그 함수를 부르는 얇은 어댑터로 **통합이** 잇는다 — 같은 계산을 두 곳에 두지 않는다. 설계(M3 점검표 ⑦)에서 넣기로 했으면 결과에 `compare`(현재 운영과 비교) · `worst`(가장 나빠지는 건) · `excluded`(뺀 기록)를 채운다 — 계약은 `src/ui/server/run.mjs` 머리 주석. 데이터 과제면 `docs/experiments/profile.py` 의 assert 목록을 완료 보고 「된다」 표에 넘긴다(규칙 파일은 통합이 쓴다). 계약 테스트 초록 → **전량 데이터 1회 실행**(시간·메모리 기록) → PLAN 5절 품질 비교표 「전체 기간」 행(최악 사례 5개 · 개인별 악화 수 · p95/최대 · 자원 · 하드 제약 지킴 · SOLUTION 0절에 킥이 있으면 그 지표도). **표본과 크게 다르면** 완료 보고 첫 줄에 쓴다 — 「크게」 = ① 풀이 조건표의 상한·필수 조건을 넘는 건이 생겼거나, M2 에서 이 해법을 고른 이유가 뒤집힐 만큼(다른 후보가 이겼을 수준) 최악·악화 수·자원이 달라졌다. **완료 보고 뒤** 결과를 좌우하는 기본값(PLAN 2절 「가정」 행) 1~2개를 앞뒤로 한 번씩 더 돌려 PLAN 5절에 「민감도 <값>」 행을 적는다(전량이 오래 걸리면 표본으로, 표에 밝힌다). 결론이 뒤집히면 「기본값에 민감」으로 보고한다.
