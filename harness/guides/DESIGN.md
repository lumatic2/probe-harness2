# DESIGN.md — 결정 화면 디자인 규약

> UI 코드를 쓰기 전에 읽는다. 산출물은 마케팅 페이지가 아니라 **현업 엔지니어가 매일 여는 내부 운영 도구**다. 목표는 "예쁘다"가 아니라 **30초 안에 오늘 뭘 할지 보인다**.
> **화면 출발점**: 기본 = `bash harness/starter/shadcn/make.sh src/ui` 로 M2 「OK」 때 스캐폴드 서브에이전트가 세우는 shadcn 앱(폴더는 항상 `src/ui/`)(페이지 6개 + 도메인 설정으로 켜는 8개(일정 격자 `#/schedule` · 문서 검토 `#/review` · AI 기능 `#/assist` · CSV 가져오기 `#/import` · 기준값 `#/settings` · 데이터셋 `#/datasets` · 실행 `#/run` · 노드 그래프 `#/graph`) + 로그인·내 정보 · 위젯 19종(W17 = AI 대화창 · W18 = 녹음·전사 · W19 = 노드 그래프, React Flow) · 기본 부품 19종(U1~U19) · 결정 부품 5종(D1~D5) · 보기 부품 7종(V1~V7) · 검토 부품 8종(R1~R8) · SK 색 · 한국어, 약 1분). npm 이 막히면 화면 없이 API·CSV 출력으로 가고 `$decision` 한 줄. 출발점은 사용자만 바꾼다(`AGENTS.md` 판단 원칙 8).
> **새 과제 데이터로 바꾸기**: 열·상태·지표·안내문은 `harness/starter/domains/<이름>/domain.json` 한 곳에서 정하고 화면 코드는 그대로 둔다 — 순서는 `harness/starter/DOMAIN.md`. 화면 커버리지·실전 결과 연결·로딩/오류 상태는 `harness/starter/shadcn/INTEGRATION.md`.
> shadcn 앱의 테마 정본은 생성기가 넣는 `sk-theme.css` 하나다. `harness/vendor/skhynix/design.css` 는 shadcn 을 못 쓸 때(정적 HTML)의 토큰표다 — 둘을 섞지 않는다(빠른 시작 8). 토큰 값은 과제에 맞게 바꿔도 되지만 규칙(§원칙·§금지)은 유지한다.

**빠른 시작 — 앱용 파생 규칙**
1. 앱 주색 #ff6600(`--skh-accent`). 캠페인 #ff8e20은 기본 버튼에서 제외한다. 해커톤 사이트색은 쓰지 않는다.
2. 글꼴 = Pretendard 고정, 키트 동봉(`harness/vendor/fonts/PretendardVariable.woff2`, OFL-1.1). 대체: "Malgun Gothic","Apple SD Gothic Neo",system-ui,sans-serif.
3. shadcn은 생성기가 넣은 sk-theme.css와 원본 부품을 유지한다. 원본 컴포넌트 모양·상태 표현을 바꾸지 않는다 — 바꾸는 것은 색 토큰·데이터·라벨뿐(원본에 없는 장식 = slop). 기준 그림 `harness/guides/img/shadcn-recipe-sk.png`.
4. 색 쓰임: 주 버튼 = 검정 + 흰 글자. SK 주황은 데이터 강조(차트 강조 계열·긴급 배지·히트맵)에만 — 선택·포커스 표시는 원본 회색, 주황 선·테두리 금지. 긴급 배지 = 옅은 주황 바탕 + 진한 주황 글자. 주황 면 위 글자 금지(히트맵 최진 칸만 #c24e00 + 흰 글자). 라이트 모드만(다크 없음).
5. 표: 44px 행, 숫자 우측·단위 머리·미수집 —·표 안 가로 스크롤.
6. 개선은 중립색, 악화는 위험색; 방향과 개선/악화 글자를 함께 쓴다.
7. 공통 사이드바는 공식 동봉 로고 아래에 도메인 제목(`harness/vendor/skhynix/ASSETS.md`).
8. `harness/vendor/skhynix/design.css` 는 참고용 토큰표다 — shadcn 앱에 그 CSS·클래스를 섞지 않는다(테마는 `sk-theme.css` 하나).

## 원칙

1. **정보 위계가 디자인이다** — 요약 숫자(3~4개) → 오늘의 큐(행동 대상) → 상세·근거 순. 가장 중요한 것이 가장 크고 가장 위에.
2. **상위 N 시각 분리** — 목록이 있으면 "먼저 볼 것"이 테두리·배경으로 구분돼야 한다. 전부 같은 무게면 아무것도 안 중요한 것.
3. **색은 의미다** — 상태색은 의미에 고정하고 장식으로 쓰지 않는다. 색만으로 의미를 전달하지 않는다 — 반드시 텍스트 라벨 병기(색약·흑백 인쇄 대응).
4. **숫자는 정렬한다** — 금액·건수는 `font-variant-numeric: tabular-nums` + 우측 정렬. 천 단위 콤마.
5. **화면 실행 중 외부 자산 요청 0** — 번들에 포함된 shadcn·Radix·Lucide·Recharts·Sonner와 동봉 vendor(`harness/vendor/`)만. 외부 CDN·외부 웹폰트·아이콘폰트 금지(오프라인 샌드박스에서 죽는 지점은 외부 요청이다).

## 인터랙션·차트 규율

판단 기준 하나: **현업 엔지니어의 클릭·판단을 줄이는가.** 보여주기 위한 움직임은 전부 감점 신호다.

**넣을 값어치 있는 것 (선택지)**
- **접힘 섹션** — 보조 정보(제외된 건·상세 로그)는 shadcn Collapsible.
- **정렬·필터 토글** — 큐가 20건 넘으면 유형별 필터가 클릭을 줄인다. 토글 상태는 URL이나 화면에 보이게.
- **행동 버튼 + 즉답 피드백** — "복사" 누르면 라벨이 "복사됨 ✓"으로 1~2초. shadcn은 동봉 Sonner. 성공 표시는 실제 처리 완료 뒤에만.
- **행 hover 하이라이트 · 행 클릭 상세** — 상세는 drawer/sheet로 맥락 유지, 짧은 입력은 dialog, 영향 있는 실행 확인은 alert-dialog. `harness/starter/shadcn/INTEGRATION.md`의 재사용 부품을 먼저 쓴다.
- **차트** — 아래 규율로, 필요할 때만. **숫자가 3~4개면 차트가 아니라 스탯 바가 이긴다.**

**차트 규율 (쓸 때)**
- 차트는 번들 Recharts. Chart.js 등 외부 요청 금지.
- 허용: 막대·선/면·100% 누적 막대·히트맵·진척 막대·퍼널·간트 간이판·노드 그래프(위젯 W1~W19). 금지: 3D·도넛·파이·그라데이션 채움·카운트업. 색은 토큰만 — 기본 회색, **강조는 딱 하나**(`--skh-data-accent`, 문제의 막대만 상태색). 히트맵은 sequential 단색 농도 + 칸 수치.
- W17 AI 대화창: 말풍선은 AI = `muted` 배경, 사용자 = 기본(검정) — 원본 톤 그대로, 장식·아바타·글자 효과 없음. 응답 옆에 「AI 응답」/「모의 응답」 배지를 항상 둔다. 질문 칩·입력칸에 설명 캡션·지시형 문구를 붙이지 않는다.
- 축·단위 라벨 필수, 숫자는 tabular-nums. 범례가 필요하면 차트가 너무 복잡한 것.

**모션 한도**: 상태 전환(hover·접힘·나타남)만 100~150ms ease-out. `prefers-reduced-motion` 존중. 그 외 움직임 0. 쓸 수 있는 것은 `sk-theme.css` 「움직임」의 세 가지뿐이다 — 새로 만들지 않는다.
- 화면 안내(`widgets/tour.tsx`)의 밝은 칸과 설명 카드는 단계 사이를 150ms 로 옮겨 간다.
- `<Reveal open>`(`widgets/parts.tsx`) — 펼침·접힘 150ms. 조건에 따라 나타나는 입력 칸(결정 바의 사유), 트리 가지, 닫히는 알림 띠.
- `className="sk-fade"` — 내용이 통째로 바뀐 자리가 150ms 로 나타난다(지표를 바꾼 차트). `key` 를 바꿔 다시 그릴 때만.
- 로그인·로그아웃 전환 화면(`lib/transition.ts`) — **예외(1초)**: 누른 순간부터 최소 1초 동안 같은 화면을 덮어 새로고침 깜박임을 가린다. 다른 곳에 일부러 기다림을 넣지 않는다.
- `className="sk-flash"` + `useFreshIds(ids)` — **예외(1.2초, 1회)**: 방금 저장돼 새로 생긴 행을 옅게 강조했다가 푼다. 「내 결정이 여기 남았다」를 보이는 용도 — 결정 기록·저장된 판정 목록처럼 저장 직후의 행에만.

**머리줄과 AI 대화 패널**
- 머리줄에는 화면 이름 · 데이터 기준 시각 · AI 대화 버튼만 둔다. 같은 곳으로 가는 길을 여러 개 만들지 않는다(이동 = 사이드바 · 할 일 = 본문 안 버튼).
- AI 대화는 덮는 창이 아니라 **머리줄 아래, 화면 오른쪽에 고정된 별도 카드**다. 머리줄을 덮지 않고 위·아래·오른쪽에 여백을 둔다. 본문이 스크롤돼도 입력창은 제자리에 있고, 열리면 본문이 그만큼 좁아진다. 맨 아래에 「AI 연결됨 / 모의 응답」이 항상 보인다. 사용자는 화면의 숫자를 보면서 묻는다. 응답에는 「AI 응답」/「모의 응답」 배지가 항상 붙는다.

**화면이 흔들리지 않게**
- 무엇을 열고 닫아도, 내용이 길어지고 짧아져도 본문이 옆으로 밀리면 안 된다. 스타터는 스크롤바 자리 고정과 스크롤 잠금 여백 되돌리기를 한 쌍으로 걸어 두었다(`sk-theme.css`). 겹쳐 뜨는 부품을 새로 넣으면 열기 전후에 머리줄 제목의 위치가 그대로인지 본다.
- 조건에 따라 나타나는 칸은 아래 내용을 툭 밀지 않게 `<Reveal>` 로 펼친다.

**화면에 쓰는 글**
- 긴 줄표(—)를 문장에 쓰지 않는다. 「이름: 설명」은 쌍점, 이어지는 말은 마침표나 쉼표로 가른다. 값이 없는 칸의 `—` 한 글자만 예외다.
- 낱말 중간에서 줄이 바뀌지 않게 한다. 화면 전체에 `word-break: keep-all` 이 걸려 있다(`sk-theme.css`). 새 부품에 `break-all` 을 쓰지 않는다. 제목은 줄 길이를 고르게, 본문은 마지막 줄에 한 낱말만 남지 않게 되어 있다.
- 만든 사람이 할 말(가정·한계·개발 메모)을 사용자 화면 본문에 두지 않는다. 한계는 도움말에, 가정은 그 숫자의 근거 꼬리표에 둔다.

**메뉴와 화면 안내**
- 왼쪽 메뉴 = 설계 때 정한 화면 목록 그대로. 등록은 `src/lib/pages.ts` 의 `SCREENS` 한 곳(INTEGRATION.md 「화면 더하기·빼기」). 한 화면에 다 밀어 넣지 않는다 — 하는 일이 다르면 화면을 나눈다.
- 개발용 카탈로그(`#/widgets`)는 만드는 동안에만 메뉴에 보인다(`.env.local` 의 `VITE_DEV_MENU=1`). 제출 전에 그 줄을 지우고 다시 빌드한다. 「빠른 등록」 버튼은 필요한 서비스에서만 켠다.
- **화면 안내(온보딩)를 과제에 맞게 고친다**(`src/lib/tour-steps.ts`). 처음 들어온 사람이 무엇부터 보고 어디서 결정하는지를 5~7단계로 — 결정하는 자리와 결과를 검토하는 자리는 꼭 넣는다.
- 지표의 증감은 방향(▲▼)이 아니라 **좋아졌는지 나빠졌는지**로 색을 가른다: 개선 = 채운 중립 배지, 악화 = 위험색. 글자(개선·악화)는 항상 같이 쓴다. 카드 배경은 단색.

**헷갈리는 것 가르기**
- 접기: 묶음 여러 개를 하나씩 = U1 아코디언 · 한 덩어리만 = Collapsible · 관점 전환 = U2 탭 · 순서 있는 절차 = U3 단계 표시.
- 한 건 자세히: 잠깐 보고 닫는다 = 상세 드로어 · 목록과 나란히 비교한다 = U12 분할 패널 · 주소가 필요하다 = 상세 페이지(`#/item`).
- 알림: 화면 전체에 걸린 상태 = U9 알림 띠 · 방금 한 행동의 결과 = 토스트 · 한 건의 상태 = 배지.
- 기다림: 1초 넘는 요청에만 U10 로딩 뼈대. 바로 뜨는 데이터에는 쓰지 않는다(아래 금지).
- 거르기: 조건이 한두 개로 고정 = 목록의 공통 필터 · 값이 몇 개로 정해진 열에서 여러 개 고른다 = U17 다중 선택 필터 · 사용자가 「열·비교·값」 조건을 쌓는다 = U8 조건 필터.
- 묶음 나누기: 2~5개 = U2 탭 · 4개 넘고 묶음마다 폼이 길다(설정) = U13 세로 탭 레이아웃.
- 고르기: 켜고 끄기 = U14 설정 행(바로 적용) 또는 Checkbox(저장 버튼이 따로) · 여럿 중 하나인데 글자로 충분 = RadioGroup·Select · 미리보기가 있어야 차이가 보인다 = U15 선택 카드.
- 목록 모양: 열로 비교한다 = 표 · 항목마다 설명이 필요하다 = U18 카드 격자.
- 차트: 지표가 여러 개인데 차트 자리는 하나 = V1 · 숫자의 근거를 물을 것 같다 = V4(차트↔표) · 변화의 이유가 되는 사건이 있다 = V5 · 기준값이 있는 지표 = V7(기준은 설정 화면과 같은 숫자).
- 카드가 많아진다: 같은 대상을 다른 기준으로 나눈 카드들 = V2 로 하나에 · 카드에 다 못 담은 행 = V3 크게 보기(주소가 필요하면 「자세히」 링크로 목록 페이지).
- 못 보여 줄 때: 페이지 전체 = U19 상태 화면(없는 주소·권한 없음·오류·점검 중·내용 없음) · 카드 하나 = 그 카드 안의 빈 상태 문장.

**검토 부품을 두는 규칙 — 계산·배정·분석 결과를 보여 주는 화면에는 빠짐없이**
1. 새 결과는 **지금 운영 중인 것과 나란히**(R1). 새 결과만 보여 주면 승인하는 사람이 판단할 기준이 없다.
2. 평균만 보이지 않는다 — **가장 나빠지는 건**을 같이(R2).
3. 계산에 넣지 않은 기록은 **건수와 이유**로(R3). 0건이어도 「뺀 기록 없음」을 적는다.
4. 부서마다 뜻이 다를 수 있는 지표·용어에는 **정의·단위·산식**(R4). 숫자가 외부 자료에서 왔으면 **출처·기간·기준·상태**(R5) — 확정과 잠정, 우리가 환산한 값을 구분한다.
5. 자료마다 숫자가 다르면 하나로 뭉개지 않고 **나란히**(R7). 여러 대상×여러 기간 비교는 R6 에 「무엇을 맞췄는지」를 적어서.
6. 판정 낱말은 과제의 말로 — 결정 바(D4)의 `options`(통과·재작업·보류, 승인·조건부 승인·반려). 흐름·공급망 그래프에서 「여기가 막히면」은 노드 그래프의 `blocked`.

**결정 부품을 두는 규칙 — 사람이 결과를 확정하는 화면에는 빠짐없이**
1. AI·솔버가 낸 제안에는 **D4 결정 바**를 붙인다. 제안 문장 · 신뢰도(글자로) · 근거(접힘) · 승인/수정/반려. 수정·반려는 사유가 필수다. 「AI 제안」과 「사람의 결정」이 한 화면에서 구분돼 보여야 한다.
2. 결정은 **D5 결정 기록**에 누가·언제·무엇을·왜로 쌓인다. 기록을 고치거나 지우는 버튼을 만들지 않는다.
3. 효과·금액·비율 숫자에는 **D1 근거 꼬리표**를 붙인다. 측정 = 실제 데이터로 잰 값, 예측 = 계산·모델이 낸 값, 가정 = 사람이 둔 값. 예측과 가정을 측정처럼 보이게 두지 않는다.
4. 제안을 적용하면 바뀌는 것은 **D2 비교**로, 나빠지는 항목도 같은 표에 둔다. 제안이 나온 과정은 **D3 거친 단계**로, AI 가 맡은 단계와 규칙·솔버가 맡은 단계를 구분한다.
5. 저장이 끝나기 전에 성공을 표시하지 않는다. 쓰기 권한이 없는 계정에는 제안과 근거만 보인다(`canDecide`).

## 금지 (슬롭 신호 — 운영 도구에서 즉사)

- 그라데이션 · 장식 그림자 · 이모지 아이콘 남발 (신호를 흐린다)
- 마키·캐러셀·자동 슬라이드 (읽는 속도를 도구가 정하는 것)
- 3D·파티클·틸트·패럴랙스 (판단에 기여 0, 성능 비용만)
- 스크롤 트리거 리빌 · 숫자 카운트업 애니메이션 (두 번째 볼 때부터 대기 시간)
- hover 시 카드 떠오름(translateY+그림자 확대) — AI 상투형 대표
- 스켈레톤 쉬머 남발 (로컬 데이터엔 로딩이 없다)
- 다크모드 (범위 밖)

예외를 열면 `docs/DECISIONS.md`에 한 줄 — 이유 있는 추가는 감점이 아니라 의도 관리 가점.

## 도구 판정

| 도구 | 판정 | 이유 · 예외 조건 |
|---|---|---|
| **Tailwind + shadcn/ui** | **채택 — 화면 기본(npm 이 될 때)** | `bash harness/starter/shadcn/make.sh` 로만 세운다(Vite+React+Tailwind+shadcn+우리 overlay+SK 색). **10분 안에 안 되면 멈추고 사용자에게 알린다**(화면 없이 API·CSV 출력), `docs/DECISIONS.md` 에 선택 한 줄. 생성물을 통째로 제출물로 두지 않는다 — 문구·데이터·판정 로직은 우리 것(`src/`)으로 바꾼다 |
| **React/Vite** | 조건부 | 과제 스캐폴드가 React 로 오면 그 위에 얹는다. 우리가 새로 깔 때는 위 `make.sh` 로만 |
| **Chart.js / D3** | 기각 | 번들 Recharts·손 SVG로 충분. 예외 없음 |
| **three.js** | 기각 | 판단 화면에 3D가 기여하는 경우 없음. 예외: 과제가 진짜 공간 데이터이고 2D 평면도로 부족함이 과제 원문·데이터로 확인될 때만 — DECISIONS에 기각한 2D 대안 명시 |
| **폰트/아이콘** | 동봉 채택 | Pretendard와 번들 Lucide. 아이콘 단독 버튼에는 접근 가능한 이름을 붙인다 |
| **getdesign.md** | 조건부 | 도메인에 더 맞는 디자인 언어가 필요할 때만 `npx getdesign@latest add <이름>`, 이유 한 줄을 `docs/DECISIONS.md`에 |

판단 원칙: 이미 검증한 shadcn 부품·데이터 연결을 먼저 쓴다. 추가 라이브러리는 기존 부품으로 못 하는 이유와 설치·검증 비용을 확인해 결정한다.

## 운용

- 첫 화면도 기본은 `make.sh` 생성 화면이며, 필요한 페이지·위젯만 남긴다(npm 이 막혀 설치가 실패하면 화면 없이 API·CSV 출력으로 간다 — 위 출발점 문단과 같다) — 디자인 고민 0분으로 "거칠지 않은 기본"을 확보하고, 폴리싱은 마지막(얇은 결과 먼저).
- 최종 전 사람 눈 확인 1회: "처음 30초에 오늘 뭘 할지 보이는가" — 안 보이면 스타일이 아니라 **정보 배치**를 다시 짠다.
