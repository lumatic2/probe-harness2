## 시간 기준선 (참고 — 규칙이 아니다. 실제 시각은 `docs/PLAN.md` 1절)
이 시각쯤 이 일을 하고 있으면 원활하다는 표시다. 실제 제약은 과제설정 4절 종료 시각 하나다. 늦어도 오케·DM·워커는 스스로 자르거나 경고하거나 단계를 넘지 않는다. 사용자가 설명 탭에 「잘 되고 있어?」류로 물으면 설명 탭이 현재 시각과 이 표로 설명한다.

| 이쯤 끝나면 원활 | 신호(사용자가 친다) | 종료 N분 전 | 태그 |
|---|---|---|---|
| M0 세팅 · M1 과제설정 | 「DM 시작하자」 | 310 | `scaffold` · `config` |
| M1 실무자 대화 | 「문제 확정」(DM 탭) | 275 | `define` |
| M2 조사 · 솔루션 논의 · 솔루션 브리핑 | 「OK」 | 240 | |
| M2 솔루션 DM | 「솔루션 확정」(DM 탭) | 225 | `solution` |
| M3 설계 논의 · 스캐폴드 · 브리프 | 「설계 OK」 | 200 | `design` |
| M4 첫 화면 · 얇은 결과 시연 | 「피드백 DM 시작하자」(QA 와 겹쳐 돌아도 된다) | 140 | |
| M4 구현 · 사용자 QA · 수정 | 「구현 끝」 · 「QA 끝」 | 100 | `build` |
| M5 피드백 · 수정 | 「피드백 끝」(DM 탭) | 60 | `feedback` |
| M6 점검 기준 고정 · 점검 · 제출 문서 · 평가와 수정 → `final` | (오케 커밋) | 30 | `final` |
| M6 한 바퀴 묻고 답하기 | (설명 탭) | 20 | |
| 여유(아무 일도 잡지 않는다) | 「제출하고 문제풀기」 | 20→0 | |

위 숫자는 제한 330분을 **어림으로** 넣어 본 것이다(09:30 시작에 과제 종료를 15:00 쯤으로 짐작 — 종료 시각과 후속 서술형이 언제인지는 공지된 적이 없다). 실제 제한은 당일 공지대로 과제설정 4절에 적고, 이 표는 그 값에 맞춰 같은 비율로 다시 계산한다. 마지막 20분은 어떤 제한에서도 여유로 남긴다.

줄일지는 사용자가 정한다. 줄이기로 하면 순서: ① 추가 조사 ② 디자인 ③ 부가 기능. MUST 는 안 자른다. 버린 것은 `$decision` 과 실행 안내 「안 된다」에.
