# 지도 — 폴더와 시간 기준선 (오케·DM·통합이 읽는다. 워커는 브리프가 경로를 준다)

> `AGENTS.md` 에서 떼어 낸 참조표. 규칙이 아니라 지도다 — 이번 과제의 값은 `docs/과제설정.md`.

## 시간 기준선 (참고 — 규칙이 아니다. 실제 시각은 `docs/PLAN.md` 1절)
이 시각쯤 이 일을 하고 있으면 원활하다는 표시다. 실제 제약은 과제설정 4절 종료 시각 하나다. 늦어도 오케·DM·워커는 스스로 자르거나 경고하거나 단계를 넘지 않는다. 사용자가 설명 탭에 「잘 되고 있어?」류로 물으면 설명 탭이 현재 시각과 이 표로 설명한다.

| 이쯤 끝나면 원활 | 신호(사용자가 친다) | 종료 N분 전 | 태그 |
|---|---|---|---|
| M0 세팅 · M1 과제설정 | 「DM 시작하자」 | 165 | `scaffold` · `config` |
| M1 실무자 대화 | 「문제 확정」(DM 탭) | 140 | `define` |
| M2 조사 · 설계 · 솔루션 브리핑 | 「OK」 | 120 | |
| M2 솔루션 DM | 「솔루션 확정」(DM 탭) | 110 | `solution` |
| M3 첫 화면 · 얇은 결과 시연 | 「피드백 DM 시작하자」 | 80 | |
| M3 구현 · 사용자 QA | 「구현 끝」 · 「QA 끝」 | 60 | `build` |
| M4 피드백 | 「피드백 끝」(DM 탭) | 40 | `feedback` |
| M5 동결 · 점검 → `final` | (오케 커밋) | 20 | `final` |
| 여유 | 「제출하고 문제풀기」 | 20→0 | |

줄일지는 사용자가 정한다. 줄이기로 하면 순서: ① 추가 조사 ② 디자인 ③ 부가 기능. MUST 는 안 자른다. 버린 것은 `$decision` 과 실행 안내 「안 된다」에.
