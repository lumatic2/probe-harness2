# M1 — 실무자 대화: DM 시작 · DM 이 도는 동안 (오케)

M1 핵심 4줄(목표·종료 조건·담당·증거)은 `M1-과제설정.md` 머리.

## 「DM 시작하자」
1. **DM 에 넘기기 전 마지막 손질** — PROBLEM 첫판은 「과제 시작하자」 때 이미 썼다. 그 뒤 생긴 것을 지금 넣고 커밋한다: 사용자가 채팅에서 덧붙인 것(`[사용자]`) · 그사이 도착한 서브에이전트 결과의 「물을 것 후보」(7절 해당 주제 아래). 데이터 서브 결과(`docs/research/데이터.md` · `docs/experiments/profile.py`)가 와 있으면 「구조 한 장」을 ARCHITECTURE 3절 초안으로 옮겨 이 커밋에 함께 넣는다. 이 커밋 뒤로 PROBLEM 은 DM 것이다 — 이후 도착분만 queue 로 보낸다.
2. DM 탭 안내 한 줄: `새 탭 → codex → /permissions Full Access → /model → 「harness/roles/DM.md 읽고 DM 담당으로 시작해」 → 탭 이름 DM`. 실무자 회신은 DM 탭에 붙이고, DM 이 쓴 루트 `보낼글.txt`(대화 상대가 여럿이면 `보낼글-<이름>.txt`)를 실무자 패널에 붙인다고 알린다.
3. 이 순간부터 M1 동안 PROBLEM 은 DM 이 고친다. 오케는 고치지 않는다.
4. 2 의 안내를 **중간 응답으로 먼저** 내보낸다(마지막 줄 `다음 입력(DM): harness/roles/DM.md 읽고 DM 담당으로 시작해`). 턴은 끝내지 않는다 — 아래 「DM 이 도는 동안」 ①·② 를 **이 턴에서** 한다. 턴을 끝내면 다음 입력이 올 때까지 아무것도 못 하므로 빠뜨린다.

## DM 이 도는 동안
①·② 는 「DM 시작하자」 턴 안에서 한다: ① 확인 → ② → 턴 끝내기 전에 데이터 결과를 한 번 더 확인 — 아직 돌고 있으면 `wait_agent` 를 긴 timeout 으로 한 번 걸고 받은 결과를 ① 대로 처리한다(턴이 끝나면 완료가 오케를 깨우지 않아 문제 확정 뒤에야 보인다). (M1 에 리서치 서브에이전트는 없다 — 실무자에게 물을 재료는 원문·데이터·`PROBLEM-TYPES.md` 카드 ⑤⑥ 이고, 오케가 첫판 7절에 이미 넣었다.) 그 뒤엔 할 일이 없으면 기다린다. 바쁘게 보이려고 일을 만들지 않는다.
- ① **데이터 서브에이전트 결과 확인** — 1 에서 아직 안 왔던 `docs/research/데이터.md` 가 이제 왔으면 「실무자에게 확인할 것」을 DM 탭에 queue(`[오케→DM] docs/research/데이터.md 「실무자에게 확인할 것」 — 7절 해당 주제에, 실무자 말로`), 「구조 한 장」을 ARCHITECTURE 3절 초안으로 옮겨 결과 파일과 함께 커밋한다. 세팅 때 못 띄웠으면 지금 띄운다(`harness/roles/데이터.md`).
- ② 방향과 무관한 PLAN 2절(요구·제약 추적 표) 뼈대 — 요구 R 행만 옮긴다(출력 계약 규칙 포함). C·G·S 행은 M2 조사가 도는 동안 더한다.
- ②-2 **화면 골격을 지금 세운다**(과제가 화면·웹서비스를 요구할 때 — 과제설정 2절): 스캐폴드 서브에이전트 하나에 `bash harness/starter/shadcn/make.sh src/ui` 만 시킨다(10분 넘으면 멈추고 보고 · npm 이 막히면 화면 없이 간다고 보고 — `harness/guides/DESIGN.md`). `wait_agent` 로 기다리지 않는다 — 결과는 다음 턴에 확인해 `src/ui/` 를 커밋한다. 이래야 M3 화면 설계 때 `#/widgets` 카탈로그를 볼 수 있고, 「설계 OK」 뒤 워커가 기다리지 않는다.
- ②-3 **Browser 미리 한 번 열어 보기**(②-2 를 띄웠을 때) — 이 턴 끝에 사용자에게 한 줄: `화면 골격이 서면 Browser 가 열리는지 미리 봅니다 — DM 답을 기다리는 틈에 오케 탭에 「화면 확인」을 쳐 주세요`. 「화면 확인」을 받으면: ① 스캐폴드 결과를 확인해 `src/ui/` 를 커밋(아직 안 끝났으면 `wait_agent` 긴 timeout 한 번) ② 빌드본 서버를 뒤에서 띄운다(`cd src/ui && nohup node node_modules/vite/bin/vite.js preview > /tmp/preview.log 2>&1 & echo $! > /tmp/preview.pid` — 개발 서버 아님. npx 로 띄우지 않는다: 끌 때 진짜 서버가 남아 포트 3000 을 쥔다) → **명령을 따로 한 번 더 돌려** 살아 있는지 본다(`ss -ltnp | grep ':3000'` 에 `0.0.0.0:3000` 이 보이고 — `ss` 가 없으면 건너뛴다 — `curl -s http://127.0.0.1:3000/api/health` 가 응답 — 띄운 명령이 끝나면서 뒤에서 돌던 서버가 같이 죽는 환경이 있다). 죽어 있으면 사용자에게 `새 터미널 탭(codex 를 켜지 않은 탭) → cd src/ui && npx vite preview → 탭 이름 서버 — 이 탭은 닫지 않습니다` 를 안내하고 그 서버로 본다(이 경우 ④ 에서 끄지 않고 M4 통합 워커가 이어 쓴다 — 과제설정 3절에 `서버는 사용자 서버 탭에서 돈다` 한 줄) ③ 사용자에게 `Browser 포트 칸 3000 · 경로 칸 / — 첫 화면이 보이면 「보인다」, 흰 화면·오류면 보이는 글자 그대로` ④ 「보인다」면 `kill "$(cat /tmp/preview.pid)"` 로 자기가 띄운 서버만 끄고 `curl -s -m 2 http://127.0.0.1:3000/api/health` 가 응답하지 않는 것을 확인한 뒤(포트 3000 은 M4 에 통합 탭이 쓴다) `docs/과제설정.md` 3절에 `Browser 확인 HH:MM — 포트 3000 · 경로 / 로 스타터 첫 화면 보임` 한 줄 ⑤ 안 보이면 사용자가 붙여 준 글자로 먼저 가른다 — **「응답하는 서버가 없어요」·연결 안 됨 류** = 서버가 그 포트에 살아 있지 않다(죽었나 · 포트가 다른가 · `127.0.0.1` 에만 붙었나 → ② 의 확인을 다시) · **`Blocked request … host`** = Host 접미사(`/tmp/preview.log` 에서 접미사를 읽어 `ALLOWED_HOSTS` 로) · **흰 화면** = `harness/guides/BROWSER.md` 「흰 화면이면」 순서 — 원인과 고친 것(바꾼 환경변수·명령)을 과제설정 3절에 적어 통합 브리프(M3)에 그대로 들어가게 한다. 못 고치면 사용자에게 「화면 없이 갈지」를 묻지 않고 원인 후보와 남은 확인을 한 줄로 알리고 DM 을 막지 않는다. 사용자가 「화면 확인」을 안 치면 문제 확정 턴 끝에 한 번 더 한 줄로 알린다(강제하지 않는다).
- ③ (그 뒤, 있을 때만) 데이터와 실무자 말이 어긋나는 곳을 발견하면 사용자에게 말한다. 사용자가 DM 탭에 전한다.

**DM 에 보내는 queue 는 `docs/세션.txt` 에 DM 줄이 생긴 뒤에 보낸다** — 사용자가 아직 DM 탭을 안 열었으면 들고 있다가 다음 입력 때 보내고, 그 사실을 턴 끝에 한 줄로 말한다.

DM 상황이 궁금하면 `docs/PROBLEM.md` 7절을 읽는다. DM 이 종료 브리핑 뒤 사용자 「확정」을 받으면 `[DM→오케] 문제 확정` 을 queue 한다 → `M2.md`.
