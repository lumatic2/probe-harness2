# BROWSER.md — 플랫폼 Browser 미리보기 연결법

> 플랫폼 안내 「Browser에서 서비스 확인」과 확인된 경로를 합친 것. 통합 워커가 서버를 띄우기 전에 읽고, 오케가 사람에게 안내할 때 읽는다.

## 성공한 방법 — 빌드된 화면 + API 를 한 서버로
1. 화면은 **빌드**해서(`npm --prefix src/ui run build`) 정적 파일로 두고, API 서버가 그 파일을 같은 포트에서 함께 제공한다. 서버는 **`0.0.0.0:3000`** 에 바인딩한다(`localhost`/`127.0.0.1` 만 붙이면 미리보기가 연결되지 않는다). 포트 충돌 시 다른 포트로 자동 이동하지 않는다.
2. **개발 서버(Vite dev)를 미리보기에 직접 노출하지 않는다.** 플랫폼 Browser 는 다른 Host 로 요청하는데 개발 서버는 이를 403 으로 거절한 적이 있다. 개발 중 화면 확인은 빌드 후 같은 서버에서 한다. 화면 코드를 바꾸면 다시 빌드해야 반영된다.
3. 서버를 띄운 터미널 탭은 **닫지 않는다**(탭을 닫으면 프로세스도 죽는다). 서버 전용 탭 이름 `서버`, 통합 워커 소유. control+C 는 서버를 끈다(복사는 ⌘C).
4. 서버와 사용자 접근은 **따로** 확인한다: `curl http://127.0.0.1:3000/api/health` 응답은 API·DB 근거, **사용자가 Browser 에서 로그인 화면을 본 것**이 화면 근거. 로그인 화면 표시와 로그인 성공·전체 흐름은 또 다르다.

## 사람에게 주는 안내 (한 덩어리)
| 항목 | 값 |
|---|---|
| Browser 포트 칸 | `3000` |
| 경로 칸 | 빈칸 또는 `/` (하위 화면은 `/#/list` 식 — **전체 URL 금지**) |
| 적용 | Browser 의 원형 새로고침 버튼 |

- `http://localhost:3000/` 전체를 경로 칸에 넣으면 `/http://localhost:3000/` 라는 잘못된 경로가 된다. 포트는 따로 지정되므로 `/` 가 앱 루트다.
- 응시 화면 안의 Browser 만 쓴다. 외부 브라우저·새 탭·응시 페이지 전체 새로고침으로 바꾸지 않는다(감독 규칙).
- 눌러 볼 순서 3~5개 표(입력값 · 행동 · 예상 결과 · 요구 ID)와 두 역할의 로그인 계정 **이름**(값은 `.env.example` 참조)을 같이 준다. 샘플 화면과 실제 데이터로 도는 화면을 구분해 말한다.
- 「포트 N 에 아직 응답하는 서버가 없어요」는 서버 시작 전에도 뜬다. 서버가 준비되면 새로고침을 다시 누른다.

## 흰 화면이면 — 이 순서로 가른다
입력(포트·경로) → 리스너(`ss -ltnp` 또는 `curl 127.0.0.1:3000/`) → HTML/자산/API 각각(`curl -H "Host: 임의" …` 로 다른 Host 응답) → 실제 Browser 요청·콘솔 → Host·iframe 헤더(CSP · X-Frame-Options). CSP·Host 허용을 근거 없이 전체 해제하지 않는다. 모든 흰 화면의 원인이 개발 서버였다고 단정하지 않는다.

## 다른 장애와 섞지 않는다
- 플랫폼 **모델 게이트웨이 401**(`gateway_token_invalid` 류)은 Browser 와 무관한 장애다. 시각·코드·경로·영향을 비밀 없이 **신고**만 한다. 앱 `.env` 를 바꾸거나 토큰을 출력하거나 재시도를 반복하거나 플랫폼 서비스를 재시작하지 않는다. 앱 로그아웃 상태의 `/api/me` 401 과도 다르다.
- 터미널 연결이 끊기면 터미널의 「다시 연결」, 안 되면 `+` 로 새 터미널. 미리보기가 멈추면 우측 상단 CPU/RAM 부터 본다 — 탭·서버를 너무 많이 띄워 생긴 OOM 은 구제 대상이 아니다. 쓸모없어진 탭·서버는 닫는다.

## 당일 첫 서버를 띄울 때 확인
- 서버 탭을 백그라운드로 돌릴 수 있는지(`&`·`nohup`) — 안 되면 탭 하나를 서버에 내준다.
- 사용자가 첫 화면을 본 시각을 PLAN 1절 「얇은 결과 시연」 실제 시각에 적는다.
