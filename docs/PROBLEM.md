# PROBLEM.md — 문제 정의서

> 「과제 시작하자」 때 오케가 원문·데이터로 첫판을 쓴다. M1 동안은 **DM 탭이 소유**하고 실무자 답마다 바뀐 줄만 고친다. DM 이 종료 턴에 `python3 harness/tools/problem_check.py` 통과까지 정리하고, 「문제 확정」 때 오케가 읽는다. 확정 시각: (    )
> **출처 태그 — 모든 줄 끝에 하나**: `[README:줄]` `[<파일>:줄]` `[답변N]` `[사용자]` `[짐작]`. `[짐작]` 은 실무자 확인 전까지 설계 근거로 쓰지 않는다.
> **현재 상태만 적는다** — 줄 하나 = 사실·규칙·숫자·결정 하나. 대화 경과·「수용 아님」「대기」 같은 상태 서술은 쓰지 않는다(경과는 `docs/interview/`). 정정은 `~~옛 내용~~ → 새 내용 [답변N]` 한 번 — 가설이 어떻게 바뀌었는지가 서술형 재료다.

## 0. 한눈에
채우는 지침: 누가 무슨 일로 곤란한가 · 왜 지금인가 · 안 풀면 무엇이 비싼가 · 지금 가장 큰 미확인 1개. 줄 수 제한 없음. **맨 위 세 줄은 이 순서로**(DM 이 종료 정리 때 완성한다 — 실무자에게 「지금은 왜 그렇게 하시나」를 물어 얻은 것): `지금 방식: …` · `우리가 던진 질문: …` · `그 질문이 바꾼 문제 정의: …`. 과제 문구 그대로면 셋째 줄에 「바뀐 것 없음」이라고 적는다(지어내지 않는다).
-
