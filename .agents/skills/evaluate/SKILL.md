# evaluate — 블라인드 채점 (M6, 서브에이전트)

> **띄워졌다면**: 이 파일 + `harness/guides/RUBRIC.md` + 아래 「공통 입력」만 읽는다. `docs/judge/` 의 결과 문서 외에는 쓰지 않고 커밋하지 않는다. 마지막 메시지는 결과 문서 경로 + 결론 3줄.

**이 세션은 만든 세션이 아니다.** 제작 의도를 묻지 말고 파일·세션 로그·커밋·테스트 기록만으로 판정한다. **블라인드 = 제작 세션의 맥락을 물려받지 않는다는 뜻이다** — 세션 로그는 읽되 「AI 가 혼자 정한 것과 사용자가 바꾼 것」의 증거로만 쓴다. 기준은 실제 심사보다 높게 — 애매하면 감점. 결과는 `docs/judge/평가-<HHMM>.md`(시각은 `TZ=KST-9 date +%H%M`).

## 판정 범위

- 과제 README·실무자 합의에서 수용 기준을 먼저 추출하고 루브릭에 연결한다. RUBRIC 의 배점은 자체 점검용 참고값이고 확정 채점표가 아니다. 점수를 쓰면 **자체 점검용 추정**과 산출 근거를 명시하고 실제 점수 예측처럼 말하지 않는다.
- 기준 커밋과 시작 시 제품 변경 상태를 기록한다. 검사 중 제품이 바뀌면 영향 항목을 미확인으로 두고 새 기준에서 재검사한다. 문서 주장과 실행 증거를 구분하며, 로그가 없다는 이유만으로 실제 행동이 없었다고 단정하지 않는다.
- 제작 과정에 참여한 세션이면 블라인드라 부르지 않는다. 역할별 입력만 받은 새 세션에서 평가하거나 그 한계를 보고한다. 결과 문서 외 파일은 수정하지 않고 커밋하지 않는다.

## 공통 입력
**실제 평가 에이전트는 작업 폴더 전체와 세션 로그를 본다 — 같은 눈으로 본다.** 작업 폴더 전체(`메모.md` 제외) · `docs/세션.txt` · Codex 세션 로그(`~/.codex/sessions/` 에서 이 워크스페이스의 jsonl) · `git log --oneline`.
먼저 볼 것: `harness/guides/RUBRIC.md`(채점 4축 21항목·요건 단위 채점법) · `docs/과제설정.md`(원문 파일 목록·제출물 배치) · 과제 원문 파일 전부(출력 계약 포함). 나머지는 항목마다 필요한 곳을 연다. 테스트는 `docs/VERIFICATION.md` 에 적힌 실제 명령을 `harness/verify.sh` 로 감싸지 않고 직접 돌려 출력·종료코드를 자기 보고서에 남긴다(서버를 띄우면 `PORT=<빈 포트>` — 3000 은 통합 서버 탭).

## 절차 (M6, 보안·제출 점검과 병렬)
- 1단계 채점(아래 「결과 문서 양식」): `harness/guides/RUBRIC.md` 4축 21항목을 칸 단위로 채점하고(4축 「설득」은 서버를 띄워 받은 화면 응답과 제출 문서로 본다 — 화면을 직접 볼 수 없으면 그 칸은 「화면 미확인」으로 적는다. 4축은 배점이 없다 — 충족·부분이 아니라 「찼다 / 비었다」로만 적는다. 끝에 RUBRIC 6절 「행동 일곱 가지」를 행마다 「드러남 / 약함 / 안 보임 + 좌표」로 적는다) 「부분 충족」이 날 칸을 지목한다(실행 안내 「된다」 표 칸 ↔ 코드 줄 대조).
- 2단계 재평가: 점검 뒤 제품이 바뀌어 오케가 평가 서브에이전트를 새로 띄우면(`M6.md`) 점검 기준 커밋(`docs/VERIFICATION.md` 에 적힌 해시)과 수정 커밋의 `git diff` 로 **바뀐 부분만** 다시 판정한다.
- 3단계 전달: 결과 문서 경로를 마지막 메시지로 돌려준다.

## 결과 문서 양식 (오케는 이 문서만 읽고 지적마다 처분한다)

```
# 평가 — HH:MM (기준 커밋 <해시>)
## 결론 3줄
## 항목 판정
| 항목 | 요건 문장 | 판정(충족·부분·미충족) | 증거 좌표 | 빠진 것 |
(점수는 표 아래 한 줄로만)
## 지적 (심각한 순)
| ID | 심각도(상·중·하) | 근거 `파일:줄` | 무엇이 빠졌나 | 최소 수정 1줄 | 고칠 곳 | 실무자 확인 필요(예·아니오) |
## 부분 충족이 날 칸
```

지적 ID(`J1`…)는 오케의 `$decision` 이 가리키는 이름이다. 지적 수에 상한은 없고 심각한 순으로 쓴다.

## 규칙
- 칭찬·요약 없음. 지적마다 `파일:줄` 또는 커밋 해시.
- 오케는 결과를 받아 지적마다 검산하고 수용/기각을 `$decision` 으로 남긴다. 전면 수용 금지.
