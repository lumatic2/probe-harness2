# handoff — 세션 사이 전달과 이어받기

## 주소 — `docs/세션.txt`
- 탭 세션은 첫 행동으로 자기 줄을 더한다: `echo "<역할> $CODEX_THREAD_ID 탭 보고→<상대>" >> docs/세션.txt` (역할 = 오케 · DM · 설명 · 통합 · 검증 · 모듈 이름, 워커의 상대는 오케). 변수가 비어 있으면(`[ -n "$CODEX_THREAD_ID" ]` 실패) 등록하지 말고 사용자에게 「`/status` 의 thread id 를 알려 달라」 한 줄.
- **서브에이전트는 등록하지 않는다** — queue 가 아니라 부모 반환 채널을 쓴다. 끝난 서브에이전트에 queue 를 보내면 실패한다.
- 보낼 때는 이 파일에서 역할 이름으로 UUID 를 찾는다:
  ```bash
  codex queue --thread <상대 UUID> --message "[<나>→<상대>] <본문>"
  ```
- 「Queued message …」는 **접수**다. 반영은 상대의 답으로 확인한다. 답장은 턴이 끝난 세션도 깨운다.
- 탭을 닫을 때 그 줄 끝에 `(닫힘)` 을 붙인다(`sed -i 's/^<역할> \(.*\)$/<역할> \1 (닫힘)/' docs/세션.txt`). 닫힌 줄에는 보내지 않는다.
- 전송 실패(세션 없음 · 명령 오류)일 때만 `docs/mail/<상대>.md` 에 본문을 적고 사용자에게 `<상대> 탭에 「docs/mail/<상대>.md 읽어」 라고 쳐 줘` 한 줄. 정상일 때는 편지함을 만들지 않는다.

## 통제 메시지 전파 (오케) — 연장 · 중단 · AI 금지 시작 · 전체화면 경고
1. `docs/과제설정.md` 4절에 이력 한 줄(`[공지 HH:MM]`), PLAN 「시간 기준선」 재계산.
2. 세션.txt 의 `(닫힘)` 없는 줄 전부에 같은 본문을 queue: `[오케→전체] 통제: 종료 HH:MM 으로 변경 — PLAN 시간 기준선 반영됨`. 중단이면 `새 실행 시작 금지 · 미커밋 그대로 둘 것`.
3. 다음 응답에서 **반영됨 1회 확인**(과제설정 4절 「반영 확인」 줄). 「보냄」을 「반영됨」으로 말하지 않는다.

## 브리프 — 오케가 워커에게 (`docs/brief/<역할>.md` 파일, 5필드 — M3 「설계 OK」 때 쓰고 커밋한다. queue 로 보내지 않는다)
1. **목적과 요구·제약 ID** — 무엇을 왜, PLAN 2절의 R·C 번호(하드 제약은 빠뜨리지 않는다). 코어는 「계약 테스트 초록 → 전량 실행 → PLAN 5절 「전체 기간」 행, 다음 신호 없이 끝까지 — 멈춤은 계약 어긋남·하드 제약 깨짐·같은 원인 2번 실패만」. 엣지 대처는 SOLUTION 4절 표 그대로.
2. **소유 경로와 금지 경로** — 구현 워커는 `src/<모듈>/` · `tests/<모듈>/`. 통합 워커는 `scripts/run.sh` · `.env.example` · 서버 탭(포트 3000). 검증 워커는 `tests/e2e/` · `Dockerfile` · 실행 안내의 실행·테스트 절 재현. `tests/contract/`·다른 모듈·공유 문서 금지(예외: PLAN 5절 품질 비교표의 자기 행).
3. **계약 정본 절** — `docs/ARCHITECTURE.md` 2절 해당 행 · 3절 데이터 지도·계약 · 출력 계약 파일(과제설정 2절). 본문에 복사하지 않고 절을 가리킨다.
4. **검증 명령과 기대 결과** — `harness/verify.sh "<명령>"` 으로 돌릴 수 있는 명령과 기대. 지시보다 검증이 먼저.
5. **지킬 것** — 요구에 없는 기능 금지 · 계약 테스트 수정 금지(틀렸으면 보고) · 경계값·오류 입력 테스트 3개 이상 · 비밀값 금지 · 테스트는 실제 `.env`·운영 DB 에 기대지 않고 임시 DB·합성 계정을 주입 · 같은 원인 2번 실패면 멈추고 보고 · 완료 보고 형식(아래).

역할별 할 일(코어 · 화면 · 통합 · 검증 · 서비스)은 브리프에 옮기지 않고 `harness/guides/STAGES/M4.md` 「역할」의 자기 절을 가리킨다.

## 워커 — 시작 · 보고 · 커밋
- 시작: `AGENTS.md` · `docs/brief/<역할>.md` 읽기 → `docs/세션.txt` 등록 → 오케에 queue `[<역할>→오케] 준비됨 <내 UUID>`(등록 확인, 답을 기다리지 않는다) → 계약 절을 읽고 바로 시작한다. 브리프 파일이 없을 때만 「브리프 대기 중」 한 줄.
- 보고(queue)는 셋뿐 — 완료 1회 · 결정이 필요한 질문 · 새 오류. 항목과 꼴의 정본은 `harness/guides/STAGES/M4.md` 「공통」.
- 커밋: 자기 경로만 `git add` → `git commit -m "<무엇>" -m "<왜>"`. 다른 탭의 staged 파일이 보이면 멈추고 알린다.
- 마지막 사용자 표시: `■ <역할> 완료 — 오케에 queue 보냄 · 이 탭: 열어 둠(M5 끝까지 재지시용)`.

## 재지시 · 검수 (오케)
- 재지시는 같은 UUID 에 **변경점만**. 계약이 바뀌면 ARCHITECTURE 를 먼저 고치고 「n절 바뀜」을 보낸다. 실행 중인 지시를 덮어쓰지 않는다.
- 완료 보고는 검수 통과가 아니다. 오케는 워커가 붙인 검증 출력(계약 테스트 · `security_check.py`)을 **읽어** 검수하고, 직접 재실행은 같은 원인 2번 실패 뒤 1회(`docs/DECISIONS.md` D0). 핵심 흐름 실행은 통합 워커 E2E 로 한 번(`M4.md`).
- 같은 원인으로 2번 실패하면 브리프를 고쳐 다시 보낸다. 그래도 안 되면 새 탭에 새 브리프.

## 이어받기 — 컨텍스트가 찼거나 느려졌을 때
「context 많이 찼으니 새 세션에서 이어서 하자」·`$handoff`(위임 목적이 아닐 때)는 **세션 교체**다. 안전한 중단점에서 인계 파일을 쓰고 새 탭 문장을 출력한다.

**오케**: 먼저 **승계 선언** — 세션.txt 의 살아 있는 탭 전부에 `[오케→전체] 승계 시작 — 답 올 때까지 queue 금지, 급한 것은 docs/mail/오케.md 에 적을 것`. 그 뒤 쌓인 queue 와 `docs/mail/오케.md` 를 끝까지 소화한다(처리한 줄 끝에 `처리함 HH:MM`). 그리고 `docs/HANDOFF.md` 를 지금 기준으로 다시 쓴다(지금 어디(단계 · 마지막 커밋 · 과제설정 4절 시간) / 끝난 것(파일·증거) / 다음 할 일(첫 행동 한 줄) / 열린 질문·막힌 것(실무자 답 대기 · 사용자 결정 · 미처리 queue · 살아 있는 탭 목록)). 확인한 것만 적는다. 커밋 `handoff: <단계> — <한 줄>`. 새 탭 문장은 `harness/guides/편성.md` 「승계」. 새 오케는 `docs/mail/오케.md` 의 미처리 줄을 먼저 읽고, 세션.txt 의 오케 줄을 자기 UUID 로 바꾸고 살아 있는 탭 전부에 「오케 바뀜 <새 UUID> — queue 재개」를 queue 한다. **옛 오케 탭에 승계 뒤 도착하는 queue**(사용자 직접 입력이 쌓인 queue 보다 먼저 처리되므로 생긴다)는 행동하지 않고 본문을 `docs/mail/오케.md` 에 옮긴 뒤 「새 오케로 넘김」 한 줄만 답한다. 쌓인 queue 개수는 화면에 보이지 않는다.

**워커**: `docs/handoffs/<역할>.md` 에 같은 4절(+ 받은 브리프 요지 · 미커밋 파일 · 실행 중 서버). 오케에 경로를 queue 로 알리고 쓰기를 멈춘다. 새 탭 문장:
```
AGENTS.md와 .agents/skills/handoff/SKILL.md, docs/handoffs/<역할>.md 를 읽고 <역할> 워커를 이어받아
```
새 세션은 세션.txt 에서 옛 줄에 `(닫힘)` 을 붙이고 자기 줄을 더한 뒤 오케에 「이어받음」을 queue 한다.

**compact 만 할 때**: 오케는 `docs/HANDOFF.md` 만 갱신하고 `/compact`. 직후 `AGENTS.md` + `harness/roles/오케.md` + `docs/과제설정.md` + HANDOFF + 현 단계 파일을 다시 읽는다. 워커는 compact 대신 새 탭.

## 사용자에게 말할 것
누구에게 무엇을 맡겼나 · 완료 기준 · 사용자가 할 한 문장(새 탭 열기뿐). queue 가 성공했으면 사람에게 중계를 부탁하지 않는다.
