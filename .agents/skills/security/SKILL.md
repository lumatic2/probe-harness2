# security — 보안 점검 (제출물은 고치지 않는다 — 결과 문서만 쓴다)

> **M5 서브에이전트로 띄워졌다면**: 이 파일 + `AGENTS.md` + `docs/ARCHITECTURE.md` + `docs/과제설정.md`(5절 금지·허용) + 실행 안내 파일 + `src/`·`tests/`·`.env.example` + 의존성·실행 파일(`package.json`·잠금 파일·`requirements.txt`·`Dockerfile`·`scripts/`)만 읽는다. 결과 문서 `docs/security/M5.md` 하나만 쓰고 커밋하지 않는다. 마지막 메시지는 결과 문서 경로 + 결론 3줄. 처리는 오케가 한다.

제출물(코드·문서)은 고치지 않는다. 점검 결과만 `docs/security/M5.md` 에 쓴다 — 오케는 이 세션의 대화를 보지 않고 그 문서를 읽는다. 못 본 범위는 미확인으로 명시하며 검사한 것으로 처리하지 않는다.

**보안은 M5 에 처음 보는 것이 아니다.** 아래 7항목은 M2 설계(`docs/ARCHITECTURE.md` 5절)·M3 브리프 「지킬 것」·오케 검수에서 먼저 지킨다. 기계로 셀 수 있는 1·3·5·7번은 `python3 harness/tools/security_check.py` 가 매번 같은 명령으로 센다. M5 의 이 점검은 최종 확인이다.

## 점검 (각 항목에 통과/지적, 지적은 `파일:줄`)

0. **기계 점검 먼저**: `python3 harness/tools/security_check.py` 출력을 결과 문서 맨 위에 붙인다(FAIL 은 그대로 지적, 「확인 필요」는 아래 항목에서 판정).

1. **시크릿**: 기계 점검의 파일·줄 위치만 기록하고 값은 출력하지 않는다. `git status --short --untracked-files=all`로 미추적 제품 파일도 확인한다. 도구는 git 추적 파일 중심이고 ignored 파일·git 이력·키 변종을 모두 검사하지 못한다. 추가 검사는 일치 줄 전체 대신 경로·줄·종류만 출력하도록 작성한다. `.env` 실제 값은 읽어 채팅·보고서에 붙이지 않는다. 검사하지 못한 범위는 미확인으로 남긴다.
2. **입력 검증**: 파일 업로드·CSV 파싱·폼 입력에서 빈 값·형식 오류·초대형 입력·경로 조작(`../`)을 어떻게 받나. 깨지는 입력 1개를 실제로 만들어 돌려 본다(결과만 기록).
3. **외부 전송**: 코드가 바깥으로 요청을 보내는 곳(fetch·requests·curl) — 과제 데이터가 밖으로 나가는 경로가 있으면 **즉시 보고**(안내문: 외부 전송 금지·모니터링).
4. **의존성**: 새로 설치한 패키지 목록(`package.json`·`requirements.txt`)과 출처. 설치 없이 되는 것을 설치했나.
5. **권한·실행**: 셸 실행(`exec`·`subprocess`)에 사용자 입력이 들어가나. 서버가 `0.0.0.0` 에 열려 있으면 쓰기 엔드포인트의 인증/권한·입력 크기·허용 경로를 확인한다. CORS는 인증을 대신하지 않는다. 단일 사용자 데모라 인증이 없다면 접근 범위와 남은 위험을 적고 다중 사용자 안전성으로 주장하지 않는다.
6. **AI 호출**: 프롬프트에 원본 데이터 전체를 넣나(토큰·유출). 실패 폴백이 있나.
7. **제출물 위생**: 임시 파일·캐시·대형 데이터 복사본·`node_modules` 가 작업 공간에 남았나.

## 판정 기준

먼저 입력(폼·CSV·파일·AI 응답) → 처리 → 저장·화면·외부 요청의 경로를 실제 코드에서 찾는다. 이 경로에 없는 가상의 위협을 확정 결함으로 쓰지 않는다.
- 각 항목은 **통과 / 지적 / 미확인 / 해당 없음(이유)** 중 하나. exit 0은 패턴상 차단 항목이 없다는 뜻이며 보안 전체 통과가 아니다.
- 입력 검증은 실제 제품 진입점에서 정상 입력 1개와 위험 입력 1개를 비교한다. 기대 동작·실제 동작·실행 명령·종료코드·관련 경로를 적는다. 못 실행했으면 미확인이다. 서버를 띄워 볼 때는 `PORT=<빈 포트>` 로 — 3000 은 통합 서버 탭이 쓰고, 끝나면 자기가 띄운 것만 끈다.
- 브라우저에 표시하는 사용자/파일/AI 텍스트가 HTML 실행으로 이어지는지, CSV 내보내기의 수식 문자열과 파일 저장 경로가 실제 위험 지점에 도달하는지도 해당 입력 경로에서 확인한다. 사용하지 않는 기능은 해당 없음이다.
- 무해한 합성 입력·임시 복제본으로 검사한다. 원본 과제 데이터·실서비스를 변경하거나 네트워크로 전송해 취약성을 증명하지 않는다. 실행에 저장 부작용이 있으면 격리 후 테스트한다.
- 의존성 목록만 보고 취약점 없음으로 판정하지 않는다. 잠금 파일·버전·설치 출처를 확인하고 알려진 취약점 DB를 조회하지 않았다면 그 한계를 적는다.
- AI가 있으면 외부 문서·사용자 입력이 지시를 덮거나 도구 실행·외부 전송에 도달하는지, 실패 시 폴백을 확인한다. 외부 요청은 목적·대상·전송 데이터·과제 허용 근거를 구분한다.
- 오케는 지적의 실제 도달 가능성을 검산해 처분하고(`$decision`), 수정은 소유 워커에 맡겨 같은 위험 입력의 재실행 출력을 받아 읽는다(`docs/DECISIONS.md` D0).

## 출력 형식

```
# security M5 — <HH:MM KST>
검사 범위·기준 커밋: <경로·커밋·미커밋 제품 변경 여부>
검사 중 변경: <없음 또는 다시 확인할 경로>
통과 / 미확인 / 해당 없음(이유): <각 항목 번호>
실행 증거: <명령·입력·기대·실제·종료코드, 비밀값 제외>
지적 (심각한 순):
- [<항목>] <파일:줄> — <무엇> → <위험> → <최소 수정>
```

오케는 치명적인 것부터 소유 워커에 queue 해 고치게 하고, 그다음 덜한 것을 처분한다. 못 고친 것은 실행 안내 파일 「안 된다」, 처분은 `$decision`.
